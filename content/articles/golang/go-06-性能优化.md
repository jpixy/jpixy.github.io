## pprof性能分析

### 集成pprof

```go
import _ "net/http/pprof"

// HTTP服务中自动注册
go func() {
    http.ListenAndServe(":6060", nil)
}()
```

### CPU分析

```bash
# 采集30秒CPU数据
go tool pprof http://localhost:6060/debug/pprof/profile?seconds=30

# 交互模式
(pprof) top10       # 前10热点
(pprof) list func   # 查看函数代码
(pprof) web         # 生成火焰图

# 直接生成火焰图
go tool pprof -http=:8080 http://localhost:6060/debug/pprof/profile?seconds=30
```

### 内存分析

```bash
# 堆内存
go tool pprof http://localhost:6060/debug/pprof/heap

# 分配次数
go tool pprof -alloc_objects http://localhost:6060/debug/pprof/heap

# 分配大小
go tool pprof -alloc_space http://localhost:6060/debug/pprof/heap
```

### Goroutine分析

```bash
go tool pprof http://localhost:6060/debug/pprof/goroutine
```

### Benchmark中使用

```bash
# 运行benchmark并生成CPU profile
go test -bench=. -cpuprofile=cpu.prof

# 运行benchmark并生成内存profile
go test -bench=. -memprofile=mem.prof

# 分析
go tool pprof cpu.prof
```

## 内存优化

### 减少内存分配

```go
// 差：循环中分配
for i := 0; i < n; i++ {
    data := make([]byte, 1024)
    process(data)
}

// 好：复用缓冲区
buf := make([]byte, 1024)
for i := 0; i < n; i++ {
    process(buf)
}
```

### 预分配切片

```go
// 差：动态扩容
var result []int
for i := 0; i < n; i++ {
    result = append(result, i)
}

// 好：预分配
result := make([]int, 0, n)
for i := 0; i < n; i++ {
    result = append(result, i)
}
```

### sync.Pool复用

```go
var bufferPool = sync.Pool{
    New: func() interface{} {
        return make([]byte, 4096)
    },
}

func process() {
    buf := bufferPool.Get().([]byte)
    defer bufferPool.Put(buf)
    // 使用buf
}
```

### 字符串拼接

```go
// 差：多次拼接创建新字符串
s := ""
for _, part := range parts {
    s += part
}

// 好：使用Builder
var builder strings.Builder
for _, part := range parts {
    builder.WriteString(part)
}
s := builder.String()
```

### 避免逃逸到堆

```go
// 逃逸分析
go build -gcflags="-m" main.go

// 可能逃逸
func newInt() *int {
    x := 42
    return &x  // x逃逸到堆
}

// 避免逃逸：传入指针而非返回指针
func fillInt(x *int) {
    *x = 42
}
```

## 并发优化

### 控制Goroutine数量

```go
// 差：无限制创建goroutine
for task := range tasks {
    go process(task)
}

// 好：Worker Pool
func workerPool(numWorkers int, tasks <-chan Task) {
    var wg sync.WaitGroup
    for i := 0; i < numWorkers; i++ {
        wg.Add(1)
        go func() {
            defer wg.Done()
            for task := range tasks {
                process(task)
            }
        }()
    }
    wg.Wait()
}
```

### 避免锁竞争

```go
// 差：全局锁
var mu sync.Mutex
var counter int

func increment() {
    mu.Lock()
    counter++
    mu.Unlock()
}

// 好：分片锁
type ShardedCounter struct {
    shards [256]struct {
        mu    sync.Mutex
        count int
    }
}

func (c *ShardedCounter) Increment(key string) {
    shard := &c.shards[hash(key)%256]
    shard.mu.Lock()
    shard.count++
    shard.mu.Unlock()
}
```

### 使用原子操作

```go
// 差：锁保护计数器
var mu sync.Mutex
var count int

// 好：原子操作
var count int64
atomic.AddInt64(&count, 1)
```

### 减少锁粒度

```go
// 差：大锁
func (s *Store) Process(key string) {
    s.mu.Lock()
    defer s.mu.Unlock()
    value := s.data[key]
    result := expensiveComputation(value)  // 计算时仍持有锁
    s.data[key] = result
}

// 好：读写分离
func (s *Store) Process(key string) {
    s.mu.RLock()
    value := s.data[key]
    s.mu.RUnlock()
    
    result := expensiveComputation(value)  // 计算时不持有锁
    
    s.mu.Lock()
    s.data[key] = result
    s.mu.Unlock()
}
```

### Channel vs Mutex

| 场景 | 选择 |
|------|------|
| 传递数据所有权 | Channel |
| 保护共享数据 | Mutex |
| 协调goroutine | Channel |
| 简单计数器 | Atomic |

## 编译优化

### 编译选项

```bash
# 去除调试信息，减小二进制
go build -ldflags="-s -w" main.go

# 内联优化
go build -gcflags="-l=4" main.go

# 查看编译器决策
go build -gcflags="-m" main.go
```

### 边界检查消除

```go
// 编译器会插入边界检查
func sum(data []int) int {
    total := 0
    for i := 0; i < len(data); i++ {
        total += data[i]  // 每次访问都有边界检查
    }
    return total
}

// 提示编译器消除边界检查
func sum(data []int) int {
    total := 0
    data = data[:len(data):len(data)]  // 帮助编译器优化
    for i := 0; i < len(data); i++ {
        total += data[i]
    }
    return total
}
```

## Benchmark测试

### 编写Benchmark

```go
func BenchmarkConcat(b *testing.B) {
    for i := 0; i < b.N; i++ {
        concat("hello", "world")
    }
}

// 带设置
func BenchmarkProcess(b *testing.B) {
    data := prepareData()
    b.ResetTimer()  // 重置计时器
    for i := 0; i < b.N; i++ {
        process(data)
    }
}

// 子benchmark
func BenchmarkSize(b *testing.B) {
    for _, size := range []int{100, 1000, 10000} {
        b.Run(fmt.Sprintf("size-%d", size), func(b *testing.B) {
            data := make([]int, size)
            b.ResetTimer()
            for i := 0; i < b.N; i++ {
                process(data)
            }
        })
    }
}
```

### 运行Benchmark

```bash
go test -bench=.
go test -bench=. -benchmem           # 显示内存分配
go test -bench=. -benchtime=5s       # 运行5秒
go test -bench=. -count=10           # 运行10次

# 比较
go test -bench=. > old.txt
# 修改代码后
go test -bench=. > new.txt
benchstat old.txt new.txt
```

## 常见性能陷阱

### defer开销

```go
// 每次调用都有defer开销
func readValue(m *sync.RWMutex, key string) int {
    m.RLock()
    defer m.RUnlock()
    return data[key]
}

// 热路径可考虑手动解锁
func readValue(m *sync.RWMutex, key string) int {
    m.RLock()
    v := data[key]
    m.RUnlock()
    return v
}
```

### 接口方法调用

```go
// 接口调用有动态分发开销
func processReader(r io.Reader) {
    r.Read(buf)
}

// 热路径可使用具体类型
func processBytes(r *bytes.Reader) {
    r.Read(buf)
}
```

### 小对象频繁分配

```go
type Point struct {
    X, Y int
}

// 差：返回指针，可能逃逸
func newPoint(x, y int) *Point {
    return &Point{x, y}
}

// 好：返回值，栈分配
func makePoint(x, y int) Point {
    return Point{x, y}
}
```

### range循环值拷贝

```go
type BigStruct struct {
    Data [1000]int
}

var items []BigStruct

// 差：每次迭代都拷贝
for _, item := range items {
    process(item)
}

// 好：使用索引或指针
for i := range items {
    process(&items[i])
}
```

## 优化原则

1. **先测量，后优化**：用pprof找到真正的瓶颈
2. **优化热路径**：80%时间花在20%代码
3. **减少分配**：复用对象、预分配、sync.Pool
4. **降低锁竞争**：分片、原子操作、无锁结构
5. **合理并发**：控制goroutine数量
6. **编译优化**：了解编译器行为

性能优化是一个持续的过程，需要在可读性和性能之间取得平衡。
