## 语言基础

### slice和array的区别？

**Array（数组）**：
- 固定长度，类型的一部分
- 值类型，赋值/传参时复制
- `[3]int` 和 `[4]int` 是不同类型

**Slice（切片）**：
- 动态长度
- 引用类型，指向底层数组
- 包含三要素：指针、长度、容量

```go
// slice结构
type slice struct {
    array unsafe.Pointer
    len   int
    cap   int
}
```

### slice扩容规则？

- 当前容量 < 1024：翻倍
- 当前容量 >= 1024：增加25%
- 实际扩容还会考虑内存对齐

```go
s := make([]int, 0, 4)
s = append(s, 1, 2, 3, 4, 5)  // 容量不够，扩容到8
```

### map的实现原理？

- **底层结构**：哈希表，使用桶（bucket）存储
- **每个桶**：存8个键值对 + 溢出桶指针
- **扩容条件**：负载因子>6.5 或 溢出桶过多
- **扩容方式**：渐进式，每次操作迁移少量数据

**非线程安全**：并发读写需要加锁或使用`sync.Map`

### string的底层结构？

```go
type stringStruct struct {
    str unsafe.Pointer  // 指向字节数组
    len int
}
```

- 不可变
- UTF-8编码
- 可以包含任意字节
- `len()` 返回字节数，不是字符数

### new和make的区别？

| | new | make |
|---|-----|------|
| 返回值 | 指针 | 值 |
| 适用类型 | 任意类型 | slice、map、channel |
| 初始化 | 零值 | 根据类型初始化 |

```go
p := new(int)     // *int, 指向0
s := make([]int, 5) // []int, 长度5的切片
```

## 并发相关

### goroutine和线程的区别？

| | Goroutine | 线程 |
|---|-----------|------|
| 栈大小 | 初始2KB，可增长 | 固定1-8MB |
| 调度 | Go运行时调度 | OS内核调度 |
| 切换成本 | 低（用户态） | 高（内核态） |
| 创建成本 | 低 | 高 |

### Go调度器（GMP模型）？

- **G（Goroutine）**：协程
- **M（Machine）**：OS线程
- **P（Processor）**：逻辑处理器，默认等于CPU核数

工作流程：
1. P持有本地队列的G
2. M绑定P执行G
3. G阻塞时M释放P，P可绑定其他M
4. 工作窃取：空闲P从其他P偷取G

### channel的底层结构？

```go
type hchan struct {
    qcount   uint           // 队列中元素数量
    dataqsiz uint           // 环形队列大小
    buf      unsafe.Pointer // 环形队列
    elemsize uint16
    closed   uint32
    sendx    uint           // 发送索引
    recvx    uint           // 接收索引
    recvq    waitq          // 等待接收的goroutine
    sendq    waitq          // 等待发送的goroutine
    lock     mutex
}
```

### 向已关闭的channel发送数据？

- **发送**：panic
- **接收**：可以，返回零值和false
- **关闭**：panic（重复关闭）

```go
v, ok := <-ch
if !ok {
    // channel已关闭
}
```

### 如何优雅关闭channel？

**原则**：由发送方关闭

```go
// 单生产者
go func() {
    for data := range source {
        ch <- data
    }
    close(ch)
}()

// 多生产者：使用sync.WaitGroup
go func() {
    wg.Wait()
    close(ch)
}()
```

### sync.Mutex和sync.RWMutex？

**Mutex**：互斥锁，同一时刻只有一个goroutine持有

**RWMutex**：读写锁
- 多个读锁可以同时持有
- 写锁独占
- 适用于读多写少场景

### sync.Map vs 加锁Map？

| | sync.Map | 加锁Map |
|---|----------|---------|
| 读性能 | 高（无锁） | 一般 |
| 写性能 | 一般 | 一般 |
| 适用场景 | 读多写少，key稳定 | 通用 |

### context的用途？

1. **取消信号**：传递取消指令
2. **超时控制**：设置截止时间
3. **值传递**：请求范围的值（如traceID）

```go
ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
defer cancel()

select {
case <-ctx.Done():
    return ctx.Err()
case result := <-ch:
    return result
}
```

## 内存管理

### Go的垃圾回收算法？

**三色标记清除 + 写屏障**：

三色标记：
- 白色：未访问
- 灰色：已访问，子对象未访问
- 黑色：已访问，子对象已访问

流程：
1. STW，开启写屏障
2. 从根对象扫描
3. 并发标记
4. STW，重新扫描
5. 并发清除

### 如何减少GC压力？

1. **复用对象**：sync.Pool
2. **预分配**：make时指定容量
3. **避免逃逸**：小对象栈分配
4. **减少指针**：值类型优于指针

### 逃逸分析？

编译器决定变量分配在栈还是堆：

**逃逸到堆的情况**：
- 返回局部变量指针
- 发送指针到channel
- 存储到interface{}
- 闭包引用
- 大对象

```bash
go build -gcflags="-m" main.go
```

## 接口

### 接口的底层结构？

```go
// 空接口
type eface struct {
    _type *_type
    data  unsafe.Pointer
}

// 非空接口
type iface struct {
    tab  *itab           // 类型+方法表
    data unsafe.Pointer
}
```

### nil接口 vs 持有nil的接口？

```go
var r io.Reader         // nil接口
var f *os.File = nil
r = f                   // 非nil接口（有类型信息）

r == nil  // false！
```

### 类型断言性能？

接口调用有额外开销（动态分发），热路径考虑使用具体类型。

## 性能相关

### 如何定位性能问题？

1. **pprof**：CPU、内存分析
2. **trace**：执行追踪
3. **benchmark**：性能测试
4. **race detector**：数据竞争

```go
import _ "net/http/pprof"

go func() {
    http.ListenAndServe(":6060", nil)
}()
```

### string和[]byte转换开销？

每次转换都会分配内存：

```go
// 避免不必要的转换
s := string(b)  // 分配
b := []byte(s)  // 分配

// 零拷贝（不安全，只读）
func StringToBytes(s string) []byte {
    return unsafe.Slice(unsafe.StringData(s), len(s))
}
```

### for range的陷阱？

```go
// 陷阱1：闭包捕获
for _, v := range values {
    go func() {
        fmt.Println(v)  // 所有goroutine打印相同值
    }()
}

// 正确
for _, v := range values {
    v := v  // 创建副本
    go func() {
        fmt.Println(v)
    }()
}

// 陷阱2：大对象复制
for _, item := range bigItems {
    process(item)  // 每次迭代复制整个item
}

// 正确
for i := range bigItems {
    process(&bigItems[i])
}
```

## 项目实战

### 如何设计一个连接池？

```go
type Pool struct {
    mu       sync.Mutex
    conns    chan *Conn
    maxConns int
    factory  func() (*Conn, error)
}

func (p *Pool) Get() (*Conn, error) {
    select {
    case conn := <-p.conns:
        if conn.IsAlive() {
            return conn, nil
        }
    default:
    }
    return p.factory()
}

func (p *Pool) Put(conn *Conn) {
    select {
    case p.conns <- conn:
    default:
        conn.Close()
    }
}
```

### 如何实现限流？

```go
// 令牌桶
import "golang.org/x/time/rate"

limiter := rate.NewLimiter(100, 10)  // 100/s，桶大小10

if limiter.Allow() {
    // 处理请求
} else {
    // 拒绝
}

// 等待
err := limiter.Wait(ctx)
```

### 如何实现优雅关闭？

```go
srv := &http.Server{Addr: ":8080"}

go func() {
    if err := srv.ListenAndServe(); err != http.ErrServerClosed {
        log.Fatal(err)
    }
}()

quit := make(chan os.Signal, 1)
signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
<-quit

ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
defer cancel()

if err := srv.Shutdown(ctx); err != nil {
    log.Fatal(err)
}
```

## 编码规范

### 错误处理最佳实践？

```go
// 1. 检查错误
if err != nil {
    return err
}

// 2. 包装错误
return fmt.Errorf("failed to process: %w", err)

// 3. 自定义错误
type NotFoundError struct {
    ID int
}

func (e *NotFoundError) Error() string {
    return fmt.Sprintf("not found: %d", e.ID)
}

// 4. 错误检查
if errors.Is(err, os.ErrNotExist) {}
if errors.As(err, &notFoundErr) {}
```
