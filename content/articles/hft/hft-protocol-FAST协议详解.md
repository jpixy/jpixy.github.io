# HFT协议系列-FAST协议详解

FAST（FIX Adapted for Streaming）是专为高频行情数据分发设计的二进制协议，本文深入解析其编码机制与低延迟实现。

---

## 一、FAST 协议概述

### 1.1 设计背景

**FIX 文本协议的问题**：
- 消息体积大，带宽消耗高
- 解析开销大，延迟高
- 不适合高频行情分发

**FAST 的解决方案**：
- 二进制编码，体积减少 50-70%
- 增量编码，只传输变化部分
- 流式传输，适合组播

### 1.2 协议特点

| 特点 | 说明 |
|-----|------|
| 二进制编码 | 紧凑高效 |
| 增量传输 | 只发送变化字段 |
| 模板驱动 | 预定义消息结构 |
| 无会话层 | 纯数据编码 |
| UDP/组播友好 | 适合一对多分发 |

### 1.3 典型应用

| 交易所 | 应用场景 |
|-------|---------|
| CME | 市场数据分发 |
| NYSE | 行情推送 |
| NASDAQ | TotalView 数据 |
| 上交所/深交所 | Level-2 行情 |
| 港交所 | OMD 协议 |

## 二、编码原理

### 2.1 核心思想

```
传统方式：每次发送完整消息
  消息1: [A=100, B=200, C=300]
  消息2: [A=100, B=201, C=300]  ← 重复传输 A、C

FAST 增量方式：
  基础消息: [A=100, B=200, C=300]
  增量消息: [B=201]  ← 只传输变化的 B
```

### 2.2 Presence Map (PMAP)

PMAP 是位图，标识哪些字段存在于当前消息：

```
PMAP: 0b01000000
       │└──────── 字段1 不存在（使用前值或默认值）
       └───────── 字段0 存在（消息中包含）
```

### 2.3 Stop Bit 编码

FAST 使用 Stop Bit 编码实现变长整数：

| 特点 | 说明 |
|-----|------|
| 每字节 7 位数据 | 最高位为停止位 |
| 停止位 = 1 | 表示最后一个字节 |
| 停止位 = 0 | 表示后续还有字节 |

**编码示例**：

| 数值 | 编码 | 说明 |
|-----|------|------|
| 64 | 0xC0 | 单字节，最高位=1 |
| 128 | 0x01 0x80 | 双字节 |
| 942755 | 0x39 0x45 0xA3 | 三字节 |

### 2.4 数据类型

| 类型 | 编码方式 |
|-----|---------|
| uInt32/uInt64 | 无符号 Stop Bit |
| Int32/Int64 | 有符号 Stop Bit |
| Decimal | 指数 + 尾数 |
| ASCII String | Stop Bit + 字符 |
| Unicode String | 长度 + UTF-8 |
| ByteVector | 长度 + 原始字节 |

## 三、操作符机制

### 3.1 操作符类型

FAST 通过操作符定义字段如何编码和解码：

| 操作符 | 说明 | PMAP 影响 |
|-------|------|----------|
| None | 无特殊处理 | 否 |
| Constant | 常量，不传输 | 否（可选时是） |
| Default | 使用默认值或传输 | 是 |
| Copy | 复制前值或传输 | 是 |
| Increment | 前值 +1 或传输 | 是 |
| Delta | 传输与前值的差 | 否 |
| Tail | 传输字符串尾部变化 | 是 |

### 3.2 操作符工作原理

**Copy 操作符**：
```
前值: 100
PMAP 位 = 0 → 使用前值 100
PMAP 位 = 1 → 从消息读取新值
```

**Increment 操作符**：
```
前值: 100
PMAP 位 = 0 → 使用前值 + 1 = 101
PMAP 位 = 1 → 从消息读取新值
```

**Delta 操作符**：
```
前值: 1000
传输值: +5
当前值: 1000 + 5 = 1005
```

### 3.3 操作符选择策略

| 字段特征 | 推荐操作符 |
|---------|-----------|
| 恒定不变 | Constant |
| 通常不变，偶尔变 | Copy/Default |
| 递增序列 | Increment |
| 小幅度变化 | Delta |
| 字符串尾部变化 | Tail |

## 四、模板系统

### 4.1 模板结构

FAST 消息由模板定义，模板包含：
- 模板 ID
- 字段列表（名称、类型、操作符）
- 嵌套结构（组、序列）

### 4.2 模板示例

```xml
<template name="MarketData" id="1">
    <uInt32 name="TemplateID" id="1"/>
    <uInt32 name="MsgSeqNum" id="34">
        <increment/>
    </uInt32>
    <string name="Symbol" id="55">
        <copy/>
    </string>
    <decimal name="BidPrice" id="132">
        <delta/>
    </decimal>
    <decimal name="AskPrice" id="133">
        <delta/>
    </decimal>
    <uInt32 name="BidSize" id="134">
        <copy/>
    </uInt32>
    <uInt32 name="AskSize" id="135">
        <copy/>
    </uInt32>
</template>
```

### 4.3 动态模板引用

消息可以动态指定模板：
- 消息开头包含模板 ID
- 解码器根据 ID 选择模板
- 支持多种消息类型混合

## 五、消息结构

### 5.1 消息组成

```
┌─────────────────────────────────┐
│  PMAP (Presence Map)            │
├─────────────────────────────────┤
│  Template ID (可选)             │
├─────────────────────────────────┤
│  字段值 (按模板顺序)            │
│    - 只包含 PMAP 标记存在的字段  │
│    - Delta 字段包含差值          │
└─────────────────────────────────┘
```

### 5.2 组 (Group)

组是字段的集合，可以整体存在或不存在：

```
<group name="Parties">
    <string name="PartyID"/>
    <uInt32 name="PartyRole"/>
</group>
```

### 5.3 序列 (Sequence)

序列是重复组的列表：

```
<sequence name="MDEntries">
    <length name="NoMDEntries"/>
    <string name="MDEntryType"/>
    <decimal name="MDEntryPx"/>
    <uInt32 name="MDEntrySize"/>
</sequence>
```

## 六、行情分发架构

### 6.1 典型架构

```
┌─────────────┐     ┌─────────────┐
│ 交易所核心   │────▶│ FAST 编码器 │
└─────────────┘     └──────┬──────┘
                           │
                    ┌──────▼──────┐
                    │  UDP 组播   │
                    └──────┬──────┘
                           │
    ┌──────────────────────┼──────────────────────┐
    │                      │                      │
    ▼                      ▼                      ▼
┌─────────┐          ┌─────────┐          ┌─────────┐
│ 客户端 A │          │ 客户端 B │          │ 客户端 C │
│ 解码器   │          │ 解码器   │          │ 解码器   │
└─────────┘          └─────────┘          └─────────┘
```

### 6.2 组播通道设计

| 通道类型 | 用途 | 特点 |
|---------|------|------|
| Incremental | 增量更新 | 高频，小包 |
| Snapshot | 完整快照 | 定期，大包 |
| Recovery | 恢复通道 | 按需请求 |
| Instrument | 合约定义 | 低频，启动时 |

### 6.3 丢包处理

**增量 + 快照机制**：
1. 正常接收增量更新
2. 检测序号跳跃（丢包）
3. 等待下一个快照
4. 快照后重建状态
5. 继续接收增量

## 七、解码优化

### 7.1 延迟来源

| 环节 | 延迟因素 |
|-----|---------|
| 网络接收 | 中断延迟、缓冲区 |
| PMAP 解析 | 位操作 |
| Stop Bit 解码 | 循环处理 |
| 模板查找 | 查表开销 |
| 字段处理 | 操作符逻辑 |
| 状态管理 | 前值维护 |

### 7.2 优化策略

| 策略 | 说明 |
|-----|------|
| 代码生成 | 根据模板生成专用解码器 |
| 分支消除 | 避免条件判断 |
| SIMD 解码 | 并行处理多字段 |
| 预取 | 提前加载模板和前值 |
| 无锁状态 | 每线程独立状态 |
| 零拷贝 | 直接在网络缓冲区解码 |

### 7.3 代码生成 vs 解释执行

| 对比 | 解释执行 | 代码生成 |
|-----|---------|---------|
| 灵活性 | 高 | 低 |
| 解码速度 | 慢 | 快 |
| 启动时间 | 快 | 慢（需编译） |
| 维护性 | 好 | 复杂 |
| HFT 选择 | - | ✓ |

### 7.4 性能基准

| 实现方式 | 解码延迟 |
|---------|---------|
| 通用解释器 | 5-20μs |
| 优化解释器 | 2-5μs |
| 代码生成 | 0.5-2μs |
| FPGA | <0.1μs |

## 八、实现考虑

### 8.1 开源实现

| 项目 | 语言 | 特点 |
|-----|------|------|
| OpenFAST | Java | 参考实现 |
| QuickFAST | C++ | 功能完整 |
| mFAST | C++ | 现代 C++ |
| fast_codec | Rust | 安全高效 |

### 8.2 模板管理

| 考虑点 | 建议 |
|-------|------|
| 版本控制 | 模板 ID 包含版本 |
| 向后兼容 | 新增字段用可选 |
| 分发方式 | 启动时下载或本地 |
| 热更新 | 支持运行时切换 |

### 8.3 状态管理

| 问题 | 解决方案 |
|-----|---------|
| 多会话状态 | 按源/通道隔离 |
| 重置时机 | 每日开盘或特定消息 |
| 内存占用 | 按需分配，定期清理 |
