# Kubernetes (K8S) 基础知识面试题汇总
## 一、核心概念
1. **什么是 Kubernetes？它的主要作用是什么？**
    - 用于自动化容器化应用程序的部署、扩展和管理
    - 提供容器编排、服务发现、负载均衡、自动扩缩容等功能
2. **解释 Master 节点和 Worker 节点的区别**
    - Master：控制平面，包含 API Server、Scheduler、Controller Manager、etcd
    - Worker：运行工作负载的节点，包含 kubelet、kube-proxy、容器运行时
3. **什么是 Pod？为什么需要 Pod？**
    - Kubernetes 最小调度单元，包含一个或多个共享网络/存储的容器
    - 原因：容器分组管理、共享资源、协同调度
4. **解释 Deployment、StatefulSet 和 DaemonSet 的区别**
    - Deployment：无状态应用，支持滚动更新
    - StatefulSet：有状态应用，稳定标识和有序部署
    - DaemonSet：确保所有(或部分)节点运行一个 Pod 副本

## 二、架构与组件
5. **Kubernetes 控制平面包含哪些核心组件？**
    - kube-apiserver：集群操作入口
    - etcd：键值存储数据库
    - kube-scheduler：Pod 调度
    - kube-controller-manager：运行各种控制器
6. **kubelet 和 kube-proxy 的作用分别是什么？**
    - kubelet：节点代理，管理 Pod 和容器
    - kube-proxy：维护网络规则，实现服务抽象
7. **什么是 etcd？它在 Kubernetes 中起什么作用？**
    - 分布式键值存储，保存集群所有配置数据和状态
    - 存储集群状态、配置和元数据
8. **解释 CNI 和 CSI 的作用**
    - CNI (Container Network Interface)：提供 Pod 网络
    - CSI (Container Storage Interface)：提供持久化存储

## 三、网络与存储
9. **Kubernetes 网络模型的基本原则是什么？**
    - 每个 Pod 有唯一 IP
    - Pod 间可直接通信(无需 NAT)
    - 节点可以与所有 Pod 通信
    - Pod 内部容器共享网络命名空间
10. **Service 有哪些类型？它们的区别是什么？**
    - ClusterIP：集群内部访问
    - NodePort：通过节点端口暴露服务
    - LoadBalancer：使用云提供商负载均衡器
    - ExternalName：返回 CNAME 记录
11. **解释 PV 和 PVC 的关系**
    - PV (PersistentVolume)：集群存储资源
    - PVC (PersistentVolumeClaim)：用户存储请求
    - PVC 绑定到 PV 后，Pod 通过 PVC 使用存储
12. **StorageClass 的作用是什么？**
    - 定义动态供应的存储类型
    - 指定供应器、参数和回收策略

## 四、调度与资源
13. **Kubernetes 调度器如何工作？**
    - 过滤阶段：排除不满足条件的节点
    - 评分阶段：为剩余节点打分
    - 绑定阶段：选择最高分节点绑定 Pod
14. **什么是污点(Taint)和容忍(Toleration)？**
    - 污点：阻止 Pod 调度到节点
    - 容忍：允许 Pod 调度到有特定污点的节点
15. **如何限制 Pod 的资源使用？**

```yaml
resources:
  limits:
    cpu: "1"
    memory: "1Gi"
  requests:
    cpu: "500m"
    memory: "512Mi"
```

16. **解释 QoS (服务质量)等级**
    - Guaranteed：requests == limits
    - Burstable：有 requests 但不满足 Guaranteed
    - BestEffort：无 requests 和 limits

## 五、运维与安全
17. **如何查看 Pod 的日志？**

```bash
kubectl logs <pod-name>
kubectl logs -f <pod-name> # 实时日志
kubectl logs <pod-name> -c <container-name> # 多容器 Pod
```

18. **如何进入运行中的 Pod？**

```bash
kubectl exec -it <pod-name> -- /bin/bash
```

19. **什么是 ConfigMap 和 Secret？它们的区别？**
    - 都用于存储配置数据
    - Secret 专为敏感数据设计，base64 编码
    - ConfigMap 存储普通配置数据
20. **ServiceAccount 的作用是什么？**
    - 为 Pod 中的进程提供身份认证
    - 用于授权 Pod 访问 Kubernetes API

## 六、故障排查
21. **Pod 一直处于 Pending 状态可能的原因？**
    - 资源不足
    - 调度约束不满足(nodeSelector/affinity/taint)
    - PV 绑定失败
    - 镜像拉取失败
22. **如何诊断 Service 无法访问的问题？**
    - 检查 Endpoints：`kubectl get endpoints <service-name>`
    - 检查 kube-proxy 是否运行
    - 检查网络策略是否阻止流量
23. **节点 NotReady 的可能原因及解决方法？**
    - kubelet 未运行：重启 kubelet
    - 节点资源不足：清理资源或扩容
    - 网络问题：检查节点间网络连接

## 七、进阶概念
24. **什么是 Operator？**
    - 自定义控制器，用于管理复杂有状态应用
    - 扩展 Kubernetes API 和功能
25. **解释 Horizontal Pod Autoscaler (HPA) 工作原理**
    - 根据 CPU/内存或自定义指标自动调整 Pod 副本数
    - 需要 Metrics Server 提供指标数据
26. **什么是 Ingress？它与 Service 有什么区别？**
    - Ingress：管理外部访问集群服务的 HTTP/HTTPS 路由
    - Service：提供内部服务发现和负载均衡
    - Ingress 需要 Ingress Controller 实现
27. **解释 CRD (Custom Resource Definition)**
    - 允许用户自定义 Kubernetes 资源类型
    - 扩展 Kubernetes API

## 八、场景题
28. **如何实现蓝绿部署？**
    - 创建新 Deployment (绿色)
    - 测试通过后，将 Service 的 selector 切换到新 Deployment
    - 旧 Deployment (蓝色) 可保留或删除
29. **如何安全地排空(Drain)一个节点？**

```bash
kubectl drain <node-name> --ignore-daemonsets --delete-emptydir-data
```

30. **如何备份和恢复 etcd 数据？**

```bash
# 备份
ETCDCTL_API=3 etcdctl --endpoints=$ENDPOINT snapshot save snapshot.db

# 恢复
ETCDCTL_API=3 etcdctl snapshot restore snapshot.db --data-dir=/var/lib/etcd-new
```

这些面试题涵盖了 Kubernetes 的核心概念和常见运维场景，建议结合实际操作经验进行准备。
