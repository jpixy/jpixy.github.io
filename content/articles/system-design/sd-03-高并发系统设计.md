## 并发指标

### 核心指标

| 指标 | 定义 | 说明 |
|------|------|------|
| QPS | 每秒查询数 | 读请求能力 |
| TPS | 每秒事务数 | 写请求能力 |
| 并发数 | 同时处理的请求数 | 系统负载 |
| 响应时间 | 请求处理时间 | 用户体验 |
| 吞吐量 | 单位时间处理量 | 系统能力 |

### 性能基准

| 场景 | 参考QPS |
|------|---------|
| 单机Nginx | 10万+ |
| 单机Tomcat | 1000-5000 |
| MySQL单机 | 1000-5000 |
| Redis单机 | 10万+ |

### Little's Law

```
并发数 = QPS × 响应时间

示例：
QPS = 1000，响应时间 = 100ms
并发数 = 1000 × 0.1 = 100
```

## 缓存设计

### 多级缓存

```
客户端 → CDN → 网关缓存 → 应用缓存 → 分布式缓存 → 数据库
```

### 缓存策略

**Cache Aside**：
```
读：先查缓存，没有则查数据库，再写缓存
写：更新数据库，删除缓存
```

**Read/Write Through**：
```
读写都通过缓存，缓存负责同步数据库
```

**Write Behind**：
```
写入缓存即返回，异步写数据库
```

### 缓存问题

**缓存穿透**：
- 问题：查询不存在的数据，每次都打到数据库
- 方案：布隆过滤器、缓存空值

**缓存击穿**：
- 问题：热点key过期，大量请求打到数据库
- 方案：热点key永不过期、互斥锁重建

**缓存雪崩**：
- 问题：大量key同时过期
- 方案：过期时间加随机值、预热

### 热点Key

**识别**：
- 客户端统计
- 代理层统计
- Redis hotkeys命令

**处理**：
- 本地缓存
- 多副本分散
- 限流保护

## 异步处理

### 消息队列

**作用**：
- 解耦：生产者消费者独立
- 削峰：平滑流量
- 异步：快速返回

**选型**：

| 产品 | 特点 | 适用场景 |
|------|------|----------|
| Kafka | 高吞吐、持久化 | 日志、大数据 |
| RabbitMQ | 功能丰富、可靠 | 业务消息 |
| RocketMQ | 事务消息、延迟 | 电商 |
| Redis | 轻量、简单 | 简单队列 |

### 异步模式

**发布订阅**：
```
发布者 → Topic → 订阅者1
              → 订阅者2
```

**点对点**：
```
生产者 → Queue → 消费者
```

### 消息可靠性

**生产端**：
- 确认机制
- 重试
- 本地消息表

**消费端**：
- 幂等消费
- 消费确认
- 死信队列

## 数据库优化

### 读写分离

```
写请求 → 主库 → 同步 → 从库1
                    → 从库2
读请求 ─────────────→ 从库
```

**问题**：主从延迟导致读不到最新数据
**方案**：
- 强制读主
- 延迟判断
- 业务容忍

### 分库分表

**垂直拆分**：
```
用户表 → 用户库
订单表 → 订单库
商品表 → 商品库
```

**水平拆分**：
```
订单表 → 订单表_0 (user_id % 4 = 0)
       → 订单表_1 (user_id % 4 = 1)
       → 订单表_2 (user_id % 4 = 2)
       → 订单表_3 (user_id % 4 = 3)
```

**分片键选择**：
- 分布均匀
- 查询友好
- 避免跨分片

### 索引优化

- 覆盖索引：避免回表
- 联合索引：最左匹配
- 避免索引失效

### 连接池

```yaml
hikari:
  maximumPoolSize: 20
  minimumIdle: 5
  connectionTimeout: 30000
  idleTimeout: 600000
```

## 流量削峰

### 排队

```
用户请求 → 队列 → 按能力消费
```

**实现**：
- 消息队列
- 请求缓冲区

### 答题/验证

```
秒杀开始 → 用户答题 → 打散请求时间
```

### 分层过滤

```
流量 → 限流（挡住超量）
     → 校验（挡住无效）
     → 缓存（挡住重复）
     → 数据库（处理有效）
```

### 预约/分批

```
10:00 第一批预约用户
10:05 第二批预约用户
10:10 第三批预约用户
```

## 池化技术

### 连接池

- 数据库连接池
- Redis连接池
- HTTP连接池

**配置原则**：
```
最大连接数 ≥ 并发数
最小连接数 = 常态并发数
```

### 线程池

```java
ThreadPoolExecutor(
    corePoolSize,     // 核心线程数
    maximumPoolSize,  // 最大线程数
    keepAliveTime,    // 空闲超时
    workQueue,        // 任务队列
    handler           // 拒绝策略
)
```

**拒绝策略**：
- AbortPolicy：抛异常
- CallerRunsPolicy：调用者执行
- DiscardPolicy：丢弃
- DiscardOldestPolicy：丢弃最老的

### 对象池

复用昂贵对象：
- 数据库连接
- TCP连接
- 大对象

## 总结

| 手段 | 作用 |
|------|------|
| 缓存 | 减少计算和IO |
| 异步 | 快速返回，削峰 |
| 池化 | 复用资源 |
| 无锁 | 减少竞争 |
| 分片 | 分散压力 |
| 读写分离 | 扩展读能力 |

高并发设计的核心是：**减少不必要的工作，分散压力到多个节点**。
