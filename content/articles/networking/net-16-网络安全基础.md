## 密码学基础

### 对称加密

**同一密钥加密解密**：

```
明文 + 密钥 → 加密 → 密文
密文 + 密钥 → 解密 → 明文
```

**常用算法**：

| 算法 | 密钥长度 | 特点 |
|------|----------|------|
| AES | 128/192/256位 | 最广泛使用 |
| ChaCha20 | 256位 | 软件实现快 |
| 3DES | 168位 | 已过时 |

**优点**：速度快
**缺点**：密钥分发困难

### 非对称加密

**公钥加密，私钥解密**：

```
明文 + 公钥 → 加密 → 密文
密文 + 私钥 → 解密 → 明文
```

**常用算法**：

| 算法 | 特点 |
|------|------|
| RSA | 最广泛，基于大数分解 |
| ECDSA | 椭圆曲线，密钥短 |
| Ed25519 | 现代椭圆曲线 |

**优点**：解决密钥分发问题
**缺点**：速度慢

### 哈希函数

**单向转换**：

```
任意数据 → 哈希函数 → 固定长度摘要
```

**特性**：
- 单向：无法从摘要反推原文
- 抗碰撞：难以找到相同摘要的不同输入
- 雪崩效应：输入微小变化导致输出巨大变化

**常用算法**：

| 算法 | 输出长度 | 状态 |
|------|----------|------|
| MD5 | 128位 | 不安全，避免使用 |
| SHA-1 | 160位 | 不安全，避免使用 |
| SHA-256 | 256位 | 推荐 |
| SHA-3 | 可变 | 最新标准 |

### 数字签名

**私钥签名，公钥验证**：

```
数据 → 哈希 → 摘要 → 私钥加密 → 签名

接收方：
签名 → 公钥解密 → 摘要1
数据 → 哈希 → 摘要2
比较摘要1和摘要2
```

**用途**：
- 身份认证
- 数据完整性
- 不可否认性

## TLS/SSL

### TLS版本

| 版本 | 状态 |
|------|------|
| SSL 2.0/3.0 | 已废弃 |
| TLS 1.0/1.1 | 已废弃 |
| TLS 1.2 | 广泛使用 |
| TLS 1.3 | 推荐使用 |

### TLS 1.2握手

```
客户端                          服务端
  |  -- ClientHello ---------->  |  支持的加密套件
  |  <-- ServerHello -----------  |  选择的加密套件
  |  <-- Certificate -----------  |  服务端证书
  |  <-- ServerKeyExchange -----  |  密钥交换参数
  |  <-- ServerHelloDone -------  |
  |  -- ClientKeyExchange ----->  |  客户端密钥部分
  |  -- ChangeCipherSpec ------>  |  开始加密
  |  -- Finished -------------->  |  加密的握手摘要
  |  <-- ChangeCipherSpec ------  |
  |  <-- Finished --------------  |
  |  <-- 加密通信 -------------->  |
```

### TLS 1.3改进

**更快**：
- 1-RTT握手（vs 2-RTT）
- 0-RTT恢复

**更安全**：
- 移除不安全算法
- 加密更多握手内容
- 完美前向保密必须

### 加密套件

**TLS 1.2示例**：
```
TLS_ECDHE_RSA_WITH_AES_256_GCM_SHA384

ECDHE: 密钥交换
RSA: 身份认证
AES_256_GCM: 加密算法
SHA384: 哈希算法
```

**TLS 1.3示例**：
```
TLS_AES_256_GCM_SHA384

密钥交换和认证由握手协议决定
```

### 证书

**X.509证书内容**：
- 主题（域名）
- 公钥
- 颁发者
- 有效期
- 签名

**证书链**：
```
根CA证书（预装在系统）
  ↓ 签发
中间CA证书
  ↓ 签发
服务器证书
```

## 防火墙

### 防火墙类型

**包过滤防火墙**：
- 基于IP、端口、协议过滤
- 无状态或有状态

**应用层防火墙（WAF）**：
- 理解HTTP等协议
- 检测应用层攻击

**下一代防火墙（NGFW）**：
- 深度包检测
- 应用识别
- 入侵防御

### iptables

**链（Chain）**：
- INPUT：进入本机
- OUTPUT：本机发出
- FORWARD：转发

**表（Table）**：
- filter：过滤
- nat：地址转换
- mangle：修改包

**规则示例**：
```bash
# 允许已建立的连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 允许SSH
iptables -A INPUT -p tcp --dport 22 -j ACCEPT

# 允许HTTP/HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# 默认拒绝
iptables -P INPUT DROP
```

### nftables

**iptables的替代**：
```bash
nft add table inet filter
nft add chain inet filter input { type filter hook input priority 0 \; }
nft add rule inet filter input tcp dport 22 accept
```

### 安全组

**云平台的虚拟防火墙**：
```yaml
安全组规则:
  入站:
    - 协议: TCP, 端口: 22, 来源: 10.0.0.0/8
    - 协议: TCP, 端口: 80, 来源: 0.0.0.0/0
    - 协议: TCP, 端口: 443, 来源: 0.0.0.0/0
  出站:
    - 协议: ALL, 目标: 0.0.0.0/0
```

## 常见攻击与防护

### DDoS攻击

**类型**：

| 类型 | 目标 | 示例 |
|------|------|------|
| 容量型 | 带宽 | UDP洪水 |
| 协议型 | 服务器资源 | SYN洪水 |
| 应用型 | 应用 | HTTP洪水 |

**防护**：
- 流量清洗
- CDN分散
- 速率限制
- SYN Cookie

### 中间人攻击（MITM）

**原理**：攻击者插入通信双方之间

**防护**：
- 使用HTTPS
- 证书固定（Certificate Pinning）
- HSTS

### SQL注入

**原理**：用户输入被当作SQL执行

```
输入：' OR '1'='1
查询变成：SELECT * FROM users WHERE name='' OR '1'='1'
```

**防护**：
- 参数化查询
- 输入验证
- WAF

### XSS（跨站脚本）

**原理**：注入恶意脚本到页面

**类型**：
- 存储型：恶意脚本存入数据库
- 反射型：恶意脚本在URL中
- DOM型：纯前端漏洞

**防护**：
- 输出编码
- Content Security Policy (CSP)
- HttpOnly Cookie

### CSRF（跨站请求伪造）

**原理**：诱导用户在已登录网站执行操作

**防护**：
- CSRF Token
- SameSite Cookie
- 验证Referer

## 安全最佳实践

### 传输安全

- 全站HTTPS
- 使用TLS 1.2+
- HSTS头部
- 禁用不安全协议

```
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

### 访问控制

- 最小权限原则
- 网络分段
- 多因素认证
- 定期审计

### 数据保护

- 敏感数据加密存储
- 密钥安全管理
- 数据脱敏
- 备份加密

### 安全监控

- 日志收集分析
- 入侵检测系统（IDS）
- 安全信息与事件管理（SIEM）
- 定期漏洞扫描

## 总结

| 领域 | 关键技术 |
|------|----------|
| 加密 | 对称加密、非对称加密、哈希 |
| 传输安全 | TLS 1.3、证书 |
| 边界防护 | 防火墙、WAF |
| 攻击防御 | DDoS防护、输入验证 |
| 安全实践 | 最小权限、监控审计 |

网络安全是一个持续的过程，需要纵深防御，不能依赖单一措施。
