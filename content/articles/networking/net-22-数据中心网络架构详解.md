# 数据中心网络架构详解

本文深入介绍现代数据中心网络架构，包括大二层/大三层概念、Spine-Leaf 架构、Overlay 网络技术等。

---

## 一、传统数据中心网络架构

### 1.1 经典三层架构

**定义**：传统数据中心采用 Core-Aggregation-Access 三层架构。

```
                    ┌─────────┐
                    │  Core   │  核心层：高速转发，连接外网
                    │ (L3路由) │
                    └────┬────┘
                         │
            ┌────────────┼────────────┐
            │            │            │
       ┌────┴────┐  ┌────┴────┐  ┌────┴────┐
       │  Agg 1  │  │  Agg 2  │  │  Agg 3  │  汇聚层：VLAN间路由，策略
       │ (L2/L3) │  │ (L2/L3) │  │ (L2/L3) │
       └────┬────┘  └────┬────┘  └────┬────┘
            │            │            │
       ┌────┴────┐  ┌────┴────┐  ┌────┴────┐
       │ Access  │  │ Access  │  │ Access  │  接入层：连接服务器
       │  (L2)   │  │  (L2)   │  │  (L2)   │
       └────┬────┘  └────┬────┘  └────┬────┘
            │            │            │
         服务器        服务器        服务器
```

### 1.2 传统架构的问题

| 问题 | 说明 |
|------|------|
| **STP 限制** | 生成树协议阻塞冗余链路，带宽利用率低 |
| **VLAN 数量** | 最多 4096 个 VLAN，大规模租户不够用 |
| **南北流量设计** | 设计针对南北向（客户端↔服务器），东西向（服务器↔服务器）效率低 |
| **VM 迁移困难** | 跨子网迁移需要改 IP，影响业务 |
| **扩展性差** | 增加设备时 STP 重新收敛，影响全网 |

```
南北向流量 (传统):           东西向流量 (云/AI):
                              
  客户端                      服务器 ←──→ 服务器
     │                            │
     ↓                            ↓
  ┌──────┐                   ┌──────────────┐
  │ Core │                   │ 大量横向通信  │
  └──────┘                   │ (分布式计算)  │
     │                       └──────────────┘
     ↓                       
  服务器                      
```

## 二、大二层网络 (Large Layer 2)

### 2.1 什么是大二层

**一句话：大二层让整个数据中心像一个巨大的交换机，所有服务器在同一个广播域**

```
传统二层 (小范围):              大二层 (跨机房):

┌─────────────┐               ┌──────────────────────────────┐
│   VLAN 10   │               │         大二层域              │
│  (一个机架)  │               │                              │
│  ┌───┬───┐  │               │  机房A      机房B      机房C  │
│  │VM │VM │  │               │  ┌───┐     ┌───┐     ┌───┐  │
│  └───┴───┘  │               │  │VM │ ←─→ │VM │ ←─→ │VM │  │
└─────────────┘               │  └───┘     └───┘     └───┘  │
                              │       同一个二层网络          │
                              └──────────────────────────────┘

VM可以在任意位置迁移，保持IP不变
```

### 2.2 为什么需要大二层

| 需求 | 说明 |
|------|------|
| **VM 热迁移** | 虚拟机从一台物理机迁移到另一台，IP 不变，连接不断 |
| **负载均衡** | 集群内服务器需要在同一子网，方便 ARP |
| **多租户隔离** | 云环境需要大量隔离的虚拟网络 |
| **灾备** | 跨机房的业务连续性 |

### 2.3 大二层实现技术

#### VXLAN (Virtual Extensible LAN)

**定义**：在三层网络上封装二层帧，实现跨三层的二层网络。

```
原始以太网帧:
┌──────────────────────────────────────────────┐
│ Dst MAC │ Src MAC │ Type │ IP头 │ 数据 │ FCS │
└──────────────────────────────────────────────┘

VXLAN 封装后:
┌───────────────────────────────────────────────────────────────────────┐
│ 外层  │ 外层  │ 外层IP头  │ 外层UDP │ VXLAN │ 原始以太网帧           │
│ MAC   │ MAC   │ (Underlay)│ (4789)  │ Header│                        │
└───────────────────────────────────────────────────────────────────────┘
                                        │
                                  24位 VNI (约1600万个)
```

**VXLAN 关键概念**：

| 概念 | 说明 |
|------|------|
| **VNI** | VXLAN Network Identifier，24位，支持约1600万个虚拟网络 |
| **VTEP** | VXLAN Tunnel Endpoint，执行封装/解封装的设备 |
| **NVE** | Network Virtualization Edge，华为叫法，等同于 VTEP |
| **Underlay** | 底层物理网络，负责 VTEP 之间的 IP 可达 |
| **Overlay** | 上层虚拟网络，用户看到的逻辑网络 |

```
                    Overlay (虚拟网络，VNI 1000)
  VM1 ─────────────────────────────────────────── VM2
  10.0.1.1                                       10.0.1.2
    │                                              │
    ↓                                              ↓
┌───────┐                                    ┌───────┐
│ VTEP1 │                                    │ VTEP2 │
│192.168│                                    │192.168│
│ .1.1  │                                    │ .1.2  │
└───┬───┘                                    └───┬───┘
    │            Underlay (物理网络)              │
    └──────────── IP 路由可达 ───────────────────┘
```

**VXLAN 配置示例 (Linux)**：

```bash
# 创建 VXLAN 接口
ip link add vxlan100 type vxlan id 100 \
    local 192.168.1.1 \
    remote 192.168.1.2 \
    dstport 4789 \
    dev eth0

# 启用接口
ip link set vxlan100 up

# 添加到网桥
ip link add br0 type bridge
ip link set vxlan100 master br0
ip link set br0 up

# 查看 VXLAN 信息
bridge fdb show dev vxlan100
ip -d link show vxlan100
```

#### 其他大二层技术对比

| 技术 | 标准/厂商 | 特点 |
|------|-----------|------|
| **VXLAN** | RFC 7348 | 业界主流，UDP封装，支持多租户 |
| **NVGRE** | Microsoft | GRE封装，Windows Server支持好 |
| **TRILL** | IETF | 替代STP，IS-IS路由，Juniper/Brocade |
| **SPB** | IEEE 802.1aq | IS-IS路由，运营商场景 |
| **FabricPath** | Cisco | 思科私有，数据中心 |

## 三、大三层网络 (Routed Layer 3)

### 3.1 什么是大三层

**一句话：大三层用纯三层路由替代二层交换，每个交换机都是路由器**

```
传统二层 + STP:                 大三层 (纯路由):

   ┌─────┐                        ┌─────┐
   │ Core│                        │Spine│ ←─ 三层路由
   └──┬──┘                        └──┬──┘
      │                              │
   STP阻塞                        ECMP (所有链路active)
   部分链路                           │
      │                         ┌────┴────┐
   ┌──┴──┐                      ↓         ↓
   │ Agg │                   ┌─────┐   ┌─────┐
   └──┬──┘                   │Leaf │   │Leaf │ ←─ 三层路由
      │                      └──┬──┘   └──┬──┘
   ┌──┴──┐                      │         │
   │ Acc │                   服务器     服务器
   └─────┘
```

### 3.2 Spine-Leaf 架构

**定义**：现代数据中心标准拓扑，所有 Leaf 连接所有 Spine，形成 Clos 网络。

```
              Spine 层 (脊)
        ┌─────┐         ┌─────┐
        │Spine│         │Spine│
        │  1  │         │  2  │
        └──┬──┘         └──┬──┘
           │╲             ╱│
           │ ╲           ╱ │
           │  ╲         ╱  │      全互联
           │   ╲       ╱   │      任意两个Leaf
           │    ╲     ╱    │      最多2跳可达
           │     ╲   ╱     │
           │      ╲ ╱      │
           │       ╳       │
           │      ╱ ╲      │
           │     ╱   ╲     │
           │    ╱     ╲    │
           │   ╱       ╲   │
        ┌──┴──┐       ┌──┴──┐
        │Leaf │       │Leaf │
        │  1  │       │  2  │      Leaf 层 (叶)
        └──┬──┘       └──┬──┘
           │              │
      ┌────┴────┐    ┌────┴────┐
      │ Server  │    │ Server  │
      │ Rack 1  │    │ Rack 2  │
      └─────────┘    └─────────┘
```

**Spine-Leaf 特点**：

| 特点 | 说明 |
|------|------|
| **无 STP** | 全三层路由，无需生成树 |
| **ECMP** | 等价多路径，所有链路同时使用 |
| **可预测延迟** | 任意两点最多 2 跳（Leaf→Spine→Leaf） |
| **水平扩展** | 增加 Spine/Leaf 即可扩容 |
| **东西向优化** | 适合服务器间大量横向通信 |

### 3.3 大三层 + Overlay

**现代主流方案：Spine-Leaf (Underlay) + VXLAN (Overlay) + BGP EVPN (控制面)**

```
┌────────────────────────────────────────────────────────────────┐
│                     Overlay (VXLAN)                            │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │  租户A VNI 1000      租户B VNI 2000      租户C VNI 3000  │  │
│  │  10.1.0.0/16         10.2.0.0/16         10.3.0.0/16     │  │
│  └─────────────────────────────────────────────────────────┘  │
│                              │                                 │
│                         VTEP 封装                              │
│                              ↓                                 │
├────────────────────────────────────────────────────────────────┤
│                    Underlay (Spine-Leaf)                       │
│  ┌─────────────────────────────────────────────────────────┐  │
│  │              纯三层 IP 路由 (BGP/OSPF)                    │  │
│  │              Spine: 192.168.0.x                          │  │
│  │              Leaf:  192.168.1.x                          │  │
│  └─────────────────────────────────────────────────────────┘  │
└────────────────────────────────────────────────────────────────┘
```

## 四、BGP EVPN

### 4.1 什么是 EVPN

**一句话：EVPN 是 VXLAN 的"大脑"，自动学习和分发 MAC/IP 地址映射**

```
传统方式 (数据面学习):          EVPN (控制面分发):

VM1 要找 VM2                    VM1 要找 VM2
     │                               │
     ↓ 广播 ARP                      ↓ 查本地路由表
  泛洪到所有 VTEP                    直接知道 VM2 在哪
     │                               │
效率低，广播风暴                   效率高，无泛洪
```

### 4.2 EVPN 路由类型

| 类型 | 名称 | 用途 |
|------|------|------|
| **Type-2** | MAC/IP Advertisement | 通告主机 MAC 和 IP |
| **Type-3** | Inclusive Multicast | BUM 流量（广播/未知单播/组播） |
| **Type-5** | IP Prefix | 通告子网前缀（三层路由） |

### 4.3 BGP EVPN 工作流程

```
1. VM1 启动，VTEP1 学习到 MAC1/IP1

2. VTEP1 生成 Type-2 路由，通过 BGP 通告：
   ┌─────────────────────────────────────────────────┐
   │ Route Type: 2 (MAC/IP)                          │
   │ VNI: 1000                                       │
   │ MAC: aa:bb:cc:dd:ee:01                          │
   │ IP: 10.0.1.1                                    │
   │ Next Hop: 192.168.1.1 (VTEP1)                   │
   └─────────────────────────────────────────────────┘

3. 其他 VTEP 收到路由，更新转发表

4. VM2 → VM1 时，VTEP2 查表直接封装发送
   无需 ARP 广播
```

### 4.4 配置示例 (FRRouting)

```bash
# /etc/frr/frr.conf

router bgp 65001
 bgp router-id 192.168.1.1
 neighbor 192.168.0.1 remote-as 65000
 neighbor 192.168.0.1 update-source lo
 !
 address-family l2vpn evpn
  neighbor 192.168.0.1 activate
  advertise-all-vni
 exit-address-family
!
vni 1000
 rd 192.168.1.1:1000
 route-target import 65000:1000
 route-target export 65000:1000
```

## 五、Underlay 与 Overlay

### 5.1 概念区分

```
┌─────────────────────────────────────────────────────────────┐
│  Overlay (虚拟网络)                                          │
│  - 用户/租户看到的网络                                       │
│  - 可以重叠 IP 地址（不同租户可用相同 10.0.0.0/8）            │
│  - 技术：VXLAN、GRE、IPsec                                  │
│  - 控制面：BGP EVPN、OVSDB                                  │
└─────────────────────────────────────────────────────────────┘
                           ↑ 封装/解封装
┌─────────────────────────────────────────────────────────────┐
│  Underlay (物理网络)                                         │
│  - 底层物理互联                                              │
│  - 只需保证 VTEP 之间 IP 可达                                │
│  - 技术：纯 IP 路由 (BGP/OSPF/IS-IS)                        │
│  - 拓扑：Spine-Leaf                                         │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 为什么分离

| 好处 | 说明 |
|------|------|
| **解耦** | 上层虚拟网络变化不影响底层物理网络 |
| **简化** | Underlay 只需关心 IP 可达，配置简单 |
| **多租户** | 不同租户的 Overlay 完全隔离 |
| **灵活** | Overlay 可以跨越多个物理站点 |

### 5.3 完整数据流示例

```
VM1 (10.0.1.1, VNI 1000) → VM2 (10.0.1.2, VNI 1000)

┌─────────────────────────────────────────────────────────────────────────┐
│ 1. VM1 发送原始帧                                                        │
│    ┌──────────────────────────────────────────┐                         │
│    │ Dst: MAC2 │ Src: MAC1 │ IP: 10.0.1.1→.2 │                         │
│    └──────────────────────────────────────────┘                         │
│                          │                                               │
│                          ↓                                               │
│ 2. VTEP1 查 EVPN 路由表：MAC2 → VTEP2 (192.168.1.2)                      │
│                          │                                               │
│                          ↓                                               │
│ 3. VTEP1 封装 VXLAN                                                      │
│    ┌─────────────────────────────────────────────────────────────────┐  │
│    │外层MAC│外层IP: 192.168.1.1→.2│UDP:4789│VNI:1000│原始帧          │  │
│    └─────────────────────────────────────────────────────────────────┘  │
│                          │                                               │
│                          ↓                                               │
│ 4. Underlay 路由：VTEP1 → Spine → VTEP2                                  │
│                          │                                               │
│                          ↓                                               │
│ 5. VTEP2 解封装，转发原始帧给 VM2                                         │
└─────────────────────────────────────────────────────────────────────────┘
```

## 六、关键技术补充

### 6.1 ECMP (Equal-Cost Multi-Path)

**定义**：当存在多条等价路径时，将流量均匀分布到所有路径。

```
          ┌─────┐
          │Spine│
          └──┬──┘
     ┌───────┼───────┐
     │       │       │      3条等价路径
     ↓       ↓       ↓      流量 1:1:1 分配
  ┌─────┐ ┌─────┐ ┌─────┐
  │Leaf1│ │Leaf2│ │Leaf3│
  └─────┘ └─────┘ └─────┘

ECMP Hash：基于五元组(SrcIP, DstIP, Protocol, SrcPort, DstPort)
同一个流走同一路径，避免乱序
```

### 6.2 MLAG / VPC (多机箱链路聚合)

**定义**：跨两台交换机的链路聚合，服务器双上行到两台 Leaf，实现冗余。

```
               ┌─────┐     ┌─────┐
               │Spine│     │Spine│
               └──┬──┘     └──┬──┘
                  │           │
        ┌─────────┴───────────┴─────────┐
        │                               │
   ┌────┴────┐    Peer Link        ┌────┴────┐
   │ Leaf 1  │◄═══════════════════►│ Leaf 2  │   MLAG Peer
   └────┬────┘                     └────┬────┘
        │                               │
        └──────────┬────────────────────┘
                   │ LACP Bond (双活)
              ┌────┴────┐
              │ Server  │
              └─────────┘

优点：
- 服务器双活上行，带宽翻倍
- 任一 Leaf 故障不影响服务
- 消除 STP 单点
```

### 6.3 Anycast Gateway (分布式网关)

**定义**：所有 Leaf 配置相同的网关 IP 和 MAC，VM 在任意 Leaf 下都能本地路由。

```
传统集中式网关:              Anycast Gateway:

      ┌─────────┐                  任意 Leaf 都是网关
      │ 网关    │                  GW: 10.0.1.254
      │10.0.1.254│                 MAC: 00:00:5e:00:01:01
      └────┬────┘
           │ 所有流量                ┌─────┐      ┌─────┐
           ↓ 经过网关                │Leaf1│      │Leaf2│
      ┌─────┐                       │ GW  │      │ GW  │
      │Leaf │                       └──┬──┘      └──┬──┘
      └─────┘                          │            │
                                    VM1本地路由   VM2本地路由

优点：
- 消除网关瓶颈
- 本地路由，低延迟
- 网关高可用
```

### 6.4 ARP Suppression

**定义**：VTEP 本地代答 ARP，避免广播泛洪。

```
无 ARP Suppression:           有 ARP Suppression:

VM1: Who has 10.0.1.2?         VM1: Who has 10.0.1.2?
      ↓                              ↓
   广播到所有 VTEP               VTEP1 查 EVPN 表
      ↓                              ↓
   大量 BUM 流量                 本地代答：10.0.1.2 is MAC2
                                     ↓
                                  无广播
```

### 6.5 VRF (Virtual Routing and Forwarding)

**定义**：虚拟路由实例，实现路由表隔离，不同租户可用相同 IP。

```
┌───────────────────────────────────────────────────────────┐
│                      物理交换机                            │
│                                                           │
│   ┌─────────────┐      ┌─────────────┐                   │
│   │   VRF-A     │      │   VRF-B     │                   │
│   │ 租户A路由表  │      │ 租户B路由表  │    相互隔离       │
│   │ 10.0.0.0/8  │      │ 10.0.0.0/8  │    IP可重叠       │
│   └─────────────┘      └─────────────┘                   │
└───────────────────────────────────────────────────────────┘
```

### 6.6 BFD (Bidirectional Forwarding Detection)

**定义**：毫秒级故障检测协议，快速发现链路/邻居故障。

```bash
# 典型配置
BFD 间隔: 100ms
检测倍数: 3
故障检测时间: 300ms (vs OSPF 默认 40秒)
```

## 七、多 Pod 与 DCI

### 7.1 多 Pod 架构

**定义**：超大规模数据中心拆分为多个 Pod，通过 Super Spine 互联。

```
                    ┌───────────────────────────────┐
                    │         Super Spine           │
                    │   (跨Pod互联，高带宽核心)       │
                    └───────────────┬───────────────┘
                                    │
          ┌─────────────────────────┼─────────────────────────┐
          │                         │                         │
    ┌─────┴─────┐             ┌─────┴─────┐             ┌─────┴─────┐
    │   Pod 1   │             │   Pod 2   │             │   Pod 3   │
    │ ┌───────┐ │             │ ┌───────┐ │             │ ┌───────┐ │
    │ │ Spine │ │             │ │ Spine │ │             │ │ Spine │ │
    │ └───┬───┘ │             │ └───┬───┘ │             │ └───┬───┘ │
    │ ┌───┴───┐ │             │ ┌───┴───┐ │             │ ┌───┴───┐ │
    │ │ Leafs │ │             │ │ Leafs │ │             │ │ Leafs │ │
    │ └───────┘ │             │ └───────┘ │             │ └───────┘ │
    │  Servers  │             │  Servers  │             │  Servers  │
    └───────────┘             └───────────┘             └───────────┘

典型规模：
- 每 Pod: 数百台服务器
- Super Spine: 连接数十个 Pod
- 总规模: 数万台服务器
```

### 7.2 DCI (Data Center Interconnect)

**定义**：数据中心互联，将多个物理数据中心连接成逻辑统一的网络。

```
              数据中心 A                         数据中心 B
         ┌─────────────────┐               ┌─────────────────┐
         │   Spine-Leaf    │               │   Spine-Leaf    │
         │                 │               │                 │
         │    ┌──────┐     │               │     ┌──────┐    │
         │    │ DCI  │     │               │     │ DCI  │    │
         │    │ GW   │     │               │     │ GW   │    │
         └────┴──┬───┴─────┘               └─────┴──┬───┴────┘
                 │                                  │
                 │        DCI 链路                   │
                 │   (专线/MPLS/互联网)              │
                 └──────────────────────────────────┘

DCI 技术选项：
┌──────────────┬────────────────────┬─────────────┐
│ 技术         │ 特点               │ 适用场景    │
├──────────────┼────────────────────┼─────────────┤
│ VXLAN+EVPN   │ 二层延伸，标准化   │ 主流方案    │
│ OTV          │ Cisco私有，二层    │ 思科环境    │
│ VPLS         │ MPLS二层VPN       │ 运营商      │
│ SD-WAN       │ 软件定义，灵活     │ 分支互联    │
└──────────────┴────────────────────┴─────────────┘
```

### 7.3 跨 DC 流量优化

```
               ┌─────────────────────────────────────────┐
               │              Global Load Balancer        │
               │        (DNS/Anycast/GSLB)                │
               └───────────────────┬─────────────────────┘
                                   │
                      ┌────────────┴────────────┐
                      ↓                         ↓
               ┌─────────────┐           ┌─────────────┐
               │   DC West   │           │   DC East   │
               │  (主站)     │◄─────────►│  (灾备)     │
               └─────────────┘   同步     └─────────────┘

流量策略：
- 就近访问：用户访问最近DC
- 故障切换：主DC故障时切到备DC
- 读写分离：写入主DC，读取就近DC
```

## 八、SDN 与数据中心网络

### 8.1 SDN 架构

**一句话：SDN 将网络的控制面从设备中抽离，集中到控制器统一管理**

```
传统网络:                       SDN:

┌───────┐  ┌───────┐           ┌──────────────────┐
│ Switch│  │ Switch│           │   SDN Controller │ ← 控制面集中
│控制面 │  │控制面 │           │   (OpenDaylight) │
│转发面 │  │转发面 │           └────────┬─────────┘
└───────┘  └───────┘                    │ OpenFlow/gRPC
    ↑          ↑                        ↓
  分布式      分布式           ┌───────┐  ┌───────┐
  控制面      控制面           │ Switch│  │ Switch│ ← 转发面
                              │(转发) │  │(转发) │
                              └───────┘  └───────┘
```

### 8.2 数据中心 SDN 方案

| 方案 | 说明 |
|------|------|
| **VMware NSX** | 虚拟化网络，VXLAN + 分布式防火墙 |
| **Cisco ACI** | 应用中心基础设施，策略驱动 |
| **OpenStack Neutron** | 开源云网络，支持多种后端 |
| **Calico** | Kubernetes 网络，纯三层 BGP |
| **Cilium** | Kubernetes 网络，eBPF 数据面 |

## 九、AI/GPU 集群网络

### 9.1 AI 训练网络需求

| 需求 | 说明 |
|------|------|
| **超高带宽** | 梯度同步需要 100-400 Gbps |
| **超低延迟** | 集合通信对延迟敏感 |
| **无阻塞** | 全互联带宽 |
| **大规模** | 数千 GPU 互联 |

### 9.2 典型架构

```
                    AI 集群网络架构

┌─────────────────────────────────────────────────────────────┐
│                      存储网络                                │
│                   (NFS/Lustre/GPFS)                         │
└─────────────────────────────────────────────────────────────┘
                           │
┌─────────────────────────────────────────────────────────────┐
│                     管理网络                                 │
│                   (SSH/监控/API)                             │
│                   1-10 Gbps 以太网                          │
└─────────────────────────────────────────────────────────────┘
                           │
┌─────────────────────────────────────────────────────────────┐
│                    计算/训练网络                             │
│              InfiniBand (200-400 Gbps) 或                   │
│              RoCE v2 (100-400 Gbps)                         │
│                                                             │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              Fat-Tree / Rail-Only 拓扑               │   │
│  │                                                      │   │
│  │    Spine (IB/RoCE Switches)                         │   │
│  │         ╱    │    ╲                                 │   │
│  │        ╱     │     ╲                                │   │
│  │     Leaf   Leaf   Leaf                              │   │
│  │       │      │      │                               │   │
│  │    GPU节点 GPU节点 GPU节点                           │   │
│  │    (8xGPU) (8xGPU) (8xGPU)                          │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 9.3 Rail-Optimized 拓扑

**定义**：针对 GPU 间通信模式优化的拓扑，每个 Rail（轨道）连接所有节点的对应 GPU。

```
传统 Fat-Tree:              Rail-Optimized:

所有 GPU 共享同一网络         每个 GPU 位置有独立 "Rail"
带宽竞争                      同位置 GPU 通信无阻塞

Node1: GPU0 GPU1 GPU2 ...    Rail0 ─ GPU0 ─ GPU0 ─ GPU0 (所有Node的GPU0)
Node2: GPU0 GPU1 GPU2 ...    Rail1 ─ GPU1 ─ GPU1 ─ GPU1 (所有Node的GPU1)
Node3: GPU0 GPU1 GPU2 ...    Rail2 ─ GPU2 ─ GPU2 ─ GPU2 ...
        ↓                          ↓
      共享交换机                 独立交换机
```

## 十、网络虚拟化技术

### 10.1 Open vSwitch (OVS)

**定义**：软件实现的多层虚拟交换机，支持 OpenFlow。

```bash
# 创建 OVS 网桥
ovs-vsctl add-br br0

# 添加端口
ovs-vsctl add-port br0 eth0
ovs-vsctl add-port br0 vxlan0 -- set interface vxlan0 \
    type=vxlan options:remote_ip=192.168.1.2

# 查看信息
ovs-vsctl show
ovs-ofctl dump-flows br0

# VXLAN + OVS
ovs-vsctl add-port br0 vxlan100 -- set interface vxlan100 \
    type=vxlan \
    options:key=100 \
    options:remote_ip=192.168.1.2
```

### 10.2 Linux Bridge vs OVS

| 特性 | Linux Bridge | Open vSwitch |
|------|--------------|--------------|
| 复杂度 | 简单 | 复杂 |
| 功能 | 基础二层 | 丰富（OpenFlow、隧道等） |
| 性能 | 原生 | 接近原生（DPDK 加速） |
| 管理 | ip/brctl | ovs-vsctl |
| 适用 | 简单场景 | 云平台/SDN |

### 10.3 SR-IOV

**定义**：Single Root I/O Virtualization，让网卡硬件虚拟化出多个虚拟网卡，直通给 VM/容器。

```
传统虚拟网络:                  SR-IOV:

  VM1      VM2                  VM1      VM2
   │        │                    │        │
   ↓        ↓                    │        │
┌──────────────┐                 │        │
│   vSwitch    │ ← CPU处理       │        │
└──────┬───────┘                 │        │
       │                         ↓        ↓
   ┌───┴───┐                ┌─────────────────┐
   │  NIC  │                │   SR-IOV NIC    │
   └───────┘                │  VF1   VF2  PF  │ ← 硬件虚拟化
                            └─────────────────┘
                            
性能：                       性能：
  VM → vSwitch → NIC          VM → VF → Wire
  延迟高，CPU开销大            接近裸机性能
```

```bash
# 启用 SR-IOV
echo 4 > /sys/class/net/eth0/device/sriov_numvfs

# 查看 VF
ip link show eth0

# 绑定 VF 到 VM (libvirt)
<interface type='hostdev'>
  <source>
    <address type='pci' domain='0x0000' bus='0x03' slot='0x10' function='0x0'/>
  </source>
</interface>
```

## 十一、常用命令与排查

### 11.1 VXLAN 调试

```bash
# 查看 VXLAN 接口详情
ip -d link show vxlan100

# 查看 FDB 表（MAC → VTEP 映射）
bridge fdb show dev vxlan100

# 抓取 VXLAN 流量
tcpdump -i eth0 port 4789 -nn

# 查看 VXLAN 统计
ip -s link show vxlan100
```

### 11.2 BGP EVPN 调试

```bash
# FRRouting
vtysh -c "show bgp l2vpn evpn"
vtysh -c "show bgp l2vpn evpn route type macip"
vtysh -c "show evpn vni"
vtysh -c "show evpn mac vni 1000"

# 查看路由表
ip route show vrf vrf1
```

### 11.3 OVS 调试

```bash
# 查看流表
ovs-ofctl dump-flows br0

# 追踪包路径
ovs-appctl ofproto/trace br0 in_port=1,dl_dst=aa:bb:cc:dd:ee:ff

# 查看端口统计
ovs-ofctl dump-ports br0

# 日志
ovs-appctl vlog/set dpif:dbg
```

---

### 11.4 Underlay 路由调试

```bash
# BGP 状态
vtysh -c "show bgp summary"
vtysh -c "show ip bgp"
vtysh -c "show ip route"

# OSPF 状态
vtysh -c "show ip ospf neighbor"
vtysh -c "show ip ospf route"

# BFD 状态
vtysh -c "show bfd peers"

# ECMP 验证
ip route show | grep nexthop
```

### 11.5 常见故障排查

| 故障现象 | 可能原因 | 排查命令 |
|----------|----------|----------|
| VM 间不通 | VNI 不匹配 | `ip -d link show vxlan*` |
| VTEP 不通 | Underlay 路由问题 | `ping <remote_vtep>`, `traceroute` |
| MAC 学习慢 | EVPN 未同步 | `show bgp l2vpn evpn` |
| 单向通信 | ARP/MAC 未学习 | `bridge fdb show` |
| 性能差 | MTU 问题 (需 ≥1550) | `ip link show`, 抓包看分片 |
