# 802.11 WiFi 协议详解

WiFi 是嵌入式和网络设备中最重要的无线技术之一。本文深入解析 802.11 协议族，从物理层到驱动开发，帮助你全面掌握 WiFi 技术。

---

## 一、802.11 协议族演进

### 1.1 协议版本对照表

```
802.11 协议演进历史：

┌──────────┬──────────┬──────────┬──────────┬──────────┬──────────────┐

│ 802.11   │ -        │ 1997     │ 2.4GHz   │ 2 Mbps   │ FHSS/DSSS    │

│ 802.11b  │ -        │ 1999     │ 2.4GHz   │ 11 Mbps  │ CCK          │
│ 802.11g  │ -        │ 2003     │ 2.4GHz   │ 54 Mbps  │ OFDM         │

### 1.3 DFS（动态频率选择）

```
DFS 机制详解：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  背景：5 GHz 部分频段与雷达共享                                     │
│  ━━━━                                                               │
│  • 气象雷达、军用雷达使用同频段                                     │
│  • WiFi 设备必须实现 DFS 避让                                       │
│                                                                      │
│  DFS 工作流程：                                                      │
│  ━━━━━━━━━━━━                                                       │
│                                                                      │
│  1. CAC（Channel Availability Check）                               │
│     ┌────────────────────────────────────────┐                      │
│     │ 开机后先静默监听 60 秒（部分信道 10 分钟）│                    │
│     │ 检测是否有雷达信号                       │                    │
│     └────────────────────────────────────────┘                      │
│                       ↓                                              │
│  2. 正常工作                                                         │
│     ┌────────────────────────────────────────┐                      │
│     │ 边工作边持续监测雷达信号                 │                    │
│     └────────────────────────────────────────┘                      │
│                       ↓                                              │
│  3. 检测到雷达                                                       │
│     ┌────────────────────────────────────────┐                      │
│     │ 200ms 内停止发射                         │                    │
│     │ 切换到其他信道                           │                    │
│     │ 被占用信道需等待 30 分钟才可重新使用     │                    │
│     └────────────────────────────────────────┘                      │
│                                                                      │
│  DFS 信道列表（中国）：                                              │
│  • Ch 52-64: UNII-2A，需 DFS                                        │
│  • Ch 100-144: UNII-2C，需 DFS                                      │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.2 OFDM（正交频分复用）

```
OFDM 原理详解：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  传统单载波 vs OFDM：                                               │
│  ━━━━━━━━━━━━━━━━━━━                                               │
│                                                                      │
│  单载波（宽带）：                                                    │
│  ┌──────────────────────────────────┐                               │
│  │  █████████████████████████████   │ ← 一个宽频信号                │
│  └──────────────────────────────────┘                               │
│  问题：多径效应导致符号间干扰（ISI）                                │
│                                                                      │
│  OFDM（多窄带子载波）：                                              │
│  ┌──┬──┬──┬──┬──┬──┬──┬──┬──┬──┐                                    │
│  │▓▓│▓▓│▓▓│▓▓│▓▓│▓▓│▓▓│▓▓│▓▓│▓▓│   ← 多个窄带子载波并行            │
│  └──┴──┴──┴──┴──┴──┴──┴──┴──┴──┘                                    │
│  优点：每个子载波视为平坦衰落，抗多径                               │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  OFDM 参数（802.11a/g）：                                           │
│  ━━━━━━━━━━━━━━━━━━━━━                                             │
│  • 总带宽：20 MHz                                                   │
│  • 子载波数：64（52 个用于数据/导频）                               │
│  • 子载波间隔：312.5 kHz                                            │
│  • 符号时间：4 μs（含 0.8 μs 保护间隔）                             │
│                                                                      │
│  802.11ax OFDMA 参数：                                               │
│  ━━━━━━━━━━━━━━━━━━━━                                               │
│  • 子载波间隔：78.125 kHz（更窄，更多子载波）                       │
│  • 符号时间：12.8 μs + 0.8/1.6/3.2 μs GI                            │
│  • 支持更精细的资源分配                                             │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.3 MIMO（多输入多输出）

```
MIMO 技术详解：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  MIMO 基本原理：                                                     │
│  ━━━━━━━━━━━━━                                                      │
│                                                                      │
│     发送端              空间信道              接收端                 │
│    ┌──────┐                                ┌──────┐                 │
│    │ Tx1 ─┼─────────╲    ╱─────────────┼─ Rx1 │                 │
│    │ Tx2 ─┼──────────╲  ╱──────────────┼─ Rx2 │                 │
│    │ Tx3 ─┼───────────╲╱───────────────┼─ Rx3 │                 │
│    │ Tx4 ─┼───────────╱╲───────────────┼─ Rx4 │                 │
│    └──────┘          ╱  ╲              └──────┘                 │
│                                                                      │
│  表示为 NxM MIMO：N 个发送天线，M 个接收天线                        │
│  如 4x4 MIMO 可以同时传输 4 个独立数据流                            │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  MIMO 模式：                                                         │
│  ━━━━━━━━━                                                          │
│                                                                      │
│  1. 空间复用（Spatial Multiplexing）                                │
│     • 多天线同时发送不同数据                                        │
│     • 提高吞吐量                                                    │
│     • 需要接收端有足够天线                                          │
│                                                                      │
│  2. 空间分集（Spatial Diversity）                                   │
│     • 多天线发送相同数据（不同编码）                                │
│     • 提高可靠性                                                    │
│     • 对抗衰落                                                      │
│                                                                      │
│  3. 波束成形（Beamforming）                                         │
│     • 调整各天线相位，形成定向波束                                  │
│     • 增加信号强度                                                  │
│     • 减少干扰                                                      │
│                                                                      │
│     无波束成形        波束成形                                       │
│         *                 *                                         │
│        /|\               /|                                         │
│       / | \             / |                                         │
│      /  |  \           /  |                                         │
│     全向辐射          定向辐射                                       │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  MU-MIMO（多用户 MIMO）：                                           │
│  ━━━━━━━━━━━━━━━━━━━━━                                             │
│                                                                      │
│  SU-MIMO（单用户）：                                                 │
│     AP ──────→ STA1 (4 流)                                          │
│                STA2 等待                                            │
│                                                                      │
│  MU-MIMO（多用户）：                                                 │
│     AP ──────→ STA1 (2 流)                                          │
│        ╲─────→ STA2 (2 流)  同时服务                                │
│                                                                      │
│  802.11ac: 下行 MU-MIMO（最多 4 用户）                              │
│  802.11ax: 上下行 MU-MIMO（最多 8 用户）                            │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 2.4 802.11ax (WiFi 6) PHY 特性

```
WiFi 6 关键 PHY 技术：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  1. OFDMA（正交频分多址）                                           │
│  ━━━━━━━━━━━━━━━━━━━━━━━                                           │
│                                                                      │
│  传统 OFDM（每次一个用户）：                                         │
│  时间 ┌────────────────────────────┐                                │
│   │   │       STA1 (全部子载波)    │                                │
│   ▼   ├────────────────────────────┤                                │
│       │       STA2 (全部子载波)    │                                │
│       └────────────────────────────┘                                │
│                                                                      │
│  OFDMA（多用户并行）：                                               │
│  时间 ┌──────┬──────┬──────┬──────┐                                 │
│   │   │ STA1 │ STA2 │ STA3 │ STA4 │  ← 同一时隙                     │
│   ▼   └──────┴──────┴──────┴──────┘                                 │
│       ← 子载波分配给不同用户 →                                       │
│                                                                      │
│  资源单位（RU）：                                                    │
│  • 26-tone RU：最小单位                                             │
│  • 52-tone, 106-tone, 242-tone, 484-tone, 996-tone                  │
│  • 20 MHz 信道最多支持 9 个用户同时接入                             │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  2. 1024-QAM                                                        │
│  ━━━━━━━━━━━                                                        │
│  • 每符号 10 bits（vs 802.11ac 的 8 bits）                          │
│  • 理论速率提升 25%                                                 │
│  • 需要高信噪比（近距离场景）                                       │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  3. 更长的符号时间                                                   │
│  ━━━━━━━━━━━━━━━                                                    │
│  • 符号时间：12.8 μs（vs 802.11ac 的 3.2 μs）                       │
│  • 子载波间隔：78.125 kHz（vs 312.5 kHz）                           │
│  • 更抗多径干扰，适合室外和高密度场景                               │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  4. BSS Coloring（基本服务集着色）                                  │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                                   │
│  • 每个 BSS 分配一个颜色（6 bits，0-63）                            │
│  • 帧头包含颜色信息                                                 │
│  • 检测到不同颜色的弱信号，可继续发送                               │
│  • 减少 CCA 误判，提高信道利用率                                    │
│                                                                      │
│  传统 CCA：                                                          │
│     检测到任何信号 > -82dBm → 退避                                  │
│                                                                      │
│  BSS Coloring：                                                      │
│     不同颜色信号 > -82dBm → 可忽略（如果足够弱）                    │
│     同颜色信号 > -82dBm → 退避                                      │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```

### 3.3 CSMA/CA（载波监听多点接入/冲突避免）

```

│  ────────────────────────────────────────────────────────────────   │
│                                                                      │

│     是    │    否                                                    │

│  ┌──────────────────┐                                               │

│     ▼                                                                │

│  时序图：                                                            │
│  ┌──────┐  ┌──────────────────┐  ┌───┐  ┌─────┐                    │

### 4.1 扫描与关联流程

```
STA 连接 AP 的完整流程：

│                                                                      │

│  ━━━━━━━━━━━━━━━━━━                                                 │
│                                                                      │
│  被动扫描：                                                          │
│    STA 在各信道监听 Beacon 帧                                       │
│    优点：省电                                                       │
│    缺点：慢（需等待 Beacon 间隔）                                   │

│    缺点：耗电                                                       │
│                                                                      │
│  STA                           AP                                   │
│   │                             │                                   │
│   │────Probe Request (广播)────►│                                   │
│   │                             │                                   │
│   │◄───Probe Response (单播)────│                                   │
│   │                             │                                   │
│                                                                      │

│                                                                      │
│  2. 认证（Authentication）                                          │

│                                                                      │

│                                                                      │

│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  3. 关联（Association）                                             │
│  ━━━━━━━━━━━━━━━━━━━━━                                              │
│                                                                      │
│  STA                           AP                                   │
│   │                             │                                   │
│   │───Association Request──────►│                                   │
│   │   (SSID, 支持的速率, 能力)  │                                   │

│                                                                      │

│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                           │

### 4.2 WPA3 安全增强

```
WPA3 关键特性：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  WPA2 vs WPA3：                                                     │
│  ━━━━━━━━━━━━━                                                      │
│                                                                      │
│  ┌────────────────┬─────────────────┬─────────────────────────────┐│
│  │ 特性            │ WPA2            │ WPA3                        ││
│  ├────────────────┼─────────────────┼─────────────────────────────┤│
│  │ 密钥交换        │ PSK (4-way)     │ SAE (Dragonfly)             ││
│  │ 前向保密        │ 无              │ 有                          ││
│  │ 离线攻击        │ 可能            │ 防护                        ││
│  │ 企业级          │ 192-bit         │ 192-bit 加强                ││
│  │ 开放网络        │ 无加密          │ OWE 加密                    ││
│  │ 管理帧保护      │ 可选            │ 必须                        ││
│  └────────────────┴─────────────────┴─────────────────────────────┘│
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  1. SAE（Simultaneous Authentication of Equals）                    │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                   │
│                                                                      │
│  基于 Dragonfly 密钥交换（椭圆曲线）：                              │
│  • 无需传输密码                                                     │
│  • 即使密码泄露，过去的会话也无法解密（前向保密）                   │
│  • 抗离线字典攻击                                                   │
│                                                                      │
│  SAE 流程：                                                          │
│  STA                           AP                                   │
│   │                             │                                   │
│   │────Commit (标量 + 元素)────►│                                   │
│   │◄───Commit (标量 + 元素)─────│                                   │
│   │                             │                                   │
│   │────Confirm (确认)─────────►│                                   │
│   │◄───Confirm (确认)──────────│                                   │
│   │                             │                                   │
│   │  双方得到相同的 PMK                                             │
│   │  然后进行 4-way handshake                                       │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │

│  ━━━━━━━━━━                                                         │

│                                                                      │
│  6. 驱动/固件                                                        │
│  ━━━━━━━━━━                                                         │

## 九、企业级漫游协议

### 9.1 802.11k/r/v 协议

```
企业级快速漫游协议：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  802.11k（无线资源管理）                                            │
│  ━━━━━━━━━━━━━━━━━━━━━━━                                            │
│  • AP 向 STA 提供邻居 AP 列表                                       │
│  • STA 知道可切换的目标，无需全信道扫描                             │
│  • 加速漫游决策                                                     │
│                                                                      │
│  工作流程：                                                          │
│  STA ──Neighbor Report Request──► AP                                │
│  STA ◄──Neighbor Report Response── AP                               │
│       (包含邻居 AP 的 BSSID、信道、PHY 类型等)                      │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  802.11r（快速 BSS 切换，FT）                                       │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━                                        │
│  • 预认证：在漫游前完成密钥协商                                     │
│  • 减少漫游时的 4-way handshake 延迟                                │
│  • 目标：漫游延迟 < 50ms（VoIP 要求）                               │
│                                                                      │
│  两种模式：                                                          │
│  • Over-the-Air：STA 直接与目标 AP 通信                             │
│  • Over-the-DS：通过当前 AP 中转到目标 AP                           │
│                                                                      │
│  密钥层次（增加 PMK-R0 和 PMK-R1）：                                │
│  MSK → PMK-R0 (Mobility Domain) → PMK-R1 (per-AP) → PTK            │
│                                                                      │
├─────────────────────────────────────────────────────────────────────┤
│                                                                      │
│  802.11v（无线网络管理）                                            │
│  ━━━━━━━━━━━━━━━━━━━━━━━━                                           │
│  • BSS Transition Management：AP 建议 STA 漫游到特定 AP            │
│  • 负载均衡：引导 STA 离开拥挤的 AP                                 │
│  • 省电增强：Extended Sleep Mode                                    │
│                                                                      │
│  BSS Transition 流程：                                               │
│  AP ──BSS Transition Request──► STA                                 │
│       (建议切换到 AP2，包含候选列表)                                │
│  AP ◄──BSS Transition Response── STA                                │
│       (接受/拒绝，并说明原因)                                       │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘

漫游场景最佳实践：
• 启用 802.11k：减少扫描时间
• 启用 802.11r：减少认证时间（需所有 AP 支持）
• 启用 802.11v：实现网络辅助漫游
• RSSI 阈值：通常 -70 到 -75 dBm 触发漫游
• 避免粘滞：调整 STA 漫游灵敏度
```

### 9.2 漫游配置示例

```bash
# hostapd.conf 启用 802.11r
ieee80211r=1
mobility_domain=a1b2           # 所有 AP 使用相同的域 ID
pmk_r1_push=1                   # 主动推送 PMK-R1
ft_over_ds=1                    # 启用 Over-the-DS
nas_identifier=ap1.example.com
r1_key_holder=00:11:22:33:44:55

# 802.11k
rrm_neighbor_report=1
rrm_beacon_report=1

# 802.11v
bss_transition=1
wnm_sleep_mode=1

# wpa_supplicant.conf 客户端配置
network={
    ssid="Enterprise-WiFi"
    key_mgmt=FT-PSK        # 或 FT-EAP
    psk="password"
}
```

## 十、WiFi 安全漏洞

### 10.1 已知漏洞与防护

```
WiFi 重要安全漏洞：

┌─────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  KRACK (2017) - Key Reinstallation Attacks                          │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                         │
│  • 影响：WPA2 四次握手中的密钥重装                                  │
│  • 攻击：强制重用 nonce，可能解密流量                               │
│  • 修复：更新客户端和 AP 固件                                       │
│  • CVE：CVE-2017-13077 至 CVE-2017-13088                            │
│                                                                      │
│  Dragonblood (2019) - WPA3 漏洞                                     │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                                    │
│  • 影响：WPA3-SAE 的 Dragonfly 握手                                 │
│  • 攻击：侧信道攻击可恢复密码                                       │
│  • 修复：WPA3 规范更新、实现补丁                                    │
│  • CVE：CVE-2019-9494 至 CVE-2019-9499                              │
│                                                                      │
│  FragAttacks (2021) - 分片与聚合攻击                                │
│  ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━                             │
│  • 影响：所有 WiFi 协议（设计缺陷 + 实现缺陷）                      │
│  • 攻击：注入恶意帧、窃取数据                                       │
│  • 修复：更新驱动和固件                                             │
│  • CVE：CVE-2020-24586 至 CVE-2020-26145                            │
│                                                                      │
│  Deauthentication 攻击                                               │
│  ━━━━━━━━━━━━━━━━━━━━━━                                             │
│  • 管理帧未认证（WPA2）                                             │
│  • 攻击者可发送伪造 Deauth 帧断开连接                               │
│  • 防护：启用 PMF (802.11w)，WPA3 强制要求                          │
│                                                                      │
│  Evil Twin 攻击                                                      │
│  ━━━━━━━━━━━━━━━                                                    │
│  • 设置同名恶意 AP 诱骗用户连接                                     │
│  • 防护：使用 802.1X 证书认证、VPN                                  │
│                                                                      │
└─────────────────────────────────────────────────────────────────────┘
```
