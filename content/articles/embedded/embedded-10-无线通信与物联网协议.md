# 无线通信与物联网协议

物联网时代，无线通信是嵌入式设备的核心能力。本文从技术原理、选型决策到协议设计，系统讲解无线通信知识。

---

## 一、无线通信技术全景

### 1.1 技术分类与定位

无线通信技术可按**传输距离**和**功耗**两个维度分类：

| 类别 | 技术 | 距离 | 功耗 | 速率 | 典型场景 |
|-----|------|------|------|------|---------|
| 短距离高速 | WiFi | 100m | 高 | Mbps级 | 智能家居、视频传输 |
| 短距离低功耗 | BLE | 50m | 极低 | Kbps级 | 可穿戴、传感器 |
| 中距离低功耗 | ZigBee | 100m | 低 | 250Kbps | 智能家居网状网络 |
| 长距离低功耗 | LoRa | 15km | 极低 | 0.3-50Kbps | 农业、资产追踪 |
| 广域蜂窝 | NB-IoT | 全覆盖 | 低 | 100Kbps | 智慧城市、远程抄表 |
| 广域蜂窝 | 4G Cat.1 | 全覆盖 | 中 | 10Mbps | 车载、视频监控 |

### 1.2 选型决策树

选择无线技术时，需要综合考虑以下因素：

**1. 传输距离**
- 室内10-50米：BLE、WiFi
- 室内/室外100米以内：ZigBee、WiFi
- 郊区1-15公里：LoRa
- 全国覆盖：NB-IoT、4G

**2. 功耗预算**
- 纽扣电池供电5年：BLE、LoRa
- AA电池供电1年：ZigBee、NB-IoT
- 持续供电：WiFi、4G

**3. 数据量**
- 每天几十字节：LoRa、NB-IoT
- 实时小数据流：BLE、ZigBee
- 大数据/视频：WiFi、4G

**4. 网络拓扑**
- 点对点：BLE
- 星型网络：WiFi、LoRa、NB-IoT
- 网状网络：ZigBee、BLE Mesh

**5. 成本考量**
- 模块成本：BLE最低（<¥5），4G最高（>¥50）
- 运营成本：LoRa需建基站，NB-IoT需SIM卡月租

## 二、WiFi技术详解

### 2.1 技术特点

WiFi是目前最成熟的无线局域网技术，主要优势在于**高速率**和**广泛的基础设施**。

| 协议 | 频段 | 最大速率 | 典型功耗 |
|-----|------|---------|---------|
| 802.11b/g | 2.4GHz | 54Mbps | 200mA |
| 802.11n | 2.4/5GHz | 600Mbps | 150mA |
| 802.11ax (WiFi6) | 2.4/5GHz | 9.6Gbps | 100mA |

**功耗分析**：WiFi的高功耗主要来自：
- 射频发射功率高（通常17-20dBm）
- 需要持续监听信道
- 协议开销大（TCP/IP栈）

**低功耗优化策略**：
- 使用DTIM间隔增大beacon监听间隔
- 数据聚合，减少传输次数
- 利用AP的省电模式（PSM）
- 考虑使用WiFi HaLow（802.11ah）用于IoT

### 2.2 常用模块

| 模块 | 芯片 | 特点 | 价格 |
|-----|------|------|------|
| ESP8266 | 乐鑫 | 入门首选，资料丰富 | ¥8 |
| ESP32 | 乐鑫 | WiFi+BLE，性能强 | ¥15 |
| RTL8720 | 瑞昱 | 双频，功耗优化 | ¥20 |

### 2.3 应用场景适配

**适合WiFi的场景**：
- 有稳定供电（市电/大容量电池）
- 需要高速数据传输（音视频、大文件）
- 已有WiFi基础设施
- 对成本不敏感

**不适合WiFi的场景**：
- 电池供电的低功耗设备
- 远距离传输
- 大规模节点部署（AP容量有限）

## 三、蓝牙BLE详解

### 3.1 BLE与经典蓝牙的区别

蓝牙低功耗（BLE）是专为物联网设计的协议，与经典蓝牙有本质区别：

| 特性 | 经典蓝牙 | BLE |
|-----|---------|-----|
| 设计目标 | 持续数据流 | 小数据包间歇传输 |
| 配对 | 复杂 | 简化 |
| 功耗 | 高 | 极低（峰值<15mA） |
| 延迟 | 100ms | 6ms |
| 典型应用 | 音频、文件传输 | 传感器、可穿戴 |

### 3.2 BLE协议栈

BLE协议栈分为三层：

**控制器（Controller）**：
- 物理层（PHY）：1Mbps/2Mbps射频
- 链路层（LL）：连接管理、数据分片

**主机（Host）**：
- L2CAP：逻辑链路控制
- ATT：属性协议，数据读写基础
- GATT：通用属性配置文件，定义服务和特征
- GAP：通用访问配置文件，设备发现和连接

**应用层**：
- 自定义Profile或标准Profile（心率、电池等）

### 3.3 GATT模型

GATT是BLE数据交换的核心，理解GATT是开发BLE应用的关键：

**层次结构**：
```
Profile（配置文件）
  └── Service（服务）：逻辑功能单元，如"心率服务"
        └── Characteristic（特征）：数据单元，如"心率值"
              ├── Value：实际数据
              ├── Properties：读/写/通知属性
              └── Descriptor：元数据描述
```

**UUID**：每个服务和特征用UUID标识
- 标准UUID：16位，如0x180D（心率服务）
- 自定义UUID：128位

### 3.4 BLE低功耗设计要点

**广播模式功耗**：
- 广播间隔越长，功耗越低
- 100ms间隔：~1mA平均电流
- 1s间隔：~100μA平均电流
- 10s间隔：~10μA平均电流

**连接模式功耗**：
- 连接间隔（Connection Interval）是关键参数
- 7.5ms~4s可调，间隔越长越省电
- Slave Latency允许从设备跳过多个连接事件

**最佳实践**：
- 非活跃时使用长广播间隔或停止广播
- 连接后协商较长的连接间隔
- 使用通知（Notify）代替轮询读取
- 数据打包，减少传输次数

## 四、LoRa与LoRaWAN

### 4.1 LoRa技术原理

LoRa（Long Range）是Semtech公司的专有调制技术，核心是**扩频调制**（Chirp Spread Spectrum）。

**技术特点**：
- 工作频段：433/868/915MHz（免授权频段）
- 传输距离：城市2-5km，郊区15km+
- 穿透性强：可穿透多层建筑
- 抗干扰能力强：扩频增益

**扩频因子（SF）**：
SF是LoRa的核心参数，决定了距离与速率的权衡：

| SF | 灵敏度 | 速率 | 空中时间 |
|---|--------|------|---------|
| SF7 | -123dBm | 5.5kbps | 最短 |
| SF9 | -129dBm | 1.8kbps | 中等 |
| SF12 | -137dBm | 0.3kbps | 最长 |

SF每增加1，灵敏度提高2.5dB（距离约增加30%），但速率减半。

### 4.2 LoRaWAN网络架构

LoRaWAN是基于LoRa的网络协议层：

```
终端节点 ──LoRa──► 网关 ──IP──► 网络服务器 ──► 应用服务器
```

**设备分类**：
- Class A：发送后开两个短接收窗口，最省电
- Class B：定时开启接收窗口，延迟可预测
- Class C：持续接收，延迟最低，功耗最高

**典型应用**：
- 智慧农业：土壤监测、灌溉控制
- 资产追踪：物流、车辆定位
- 智慧城市：停车、垃圾桶满溢检测
- 工业监测：远程仪表读数

### 4.3 LoRa vs NB-IoT

这是LPWAN领域最常见的选型困惑：

| 维度 | LoRa | NB-IoT |
|-----|------|--------|
| 频段 | 免授权 | 授权（运营商） |
| 网络 | 需自建或加入 | 运营商现成网络 |
| 覆盖 | 需部署网关 | 全国覆盖 |
| 成本 | 无月租，网关贵 | 模块便宜，有月租 |
| 移动性 | 弱 | 支持切换 |
| QoS | 无保证 | 运营商保证 |

**选LoRa**：私有网络、无运营商覆盖地区、成本敏感
**选NB-IoT**：快速部署、广域覆盖、需要QoS保证

## 五、NB-IoT详解

### 5.1 技术特点

NB-IoT（窄带物联网）是3GPP标准化的蜂窝物联网技术：

**核心优势**：
- 深度覆盖：比GSM增强20dB，可覆盖地下室
- 海量连接：单小区支持5万+设备
- 超低功耗：PSM模式下电流<5μA
- 低成本：模块<¥20，持续降价

**三种部署模式**：
- 独立部署（Standalone）：使用独立频段
- 保护带部署（Guard-band）：利用LTE保护带
- 带内部署（In-band）：占用LTE资源块

### 5.2 省电机制

NB-IoT的省电是精心设计的结果：

**PSM（省电模式）**：
- 设备主动进入深度睡眠
- 不接收寻呼，网络侧保留上下文
- 定时器T3412可配置（最长413天）
- 唤醒后快速恢复，无需重新附着

**eDRX（扩展非连续接收）**：
- 扩展DRX周期，最长2.91小时
- 比PSM响应快，但功耗稍高
- 适合需要一定下行响应能力的场景

**功耗估算**：
- PSM模式：<5μA
- eDRX空闲：~100μA（取决于周期）
- 发送数据：峰值200-400mA，持续<1秒

### 5.3 应用场景

**适合NB-IoT**：
- 智能抄表（水、电、气）
- 智慧城市（路灯、井盖）
- 资产追踪（非实时）
- 环境监测

**不适合NB-IoT**：
- 需要实时响应（延迟可达10秒+）
- 高频次数据上报（会消耗配额）
- 移动场景（切换性能弱）
- 大数据量传输

## 六、MQTT协议

### 6.1 为什么是MQTT

MQTT（Message Queuing Telemetry Transport）已成为IoT事实上的标准协议：

**设计哲学**：
- 为低带宽、高延迟、不可靠网络设计
- 极简协议头（最小2字节）
- 发布/订阅模式，解耦生产者和消费者
- 三种QoS级别，灵活可靠性

**对比HTTP**：

| 维度 | MQTT | HTTP |
|-----|------|------|
| 连接 | 长连接 | 短连接 |
| 协议开销 | 2字节起 | 几百字节 |
| 模式 | 发布/订阅 | 请求/响应 |
| 双向通信 | 原生支持 | 需要轮询或WebSocket |
| 资源消耗 | 低 | 高 |

### 6.2 核心概念

**Broker（代理）**：
MQTT的中心节点，负责消息路由。常用Broker：
- Mosquitto：开源轻量
- EMQX：国产，高性能集群
- AWS IoT Core：云托管

**Topic（主题）**：
消息的分类标识，使用`/`分隔的层级结构：
```
sensors/temperature/living-room
devices/+/status        # +匹配单层
devices/#               # #匹配多层
```

**QoS（服务质量）**：
- QoS 0：最多一次，可能丢失
- QoS 1：至少一次，可能重复
- QoS 2：恰好一次，保证不丢不重

**选择建议**：
- 传感器周期上报：QoS 0（偶尔丢失可接受）
- 状态变更通知：QoS 1
- 关键控制命令：QoS 2

### 6.3 遗嘱与保留消息

**遗嘱消息（Last Will）**：
客户端异常断开时，Broker自动发布预设消息：
- 用于通知设备离线
- 连接时设置，断开时触发

**保留消息（Retained）**：
Broker保存主题的最后一条消息：
- 新订阅者立即收到最新状态
- 适合设备状态发布

### 6.4 安全性

**传输层安全**：
- TLS/SSL加密
- 证书双向认证

**应用层安全**：
- 用户名/密码认证
- ACL访问控制（限制Topic权限）
- Payload加密（应用层自行实现）

## 七、实际选型案例

### 案例1：智能门锁

**需求**：电池供电3年，远程开锁，实时通知

**选型**：NB-IoT + BLE
- NB-IoT：远程控制、状态上报
- BLE：本地手机开锁（省电、低延迟）
- PSM模式待机，事件触发唤醒

### 案例2：工厂环境监测

**需求**：100个节点，实时数据，覆盖5000㎡厂房

**选型**：LoRa私有网络
- 1个网关覆盖全厂
- 无月租成本
- 可接受秒级延迟

### 案例3：智能家居

**需求**：10+设备互联，实时控制

**选型**：WiFi（网关）+ ZigBee（终端）
- ZigBee网状网络，覆盖死角
- WiFi网关连接云端
- Mesh自愈，可靠性高

## 总结

无线技术选型核心原则：

| 需求 | 推荐技术 |
|-----|---------|
| 高速率 | WiFi |
| 极低功耗 | BLE、LoRa |
| 长距离 | LoRa、NB-IoT |
| 全国覆盖 | NB-IoT、4G |
| 网状组网 | ZigBee、BLE Mesh |
| 快速上云 | WiFi、NB-IoT |

没有万能的技术，只有合适的选择。深入理解每种技术的特点和限制，才能做出正确的架构决策。
