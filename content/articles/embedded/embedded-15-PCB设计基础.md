# PCB设计基础

作为嵌入式软件工程师，理解PCB设计基础能帮助你更好地与硬件工程师协作、快速定位问题。本文讲解软件工程师需要掌握的核心硬件知识。

---

## 一、为什么软件工程师需要懂PCB

### 1.1 实际工作中的场景

**调试阶段**：
- 程序运行异常，需判断是软件还是硬件问题
- 读懂原理图，找到测试点
- 理解信号走向，配合示波器调试

**问题定位**：
- 串口不通：是程序配置问题还是线路问题？
- 传感器读数异常：是驱动问题还是接线问题？
- 系统不稳定：是软件Bug还是电源问题？

**设计评审**：
- 评估外设接口是否满足软件需求
- 提出调试接口需求（串口、JTAG）
- 确认GPIO分配是否合理

### 1.2 能力边界

**需要掌握**：
- 读懂原理图
- 理解常见电路的工作原理
- 了解PCB布局对软件的影响
- 基本的测量和调试能力

**不需要精通**：
- PCB Layout细节
- 阻抗计算和仿真
- 复杂的电路设计

## 二、原理图阅读

### 2.1 基本符号

**电源符号**：
- VCC/VDD：正电源
- GND/VSS：地
- 三角形：信号地
- 三条横线逐渐变短：电源地/大地

**常见元器件符号**：

| 元器件 | 符号特征 | 作用 |
|--------|---------|------|
| 电阻 | 锯齿线或矩形 | 限流、分压 |
| 电容 | 两条平行线 | 滤波、耦合 |
| 电感 | 螺旋线圈 | 滤波、储能 |
| 二极管 | 三角形+竖线 | 单向导通 |
| LED | 二极管+箭头 | 发光指示 |
| 晶体管 | 带箭头的三端 | 开关、放大 |
| 运放 | 三角形 | 信号放大 |

**连接符号**：
- 交叉无点：不连接
- 交叉有点：连接
- 网络标签（Net Label）：相同标签表示电气连接

### 2.2 阅读技巧

**模块化阅读**：
原理图通常按功能模块组织：
- 电源模块：找LDO、DC-DC
- MCU模块：找主芯片
- 通信模块：找串口、SPI、I2C接口
- 外设模块：传感器、执行器

**信号追踪**：
从MCU引脚出发，沿着网络标签追踪：
1. 找到MCU的某个GPIO
2. 记录其网络标签
3. 在其他页面找相同标签
4. 了解该信号连接到什么

**常见模式识别**：

| 模式 | 电路特征 | 作用 |
|-----|---------|------|
| 上拉电阻 | 电阻连接VCC和信号 | 默认高电平 |
| 下拉电阻 | 电阻连接GND和信号 | 默认低电平 |
| 分压电路 | 两电阻串联 | 电压检测 |
| RC滤波 | 电阻+电容 | 信号滤波 |
| 退耦电容 | 芯片电源脚旁的小电容 | 滤除噪声 |

### 2.3 关注重点

**对软件有影响的硬件设计**：

| 设计点 | 软件影响 |
|-------|---------|
| Boot引脚 | 决定启动模式 |
| 晶振频率 | 系统时钟配置 |
| 外设接口 | 驱动编写、引脚配置 |
| 复用关系 | GPIO复用设置 |
| 中断引脚 | 中断配置 |
| ADC输入 | 分压比、滤波影响 |

## 三、PCB基础结构

### 3.1 PCB层叠

**双层板**：
```
顶层（Top）：元器件、走线
底层（Bottom）：走线、接地
```
- 成本低，适合简单电路
- 布线空间有限

**四层板**：
```
顶层：信号+元器件
内层1：地平面（GND）
内层2：电源平面（VCC）
底层：信号
```
- 完整的参考平面
- 更好的信号完整性和EMC
- 大多数嵌入式产品使用

**六层及以上**：
高速、高密度设计使用，更多信号层和参考平面。

### 3.2 为什么需要完整地平面

**回流路径**：
电流必须形成闭合回路。高频信号的回流倾向于走信号线正下方的路径。完整地平面提供最短、最低阻抗的回流路径。

**信号完整性**：
地平面作为参考，保证阻抗一致，减少信号反射和串扰。

**EMC**：
地平面起屏蔽作用，减少辐射和抗干扰。

### 3.3 过孔

过孔是连接不同层的垂直通道：

| 类型 | 特点 | 应用 |
|-----|------|------|
| 通孔 | 贯穿所有层 | 最常用 |
| 盲孔 | 从表面到内层 | 高密度 |
| 埋孔 | 内层之间 | 高密度 |

**软件工程师需知**：
过孔会引入电感和阻抗不连续。高速信号（如USB、Ethernet）应尽量减少过孔，或使用多个过孔并联降低阻抗。

## 四、关键Layout原则

### 4.1 电源设计

**退耦电容布局**：
- 每个IC电源引脚旁放置0.1μF电容
- 电容尽量靠近引脚
- 大电容（10μF、100μF）放在电源入口
- 先过电容再到IC

**电源平面分割**：
不同电压域需要隔离，但要确保各区域回流路径完整。

### 4.2 信号布线

**高速信号**：
- 保持阻抗一致（如USB需90Ω差分）
- 差分对等长、等间距
- 避免直角拐弯（用45°或圆弧）
- 参考平面完整，避免跨分割

**敏感信号**：
- 模拟信号远离数字信号
- 时钟信号单独走线，远离其他信号
- 复位信号避免噪声干扰

**串扰防护**：
- 信号间保持距离（3W规则：间距为线宽3倍）
- 敏感信号用地线隔离
- 高速信号包地

### 4.3 接地

**单点接地 vs 多点接地**：
- 低频（<1MHz）：单点接地，避免地环路
- 高频（>10MHz）：多点接地，降低地阻抗
- 混合信号：模拟地和数字地分开，单点汇合

**接地注意事项**：
- 大电流回路不要穿过敏感区域
- 避免地平面开槽切断回流路径
- 连接器的地要可靠连接到系统地

### 4.4 晶振布局

晶振是敏感器件，布局要点：

- 尽量靠近MCU的XTAL引脚
- 晶振下方铺地，不走其他信号
- 负载电容靠近晶振
- 晶振区域用地包围

## 五、常见电路分析

### 5.1 电平转换

不同电压域器件通信需要电平转换：

**电阻分压**：
- 5V→3.3V，只能用于输入方向
- 简单但有延迟和驱动能力限制

**MOS管转换**：
- 双向，常用于I2C电平转换
- 速度适中，成本低

**专用芯片**：
- TXB0108：8通道双向，自动检测方向
- SN74LVC245：8通道单向，带使能
- MAX3232：UART电平转换（TTL↔RS232）

### 5.2 保护电路

**ESD保护**：
- TVS二极管：钳位过压
- 放置在接口入口处

**过流保护**：
- 自恢复保险丝（PTC）
- 限流电阻

**电源反接保护**：
- 串联二极管（简单但有压降）
- P-MOS管（低压降）

### 5.3 复位电路

MCU复位电路设计：

**阻容复位**：
- 上电RC延时
- 简单但不可靠

**专用复位IC**：
- MAX809/810：电压监测复位
- 可靠，推荐使用

**关注点**：
- 复位引脚是否有按键（调试用）
- 复位有效电平（高有效or低有效）
- 复位持续时间要求

## 六、EMC基础

### 6.1 EMC概念

**EMC = EMI + EMS**
- EMI（电磁干扰）：设备对外发射干扰
- EMS（电磁敏感度）：设备抗干扰能力

**为什么软件工程师要关注**：
- EMC问题可能表现为软件异常
- 程序偶发错误、通信偶发失败可能是EMC问题
- 软件可以通过配置减轻EMC问题

### 6.2 常见EMC问题

| 现象 | 可能原因 |
|-----|---------|
| 上电不稳定 | 电源纹波、复位电路 |
| 通信偶发错误 | 信号完整性、串扰 |
| 触摸失灵 | 静电干扰 |
| 程序跑飞 | 辐射干扰进入电源或复位 |
| 时钟异常 | 晶振受干扰 |

### 6.3 软件层面的EMC措施

**GPIO配置**：
- 未用引脚设为输出低或输入带上下拉
- 避免悬空引脚（天线效应）

**时钟管理**：
- 扩频功能可降低EMI峰值
- 关闭不用的外设时钟

**通信校验**：
- 增加CRC校验
- 异常检测和重传机制

**看门狗**：
- 防止EMC导致的程序跑飞

## 七、调试技能

### 7.1 万用表使用

**电压测量**：
- 确认电源电压正确
- 测量关键节点电平
- 检查信号是否存在

**通断测试**：
- 检查连接是否正确
- 排查断路问题

**电阻测量**：
- 确认元件值
- 检查短路（断电测量）

### 7.2 示波器使用

**基本操作**：
- 触发：设置正确的触发条件
- 时基：调整到合适的时间刻度
- 垂直：调整到合适的电压刻度
- 耦合：AC用于看纹波，DC用于看绝对值

**常见测量**：
- 时钟信号：频率、占空比、抖动
- 通信波形：UART、SPI、I2C时序
- 电源纹波：AC耦合测量
- 上电时序：触发上电过程

### 7.3 逻辑分析仪

**适用场景**：
- 多通道数字信号同时观察
- 协议解码（I2C、SPI、UART）
- 长时间录制

**对比示波器**：
- 逻辑分析仪：只看0/1，通道多
- 示波器：看模拟波形，精度高

### 7.4 问题定位思路

**软件还是硬件？**

| 现象 | 倾向 |
|-----|------|
| 固定规律复现 | 软件 |
| 偶发、无规律 | 硬件（电源、EMC） |
| 温度相关 | 硬件 |
| 程序完全不运行 | 硬件（电源、复位） |

**定位步骤**：
1. 确认电源正常
2. 确认时钟正常
3. 确认复位有效释放
4. 用示波器抓关键信号
5. 缩小范围，二分法

## 八、与硬件工程师协作

### 8.1 需求沟通

**软件需要提的需求**：

| 需求类型 | 具体内容 |
|---------|---------|
| 调试接口 | SWD、串口、LED |
| GPIO分配 | 哪些功能需要哪些接口 |
| 时序要求 | 采样速率、通信速率 |
| 电气参数 | 驱动能力、电平匹配 |
| 测试点 | 关键信号引出 |

### 8.2 评审参与

**原理图评审关注**：
- 外设接口是否齐全
- GPIO复用是否冲突
- Boot模式是否可选
- 调试接口是否充分
- 关键参数（晶振频率、分压比）

**Layout评审关注**：
- 调试接口位置是否方便
- 指示灯是否可见
- 按键是否方便操作
- 天线是否预留空间

### 8.3 联调配合

**好的实践**：
- 硬件先验证电源、时钟、复位
- 软件先跑最简单的程序验证基本功能
- 逐步增加功能，缩小问题范围
- 记录问题和解决方案

## 总结

软件工程师需要掌握的PCB知识：

| 能力 | 要点 |
|-----|------|
| 读原理图 | 符号识别、信号追踪、模式识别 |
| 理解PCB | 层叠结构、接地、布线原则 |
| 调试技能 | 万用表、示波器、逻辑分析仪 |
| 问题定位 | 软硬件区分、系统性排查 |
| 团队协作 | 需求表达、评审参与 |

不需要成为硬件专家，但理解这些基础知识会让你成为更全面、更有价值的嵌入式工程师。
