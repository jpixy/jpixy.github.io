# Kubernetes工作负载管理

## 一、Deployment

### 1.1 Deployment概述

Deployment是最常用的工作负载控制器，用于管理无状态应用。

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: nginx-deployment
  labels:
    app: nginx
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 200m
            memory: 256Mi
```

### 1.2 滚动更新策略

```yaml
spec:
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 25%        # 更新时最多超出期望副本数的比例
      maxUnavailable: 25%  # 更新时最多不可用的副本数比例
```

**更新过程**：

```
原始状态：v1 v1 v1 (3个Pod)

maxSurge=1, maxUnavailable=1:

Step 1: v1 v1 v1 v2    (创建1个v2)
Step 2: v1 v1 v2 v2    (删除1个v1，创建1个v2)
Step 3: v1 v2 v2 v2    (删除1个v1，创建1个v2)
Step 4: v2 v2 v2       (删除最后1个v1)
```

### 1.3 更新与回滚

```bash
# 更新镜像
kubectl set image deployment/nginx nginx=nginx:1.22

# 查看更新状态
kubectl rollout status deployment/nginx

# 查看历史版本
kubectl rollout history deployment/nginx

# 回滚到上一版本
kubectl rollout undo deployment/nginx

# 回滚到指定版本
kubectl rollout undo deployment/nginx --to-revision=2

# 暂停更新（用于批量修改）
kubectl rollout pause deployment/nginx

# 恢复更新
kubectl rollout resume deployment/nginx
```

### 1.4 扩缩容

```bash
# 手动扩缩容
kubectl scale deployment nginx --replicas=5

# 基于CPU自动扩缩容
kubectl autoscale deployment nginx --min=2 --max=10 --cpu-percent=80
```

**HPA配置**：

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler
metadata:
  name: nginx-hpa
spec:
  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: nginx
  minReplicas: 2
  maxReplicas: 10
  metrics:
  - type: Resource
    resource:
      name: cpu
      target:
        type: Utilization
        averageUtilization: 80
  - type: Resource
    resource:
      name: memory
      target:
        type: Utilization
        averageUtilization: 80
  behavior:
    scaleDown:
      stabilizationWindowSeconds: 300  # 缩容冷却时间
      policies:
      - type: Percent
        value: 10
        periodSeconds: 60
    scaleUp:
      stabilizationWindowSeconds: 0
      policies:
      - type: Percent
        value: 100
        periodSeconds: 15
```

## 二、StatefulSet

### 2.1 StatefulSet特点

StatefulSet用于有状态应用，提供：

```
稳定的网络标识：
├── 固定的Pod名称：<statefulset-name>-<ordinal>
├── 固定的DNS名称：<pod-name>.<service-name>
└── 重新调度后保持不变

有序部署和删除：
├── 按顺序创建：0, 1, 2...
├── 按逆序删除：...2, 1, 0
└── 可配置并行策略

稳定的持久化存储：
├── 每个Pod有自己的PVC
├── Pod重建后自动挂载原PVC
└── 删除Pod不会删除PVC
```

### 2.2 StatefulSet配置

```yaml
apiVersion: apps/v1
kind: StatefulSet
metadata:
  name: mysql
spec:
  serviceName: mysql-headless  # 必须指定Headless Service
  replicas: 3
  selector:
    matchLabels:
      app: mysql
  template:
    metadata:
      labels:
        app: mysql
    spec:
      containers:
      - name: mysql
        image: mysql:8.0
        ports:
        - containerPort: 3306
        env:
        - name: MYSQL_ROOT_PASSWORD
          valueFrom:
            secretKeyRef:
              name: mysql-secret
              key: password
        volumeMounts:
        - name: data
          mountPath: /var/lib/mysql
  volumeClaimTemplates:  # 自动创建PVC
  - metadata:
      name: data
    spec:
      accessModes: ["ReadWriteOnce"]
      storageClassName: standard
      resources:
        requests:
          storage: 10Gi
```

### 2.3 Headless Service

```yaml
apiVersion: v1
kind: Service
metadata:
  name: mysql-headless
spec:
  clusterIP: None  # Headless Service
  selector:
    app: mysql
  ports:
  - port: 3306
    targetPort: 3306
```

**DNS解析**：

```
Pod DNS格式：
<pod-name>.<headless-service>.<namespace>.svc.cluster.local

示例：
mysql-0.mysql-headless.default.svc.cluster.local
mysql-1.mysql-headless.default.svc.cluster.local
mysql-2.mysql-headless.default.svc.cluster.local
```

### 2.4 更新策略

```yaml
spec:
  updateStrategy:
    type: RollingUpdate  # 或 OnDelete
    rollingUpdate:
      partition: 2  # 只更新序号 >= 2 的Pod
```

**分区更新用例**：

```
用途：金丝雀发布

1. 设置 partition: 2
2. 更新镜像版本
3. 只有 pod-2 会更新，pod-0和pod-1保持旧版本
4. 验证 pod-2 正常后，设置 partition: 0
5. 所有Pod更新到新版本
```

## 三、DaemonSet

### 3.1 DaemonSet概述

DaemonSet确保每个（或指定的）Node上运行一个Pod副本。

**典型用途**：

```
系统守护进程：
├── 日志收集：Fluentd, Filebeat
├── 监控代理：Node Exporter, Datadog Agent
├── 网络插件：Calico, Flannel
├── 存储插件：CSI Driver
└── 安全代理：Falco
```

### 3.2 DaemonSet配置

```yaml
apiVersion: apps/v1
kind: DaemonSet
metadata:
  name: fluentd
  namespace: kube-system
spec:
  selector:
    matchLabels:
      name: fluentd
  template:
    metadata:
      labels:
        name: fluentd
    spec:
      tolerations:
      - key: node-role.kubernetes.io/control-plane
        operator: Exists
        effect: NoSchedule
      containers:
      - name: fluentd
        image: fluentd:v1.14
        resources:
          limits:
            memory: 200Mi
          requests:
            cpu: 100m
            memory: 200Mi
        volumeMounts:
        - name: varlog
          mountPath: /var/log
        - name: containers
          mountPath: /var/lib/docker/containers
          readOnly: true
      volumes:
      - name: varlog
        hostPath:
          path: /var/log
      - name: containers
        hostPath:
          path: /var/lib/docker/containers
```

### 3.3 节点选择

```yaml
spec:
  template:
    spec:
      # 方式1：节点选择器
      nodeSelector:
        disk: ssd
      
      # 方式2：节点亲和性
      affinity:
        nodeAffinity:
          requiredDuringSchedulingIgnoredDuringExecution:
            nodeSelectorTerms:
            - matchExpressions:
              - key: node-type
                operator: In
                values:
                - worker
```

### 3.4 更新策略

```yaml
spec:
  updateStrategy:
    type: RollingUpdate
    rollingUpdate:
      maxUnavailable: 1  # 或百分比
      maxSurge: 0        # DaemonSet通常设为0
```

## 四、Job和CronJob

### 4.1 Job

Job用于运行一次性任务：

```yaml
apiVersion: batch/v1
kind: Job
metadata:
  name: data-migration
spec:
  ttlSecondsAfterFinished: 3600  # 完成后1小时自动清理
  backoffLimit: 4                 # 失败重试次数
  activeDeadlineSeconds: 600      # 最大运行时间
  completions: 1                  # 需要成功完成的Pod数
  parallelism: 1                  # 并行运行的Pod数
  template:
    spec:
      restartPolicy: Never  # Job必须是Never或OnFailure
      containers:
      - name: migration
        image: migration-tool:v1
        command: ["./migrate.sh"]
        env:
        - name: DB_HOST
          value: "mysql.default.svc.cluster.local"
```

**并行Job模式**：

```yaml
# 模式1：固定完成数
completions: 10
parallelism: 3  # 同时运行3个，直到10个成功

# 模式2：工作队列
completions: null  # 不设置
parallelism: 3     # 运行3个worker，由应用决定何时完成
```

### 4.2 CronJob

CronJob用于定时任务：

```yaml
apiVersion: batch/v1
kind: CronJob
metadata:
  name: daily-backup
spec:
  schedule: "0 2 * * *"  # 每天凌晨2点
  timeZone: "Asia/Shanghai"  # K8s 1.27+
  concurrencyPolicy: Forbid  # 禁止并发
  successfulJobsHistoryLimit: 3
  failedJobsHistoryLimit: 1
  startingDeadlineSeconds: 200  # 错过调度的容忍时间
  jobTemplate:
    spec:
      template:
        spec:
          restartPolicy: OnFailure
          containers:
          - name: backup
            image: backup-tool:v1
            command: ["/backup.sh"]
```

**Cron表达式**：

```
┌───────────── 分钟 (0 - 59)
│ ┌───────────── 小时 (0 - 23)
│ │ ┌───────────── 日 (1 - 31)
│ │ │ ┌───────────── 月 (1 - 12)
│ │ │ │ ┌───────────── 星期 (0 - 6，0是周日)
│ │ │ │ │
* * * * *

示例：
"0 * * * *"      - 每小时整点
"0 0 * * *"      - 每天0点
"0 0 * * 0"      - 每周日0点
"0 0 1 * *"      - 每月1号0点
"*/15 * * * *"   - 每15分钟
"0 9-17 * * 1-5" - 工作日9-17点每小时
```

**并发策略**：

```yaml
concurrencyPolicy: Allow   # 允许并发（默认）
concurrencyPolicy: Forbid  # 禁止并发，跳过新任务
concurrencyPolicy: Replace # 替换运行中的任务
```

## 五、ReplicaSet

### 5.1 ReplicaSet概述

ReplicaSet确保指定数量的Pod副本运行。通常由Deployment管理，不直接使用。

```yaml
apiVersion: apps/v1
kind: ReplicaSet
metadata:
  name: nginx-rs
spec:
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
```

### 5.2 与Deployment的关系

```
Deployment
    │
    ├── ReplicaSet (revision 1) ──→ Pod, Pod, Pod
    │
    └── ReplicaSet (revision 2) ──→ Pod, Pod, Pod (新版本)

更新时：
1. Deployment创建新的ReplicaSet
2. 逐步增加新RS的副本数
3. 逐步减少旧RS的副本数
4. 旧RS保留用于回滚
```

## 六、Pod配置详解

### 6.1 容器配置

```yaml
spec:
  containers:
  - name: app
    image: myapp:v1
    imagePullPolicy: Always  # Always/IfNotPresent/Never
    
    # 命令和参数
    command: ["/bin/sh"]
    args: ["-c", "echo hello"]
    
    # 工作目录
    workingDir: /app
    
    # 端口
    ports:
    - name: http
      containerPort: 8080
      protocol: TCP
    
    # 环境变量
    env:
    - name: ENV_VAR
      value: "value"
    - name: POD_NAME
      valueFrom:
        fieldRef:
          fieldPath: metadata.name
    - name: SECRET_VAR
      valueFrom:
        secretKeyRef:
          name: my-secret
          key: password
    
    # 从ConfigMap/Secret加载所有环境变量
    envFrom:
    - configMapRef:
        name: my-config
    - secretRef:
        name: my-secret
```

### 6.2 资源管理

```yaml
resources:
  requests:
    cpu: "100m"       # 0.1 CPU
    memory: "128Mi"   # 128 MiB
  limits:
    cpu: "500m"       # 0.5 CPU
    memory: "256Mi"   # 256 MiB

# CPU单位：
# 1 = 1核
# 1000m = 1核
# 100m = 0.1核

# 内存单位：
# Ki, Mi, Gi, Ti (1024进制)
# K, M, G, T (1000进制)
```

**QoS等级**：

```
Guaranteed：
├── 所有容器设置了相等的requests和limits
├── 最高优先级，最后被驱逐

Burstable：
├── 至少一个容器设置了requests
├── 中等优先级

BestEffort：
├── 没有设置任何requests和limits
├── 最低优先级，最先被驱逐
```

### 6.3 健康检查

```yaml
# 存活探针
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
    httpHeaders:
    - name: Custom-Header
      value: Awesome
  initialDelaySeconds: 30  # 首次检查延迟
  periodSeconds: 10        # 检查间隔
  timeoutSeconds: 5        # 超时时间
  successThreshold: 1      # 成功阈值
  failureThreshold: 3      # 失败阈值

# 就绪探针
readinessProbe:
  tcpSocket:
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5

# 启动探针
startupProbe:
  exec:
    command:
    - cat
    - /tmp/healthy
  failureThreshold: 30
  periodSeconds: 10
```

### 6.4 生命周期钩子

```yaml
lifecycle:
  postStart:
    exec:
      command: ["/bin/sh", "-c", "echo Started > /tmp/started"]
  preStop:
    httpGet:
      path: /shutdown
      port: 8080
    # 或者
    exec:
      command: ["/bin/sh", "-c", "nginx -s quit; while pgrep nginx; do sleep 1; done"]
```

## 七、最佳实践

### 7.1 Deployment最佳实践

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: production-app
  labels:
    app.kubernetes.io/name: myapp
    app.kubernetes.io/version: "1.0.0"
spec:
  replicas: 3
  revisionHistoryLimit: 10  # 保留的历史版本数
  strategy:
    type: RollingUpdate
    rollingUpdate:
      maxSurge: 1
      maxUnavailable: 0  # 确保零停机
  selector:
    matchLabels:
      app: myapp
  template:
    metadata:
      labels:
        app: myapp
    spec:
      # 反亲和性：分散到不同节点
      affinity:
        podAntiAffinity:
          preferredDuringSchedulingIgnoredDuringExecution:
          - weight: 100
            podAffinityTerm:
              labelSelector:
                matchLabels:
                  app: myapp
              topologyKey: kubernetes.io/hostname
      
      # 优雅终止
      terminationGracePeriodSeconds: 60
      
      containers:
      - name: app
        image: myapp:v1.0.0  # 使用具体版本，不用latest
        
        # 资源限制
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 500m
            memory: 512Mi
        
        # 健康检查
        livenessProbe:
          httpGet:
            path: /healthz
            port: 8080
          initialDelaySeconds: 30
          periodSeconds: 10
        
        readinessProbe:
          httpGet:
            path: /ready
            port: 8080
          initialDelaySeconds: 5
          periodSeconds: 5
        
        # 优雅关闭
        lifecycle:
          preStop:
            exec:
              command: ["/bin/sh", "-c", "sleep 5"]
```

### 7.2 选择合适的工作负载

| 场景 | 推荐工作负载 |
|------|-------------|
| 无状态Web应用 | Deployment |
| 数据库、缓存 | StatefulSet |
| 日志、监控代理 | DaemonSet |
| 数据迁移、批处理 | Job |
| 定时备份、清理 | CronJob |

## 八、总结

### 8.1 核心要点

```
Deployment：
├── 无状态应用的标准选择
├── 支持滚动更新和回滚
├── 配合HPA实现自动扩缩容

StatefulSet：
├── 有状态应用的选择
├── 稳定的网络标识和存储
├── 有序的部署和删除

DaemonSet：
├── 每个节点运行一个Pod
├── 适合系统级守护进程
├── 支持节点选择

Job/CronJob：
├── 一次性或定时任务
├── 支持并行和重试
├── 自动清理机制
```
