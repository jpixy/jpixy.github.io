# Kubernetes配置与密钥管理

## 一、ConfigMap详解

### 1.1 创建ConfigMap

**命令行创建**：

```bash
# 从字面值创建
kubectl create configmap my-config \
  --from-literal=key1=value1 \
  --from-literal=key2=value2

# 从文件创建
kubectl create configmap my-config \
  --from-file=config.properties \
  --from-file=settings.json

# 从目录创建
kubectl create configmap my-config \
  --from-file=./config-dir/

# 从环境变量文件创建
kubectl create configmap my-config \
  --from-env-file=app.env
```

**YAML创建**：

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
  namespace: default
data:
  # 简单键值对
  DATABASE_HOST: mysql.default.svc.cluster.local
  DATABASE_PORT: "3306"
  LOG_LEVEL: info
  
  # 多行配置文件
  application.yaml: |
    server:
      port: 8080
      context-path: /api
    spring:
      datasource:
        url: jdbc:mysql://mysql:3306/mydb
        username: ${DB_USER}
        password: ${DB_PASS}
    logging:
      level:
        root: INFO
        com.example: DEBUG
  
  nginx.conf: |
    server {
      listen 80;
      location / {
        proxy_pass http://backend:8080;
      }
    }

binaryData:
  # 二进制数据（base64编码）
  logo.png: iVBORw0KGgoAAAANSUhEUgAAAAE...
```

### 1.2 使用ConfigMap

**作为环境变量**：

```yaml
spec:
  containers:
  - name: app
    image: myapp:v1
    
    # 单个值
    env:
    - name: DB_HOST
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: DATABASE_HOST
    
    # 可选：不存在时不报错
    - name: OPTIONAL_CONFIG
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: optional-key
          optional: true
    
    # 所有键作为环境变量
    envFrom:
    - configMapRef:
        name: app-config
      prefix: CONFIG_  # 可选前缀
```

**作为Volume挂载**：

```yaml
spec:
  containers:
  - name: app
    image: myapp:v1
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
      readOnly: true
  
  volumes:
  - name: config-volume
    configMap:
      name: app-config
      # 可选：指定文件权限
      defaultMode: 0644
      # 可选：只挂载特定键
      items:
      - key: application.yaml
        path: application.yaml
      - key: nginx.conf
        path: nginx/nginx.conf
```

**挂载为单个文件（不覆盖目录）**：

```yaml
volumeMounts:
- name: config-volume
  mountPath: /etc/nginx/nginx.conf
  subPath: nginx.conf
```

### 1.3 ConfigMap热更新

**自动更新的情况**：

```
Volume挂载方式：
├── 约60秒后自动更新
├── 使用subPath时不会自动更新
└── 应用需要监听文件变化或重启
```

**不自动更新的情况**：

```
环境变量方式：
├── 不会自动更新
└── 需要重启Pod
```

**强制触发更新**：

```bash
# 添加注解触发滚动更新
kubectl patch deployment myapp \
  -p '{"spec":{"template":{"metadata":{"annotations":{"configmap-hash":"'$(kubectl get cm app-config -o jsonpath='{.metadata.resourceVersion}')'"}}}}}'
```

## 二、Secret详解

### 2.1 Secret类型

```
Opaque：通用密钥（默认）
kubernetes.io/service-account-token：SA令牌
kubernetes.io/dockerconfigjson：Docker仓库认证
kubernetes.io/tls：TLS证书
kubernetes.io/basic-auth：HTTP基本认证
kubernetes.io/ssh-auth：SSH私钥
```

### 2.2 创建Secret

**命令行创建**：

```bash
# 通用Secret
kubectl create secret generic db-secret \
  --from-literal=username=admin \
  --from-literal=password='S3cureP@ss!'

# 从文件创建
kubectl create secret generic tls-secret \
  --from-file=tls.crt=./server.crt \
  --from-file=tls.key=./server.key

# TLS Secret
kubectl create secret tls my-tls-secret \
  --cert=./tls.crt \
  --key=./tls.key

# Docker仓库认证
kubectl create secret docker-registry regcred \
  --docker-server=registry.example.com \
  --docker-username=user \
  --docker-password=pass \
  --docker-email=user@example.com
```

**YAML创建**：

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: db-secret
type: Opaque
data:
  # base64编码的值
  username: YWRtaW4=        # echo -n "admin" | base64
  password: UzNjdXJlUEBzcyE= # echo -n "S3cureP@ss!" | base64
stringData:
  # 明文（会自动编码）
  api-key: my-api-key-12345
```

```yaml
# TLS Secret
apiVersion: v1
kind: Secret
metadata:
  name: tls-secret
type: kubernetes.io/tls
data:
  tls.crt: LS0tLS1CRUdJTi...
  tls.key: LS0tLS1CRUdJTi...
```

### 2.3 使用Secret

```yaml
spec:
  containers:
  - name: app
    image: myapp:v1
    
    # 作为环境变量
    env:
    - name: DB_PASSWORD
      valueFrom:
        secretKeyRef:
          name: db-secret
          key: password
    
    # 作为Volume挂载
    volumeMounts:
    - name: secret-volume
      mountPath: /etc/secrets
      readOnly: true
  
  # Docker仓库认证
  imagePullSecrets:
  - name: regcred
  
  volumes:
  - name: secret-volume
    secret:
      secretName: db-secret
      defaultMode: 0400  # 只读权限
```

## 三、安全最佳实践

### 3.1 Secret加密存储

**启用etcd加密**：

```yaml
# /etc/kubernetes/encryption-config.yaml
apiVersion: apiserver.config.k8s.io/v1
kind: EncryptionConfiguration
resources:
- resources:
  - secrets
  providers:
  - aescbc:
      keys:
      - name: key1
        secret: <base64-encoded-32-byte-key>
  - identity: {}
```

**kube-apiserver配置**：

```yaml
spec:
  containers:
  - command:
    - kube-apiserver
    - --encryption-provider-config=/etc/kubernetes/encryption-config.yaml
```

### 3.2 RBAC限制

```yaml
# 限制Secret访问
apiVersion: rbac.authorization.k8s.io/v1
kind: Role
metadata:
  name: secret-reader
  namespace: production
rules:
- apiGroups: [""]
  resources: ["secrets"]
  resourceNames: ["app-secret"]  # 只能访问特定Secret
  verbs: ["get"]

---
apiVersion: rbac.authorization.k8s.io/v1
kind: RoleBinding
metadata:
  name: read-app-secret
  namespace: production
subjects:
- kind: ServiceAccount
  name: app-sa
  namespace: production
roleRef:
  kind: Role
  name: secret-reader
  apiGroup: rbac.authorization.k8s.io
```

### 3.3 避免在日志中泄露

```yaml
# 不要在命令参数中使用密钥
spec:
  containers:
  - name: app
    command: 
    - /app
    # 错误：密钥会出现在进程列表和日志中
    # args: ["--password=secret123"]
    
    # 正确：使用环境变量或文件
    env:
    - name: APP_PASSWORD
      valueFrom:
        secretKeyRef:
          name: app-secret
          key: password
```

## 四、外部密钥管理

### 4.1 External Secrets Operator

**安装**：

```bash
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets external-secrets/external-secrets \
  -n external-secrets --create-namespace
```

**配置SecretStore**：

```yaml
# AWS Secrets Manager
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: aws-secrets-manager
spec:
  provider:
    aws:
      service: SecretsManager
      region: us-east-1
      auth:
        secretRef:
          accessKeyIDSecretRef:
            name: aws-credentials
            key: access-key-id
          secretAccessKeySecretRef:
            name: aws-credentials
            key: secret-access-key

---
# HashiCorp Vault
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: vault-backend
spec:
  provider:
    vault:
      server: "https://vault.example.com"
      path: "secret"
      version: "v2"
      auth:
        kubernetes:
          mountPath: "kubernetes"
          role: "my-role"
```

**创建ExternalSecret**：

```yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: database-credentials
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: db-secret  # 生成的K8s Secret名称
    creationPolicy: Owner
  data:
  - secretKey: username
    remoteRef:
      key: prod/database
      property: username
  - secretKey: password
    remoteRef:
      key: prod/database
      property: password
```

### 4.2 Sealed Secrets

**适用于GitOps，可以安全地将Secret提交到Git**：

```bash
# 安装
kubectl apply -f https://github.com/bitnami-labs/sealed-secrets/releases/download/v0.24.0/controller.yaml

# 安装kubeseal CLI
brew install kubeseal

# 加密Secret
kubeseal --format yaml < secret.yaml > sealed-secret.yaml
```

```yaml
# sealed-secret.yaml
apiVersion: bitnami.com/v1alpha1
kind: SealedSecret
metadata:
  name: mysecret
  namespace: default
spec:
  encryptedData:
    password: AgBy3i4OJSWK+PiTySYZZA9rO43cGDEq...
```

### 4.3 Vault Agent Injector

```yaml
# 启用Vault注入
metadata:
  annotations:
    vault.hashicorp.com/agent-inject: "true"
    vault.hashicorp.com/role: "myapp"
    vault.hashicorp.com/agent-inject-secret-db-creds: "secret/data/db/creds"
    vault.hashicorp.com/agent-inject-template-db-creds: |
      {{- with secret "secret/data/db/creds" -}}
      export DB_USER="{{ .Data.data.username }}"
      export DB_PASS="{{ .Data.data.password }}"
      {{- end }}
```

## 五、配置管理模式

### 5.1 环境变量覆盖

```yaml
# 基础配置
apiVersion: v1
kind: ConfigMap
metadata:
  name: base-config
data:
  LOG_LEVEL: info
  MAX_CONNECTIONS: "100"

---
# 环境特定覆盖
apiVersion: v1
kind: ConfigMap
metadata:
  name: prod-config
data:
  LOG_LEVEL: warn
  MAX_CONNECTIONS: "1000"

---
# Pod中加载
spec:
  containers:
  - name: app
    envFrom:
    - configMapRef:
        name: base-config
    - configMapRef:
        name: prod-config  # 后加载的覆盖前面的
```

### 5.2 配置分层

```yaml
# 应用配置
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  config.yaml: |
    app:
      name: myapp
      version: 1.0.0

---
# 环境配置
apiVersion: v1
kind: ConfigMap
metadata:
  name: env-config
data:
  env.yaml: |
    database:
      host: ${DB_HOST}
      port: ${DB_PORT}

---
# Pod配置
spec:
  volumes:
  - name: config
    projected:
      sources:
      - configMap:
          name: app-config
      - configMap:
          name: env-config
      - secret:
          name: db-secret
```

### 5.3 使用Kustomize管理

```yaml
# base/kustomization.yaml
resources:
- deployment.yaml
- service.yaml

configMapGenerator:
- name: app-config
  files:
  - config/application.yaml

secretGenerator:
- name: app-secret
  literals:
  - password=default-password

# overlays/production/kustomization.yaml
bases:
- ../../base

configMapGenerator:
- name: app-config
  behavior: merge
  files:
  - config/application.yaml  # 生产环境配置

secretGenerator:
- name: app-secret
  behavior: replace
  literals:
  - password=production-secret-password
```

## 六、故障排查

### 6.1 常见问题

```bash
# 检查ConfigMap/Secret是否存在
kubectl get configmap,secret

# 查看内容
kubectl describe configmap <name>
kubectl get secret <name> -o yaml

# 解码Secret
kubectl get secret <name> -o jsonpath='{.data.password}' | base64 -d

# 检查Pod中的挂载
kubectl exec <pod> -- ls -la /etc/config
kubectl exec <pod> -- cat /etc/config/application.yaml

# 检查环境变量
kubectl exec <pod> -- env | grep CONFIG
```

```yaml
# 使用initContainer验证配置
initContainers:
- name: check-config
```

## 七、总结

### 7.1 核心要点

```
ConfigMap：
├── 非敏感配置
├── 支持热更新（Volume方式）
├── 可作为环境变量或文件

Secret：
├── 敏感信息
├── base64编码（非加密）
├── 需要额外加密措施

最佳实践：
├── 不要在Git中存储明文Secret
├── 使用外部密钥管理
├── 启用etcd加密
├── 使用RBAC限制访问
└── 定期轮换凭证
```

### 7.2 工具选择

| 场景 | 推荐工具 |
|------|----------|
| GitOps | Sealed Secrets |
| 企业级密钥管理 | External Secrets + Vault/AWS SM |
| 简单场景 | K8s原生Secret + 加密 |
| 多云环境 | External Secrets Operator |
