# Kubernetes存储管理

## 一、存储概述

### 1.1 存储抽象

```
┌─────────────────────────────────────────────────────────────┐
│                        用户层                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │            PersistentVolumeClaim (PVC)              │   │
│  │            "我需要10GB的存储"                        │   │
│  └───────────────────────┬─────────────────────────────┘   │
├──────────────────────────┼──────────────────────────────────┤
│                     Kubernetes层                            │
│  ┌───────────────────────┼─────────────────────────────┐   │
│  │            StorageClass                              │   │
│  │            "定义如何动态创建存储"                    │   │
│  └───────────────────────┬─────────────────────────────┘   │
│  ┌───────────────────────┼─────────────────────────────┐   │
│  │            PersistentVolume (PV)                     │   │
│  │            "10GB的实际存储资源"                      │   │
│  └───────────────────────┬─────────────────────────────┘   │
├──────────────────────────┼──────────────────────────────────┤
│                        存储层                               │
│  ┌───────────────────────┼─────────────────────────────┐   │
│  │    NFS / iSCSI / Ceph / AWS EBS / GCE PD / ...      │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

### 1.2 Volume类型

**临时存储**：

```yaml
volumes:
# emptyDir：Pod生命周期内的临时存储
- name: cache
  emptyDir:
    sizeLimit: 1Gi
    medium: Memory  # 或 "" (磁盘)

# configMap：配置文件
- name: config
  configMap:
    name: my-config
    items:
    - key: config.yaml
      path: config.yaml

# secret：敏感信息
- name: secret
  secret:
    secretName: my-secret
    defaultMode: 0400

# downwardAPI：Pod元数据
- name: podinfo
  downwardAPI:
    items:
    - path: labels
      fieldRef:
        fieldPath: metadata.labels
```

**持久存储**：

```yaml
volumes:
# hostPath：挂载Node目录（谨慎使用）
- name: host-data
  hostPath:
    path: /data
    type: DirectoryOrCreate

# persistentVolumeClaim：持久卷声明
- name: data
  persistentVolumeClaim:
    claimName: my-pvc
```

## 二、PersistentVolume (PV)

### 2.1 PV配置

```yaml
apiVersion: v1
kind: PersistentVolume
metadata:
  name: pv-example
  labels:
    type: ssd
spec:
  capacity:
    storage: 10Gi
  
  # 访问模式
  accessModes:
  - ReadWriteOnce
  
  # 回收策略
  persistentVolumeReclaimPolicy: Retain
  
  # 存储类
  storageClassName: standard
  
  # 挂载选项
  mountOptions:
  - hard
  - nfsvers=4.1
  
  # 具体存储后端
  nfs:
    server: nfs-server.example.com
    path: /exported/path
```

### 2.2 访问模式

```
ReadWriteOnce (RWO)：
├── 单Node读写
├── 最常见
└── 块存储通常只支持RWO

ReadOnlyMany (ROX)：
├── 多Node只读
└── 共享配置/静态文件

ReadWriteMany (RWX)：
├── 多Node读写
├── 需要分布式文件系统支持
└── NFS、CephFS、GlusterFS

ReadWriteOncePod (RWOP)：
├── K8s 1.22+
├── 单Pod读写
└── 更严格的访问控制
```

### 2.3 回收策略

```
Retain：
├── 保留数据
├── 需要手动处理
└── 推荐用于重要数据

Delete：
├── 删除存储资源
├── 动态配置的默认策略
└── 云存储自动删除

Recycle（已废弃）：
└── 基本清除（rm -rf）
```

### 2.4 PV状态

```
Available：可用，未绑定
Bound：已绑定到PVC
Released：PVC已删除，等待回收
Failed：自动回收失败
```

## 三、PersistentVolumeClaim (PVC)

### 3.1 PVC配置

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: my-pvc
spec:
  accessModes:
  - ReadWriteOnce
  
  resources:
    requests:
      storage: 10Gi
  
  storageClassName: standard
  
  # 可选：指定PV
  volumeName: pv-example
  
  # 可选：选择器
  selector:
    matchLabels:
      type: ssd
```

### 3.2 在Pod中使用

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: pod-with-pvc
spec:
  containers:
  - name: app
    image: myapp
    volumeMounts:
    - name: data
      mountPath: /data
      subPath: app-data  # 可选：挂载子目录
  volumes:
  - name: data
    persistentVolumeClaim:
      claimName: my-pvc
```

### 3.3 PVC扩容

```yaml
# StorageClass需要支持扩容
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: expandable-storage
provisioner: kubernetes.io/aws-ebs
allowVolumeExpansion: true  # 启用扩容

# 修改PVC请求大小
spec:
  resources:
    requests:
      storage: 20Gi  # 从10Gi扩展到20Gi
```

```bash
# 扩容命令
kubectl patch pvc my-pvc -p '{"spec":{"resources":{"requests":{"storage":"20Gi"}}}}'
```

## 四、StorageClass

### 4.1 StorageClass配置

```yaml
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: fast-storage
  annotations:
    storageclass.kubernetes.io/is-default-class: "true"
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3
  iopsPerGB: "50"
  encrypted: "true"
reclaimPolicy: Delete
allowVolumeExpansion: true
volumeBindingMode: WaitForFirstConsumer
mountOptions:
- debug
```

### 4.2 常见Provisioner

**云提供商**：

```yaml
# AWS EBS
provisioner: kubernetes.io/aws-ebs
parameters:
  type: gp3       # gp2, gp3, io1, io2, st1, sc1
  iopsPerGB: "50"
  encrypted: "true"
  kmsKeyId: "arn:aws:kms:..."

# GCE PD
provisioner: kubernetes.io/gce-pd
parameters:
  type: pd-ssd    # pd-standard, pd-ssd, pd-balanced
  replication-type: regional-pd

# Azure Disk
provisioner: kubernetes.io/azure-disk
parameters:
  storageaccounttype: Premium_LRS
  kind: Managed
```

**本地/分布式存储**：

```yaml
# NFS (需要nfs-subdir-external-provisioner)
provisioner: nfs-subdir-external-provisioner
parameters:
  archiveOnDelete: "false"

# Ceph RBD
provisioner: rbd.csi.ceph.com
parameters:
  clusterID: ceph-cluster
  pool: kubernetes
  imageFormat: "2"
  imageFeatures: layering

# Local Path Provisioner
provisioner: rancher.io/local-path
```

### 4.3 绑定模式

```yaml
# 立即绑定（默认）
volumeBindingMode: Immediate

# 延迟绑定（等待Pod调度）
volumeBindingMode: WaitForFirstConsumer
```

**WaitForFirstConsumer的优势**：

```
1. 确保PV和Pod在同一Zone/Node
2. 避免跨Zone数据传输
3. 支持本地存储调度
4. 减少资源浪费
```

## 五、CSI (Container Storage Interface)

### 5.1 CSI架构

```
┌─────────────────────────────────────────────────────────────┐
│                    Kubernetes                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              CSI Controller Plugin                   │   │
│  │  (通常作为Deployment部署)                            │   │
│  │  - Provisioner: 创建/删除卷                          │   │
│  │  - Attacher: 挂载/卸载到Node                         │   │
│  │  - Snapshotter: 快照管理                             │   │
│  │  - Resizer: 扩容                                     │   │
│  └─────────────────────────────────────────────────────┘   │
│  ┌─────────────────────────────────────────────────────┐   │
│  │              CSI Node Plugin                         │   │
│  │  (通常作为DaemonSet部署)                             │   │
│  │  - Node服务: 在Node上挂载/卸载卷到Pod               │   │
│  └─────────────────────────────────────────────────────┘   │
├─────────────────────────────────────────────────────────────┤
│                    Storage Backend                          │
│  (AWS EBS, Ceph, NFS, Local, ...)                          │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 CSI驱动示例

```yaml
# AWS EBS CSI Driver StorageClass
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: ebs-csi-gp3
provisioner: ebs.csi.aws.com
parameters:
  type: gp3
  iops: "3000"
  throughput: "125"
  encrypted: "true"
volumeBindingMode: WaitForFirstConsumer
```

## 六、快照与克隆

### 6.1 VolumeSnapshot

```yaml
# VolumeSnapshotClass
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshotClass
metadata:
  name: csi-snapshot-class
driver: ebs.csi.aws.com
deletionPolicy: Delete

# 创建快照
apiVersion: snapshot.storage.k8s.io/v1
kind: VolumeSnapshot
metadata:
  name: my-snapshot
spec:
  volumeSnapshotClassName: csi-snapshot-class
  source:
    persistentVolumeClaimName: my-pvc
```

### 6.2 从快照恢复

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: restored-pvc
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: ebs-csi-gp3
  resources:
    requests:
      storage: 10Gi
  dataSource:
    name: my-snapshot
    kind: VolumeSnapshot
    apiGroup: snapshot.storage.k8s.io
```

### 6.3 PVC克隆

```yaml
apiVersion: v1
kind: PersistentVolumeClaim
metadata:
  name: cloned-pvc
spec:
  accessModes:
  - ReadWriteOnce
  storageClassName: ebs-csi-gp3
  resources:
    requests:
      storage: 10Gi
  dataSource:
    name: source-pvc
    kind: PersistentVolumeClaim
```

## 七、ConfigMap和Secret

### 7.1 ConfigMap

```yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  # 键值对
  database_host: mysql.default.svc.cluster.local
  log_level: info
  
  # 文件内容
  config.yaml: |
    server:
      port: 8080
      host: 0.0.0.0
    database:
      host: mysql
      port: 3306
```

**使用方式**：

```yaml
spec:
  containers:
  - name: app
    # 作为环境变量
    env:
    - name: DB_HOST
      valueFrom:
        configMapKeyRef:
          name: app-config
          key: database_host
    
    # 全部注入为环境变量
    envFrom:
    - configMapRef:
        name: app-config
    
    # 作为文件挂载
    volumeMounts:
    - name: config-volume
      mountPath: /etc/config
  volumes:
  - name: config-volume
    configMap:
      name: app-config
      items:
      - key: config.yaml
        path: config.yaml
```

### 7.2 Secret

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secret
type: Opaque
data:
  # base64编码
  password: cGFzc3dvcmQxMjM=
stringData:
  # 明文（自动编码）
  api-key: my-secret-api-key
```

**Secret类型**：

```
Opaque：任意数据（默认）
kubernetes.io/service-account-token：ServiceAccount令牌
kubernetes.io/dockerconfigjson：Docker认证
kubernetes.io/tls：TLS证书
kubernetes.io/basic-auth：基本认证
kubernetes.io/ssh-auth：SSH认证
```

**创建Docker认证Secret**：

```bash
kubectl create secret docker-registry regcred \
  --docker-server=https://index.docker.io/v1/ \
  --docker-username=user \
  --docker-password=pass \
  --docker-email=user@example.com
```

## 八、最佳实践

### 8.1 存储选择

| 场景 | 推荐存储 | 访问模式 |
|------|----------|----------|
| 数据库 | 块存储 (EBS/PD) | RWO |
| 日志/文件共享 | NFS/CephFS | RWX |
| 缓存 | emptyDir (内存) | - |
| 静态配置 | ConfigMap | - |
| 敏感信息 | Secret | - |
| 本地高性能 | Local PV | RWO |

### 8.2 数据保护

```yaml
# 1. 使用Retain回收策略
persistentVolumeReclaimPolicy: Retain

# 2. 定期备份
# - VolumeSnapshot
# - 应用级备份（mysqldump等）
# - Velero备份

# 3. 使用加密存储
parameters:
  encrypted: "true"

# 4. 设置适当的accessModes
accessModes:
- ReadWriteOnce
```

### 8.3 性能优化

```yaml
# 1. 选择合适的存储类型
parameters:
  type: gp3  # SSD
  iops: "3000"
  throughput: "125"

# 2. 使用WaitForFirstConsumer
volumeBindingMode: WaitForFirstConsumer

# 3. 本地存储用于高性能场景
apiVersion: storage.k8s.io/v1
kind: StorageClass
metadata:
  name: local-storage
provisioner: kubernetes.io/no-provisioner
volumeBindingMode: WaitForFirstConsumer
```

### 8.4 安全建议

```yaml
# 1. Secret加密存储
# 在kube-apiserver配置加密

# 2. 限制Secret访问
# 使用RBAC限制

# 3. 使用外部Secret管理
# - HashiCorp Vault
# - AWS Secrets Manager
# - External Secrets Operator

# 4. 定期轮换凭证
```

## 九、总结

### 9.1 核心概念

```
存储抽象层次：
├── PVC：用户声明（我需要什么）
├── StorageClass：动态配置（如何创建）
└── PV：实际存储（有什么）

关键决策：
├── 持久 vs 临时
├── 单节点 vs 多节点
├── 块存储 vs 文件存储
└── 性能 vs 成本
```

### 9.2 故障排查

```bash
# 检查PV/PVC状态
kubectl get pv,pvc

# 查看详细信息
kubectl describe pvc <pvc-name>

# 检查事件
kubectl get events --field-selector involvedObject.name=<pvc-name>

# 检查StorageClass
kubectl get storageclass

# 检查CSI驱动
kubectl get pods -n kube-system | grep csi
```
