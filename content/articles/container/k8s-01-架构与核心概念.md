# Kubernetes架构与核心概念

## 一、Kubernetes概述

### 1.1 什么是Kubernetes

Kubernetes（K8s）是Google开源的容器编排平台，用于自动化部署、扩展和管理容器化应用。

**核心价值**：

```
容器编排：
├── 自动化部署和回滚
├── 服务发现和负载均衡
├── 存储编排
├── 自动装箱（资源调度）
├── 自我修复
├── 密钥和配置管理
└── 水平扩缩容
```

### 1.2 K8s与Docker的关系

```
容器运行时演进：

Docker时代（早期）：
├── Docker = 容器运行时 + 镜像构建 + 编排
└── K8s使用Docker作为运行时

CRI标准化（现在）：
├── K8s通过CRI接口对接容器运行时
├── 支持多种运行时：containerd、CRI-O
├── Docker镜像格式仍是标准（OCI）
└── 1.24+版本移除dockershim

关系总结：
├── Docker：构建镜像的工具
├── containerd：容器运行时
└── Kubernetes：容器编排平台
```

### 2.2 Control Plane组件

**API Server（kube-apiserver）**：

```yaml
职责：
  - 集群的统一入口
  - 所有组件通过API Server通信
  - RESTful API接口
  - 认证、授权、准入控制
  - 数据持久化到etcd

特点：
  - 无状态，可水平扩展
  - 支持Watch机制
  - OpenAPI规范
```

**etcd**：

```yaml
职责：
  - 分布式KV存储
  - 存储集群所有配置和状态
  - 唯一的持久化存储

特点：
  - Raft一致性协议
  - 高可用（奇数节点）
  - 支持Watch
  - 关键：备份和恢复

最佳实践：
  - 独立部署，不与Master混部
  - SSD存储
  - 定期备份
  - 监控延迟和磁盘使用
```

**Scheduler（kube-scheduler）**：

```yaml
职责：
  - 为新创建的Pod选择Node
  - 根据资源需求、约束条件调度

调度流程：
  1. 过滤（Filtering）：排除不满足条件的Node
  2. 打分（Scoring）：对候选Node评分
  3. 绑定（Binding）：选择最高分Node

考虑因素：
  - 资源需求（CPU、内存）
  - 亲和性/反亲和性
  - 污点和容忍
  - 数据本地性
  - Pod优先级
```

**Controller Manager（kube-controller-manager）**：

```yaml
职责：
  - 运行各种控制器
  - 确保集群状态符合期望状态

主要控制器：
  - Node Controller：节点健康检查
  - Replication Controller：Pod副本数
  - Endpoints Controller：Service端点
  - ServiceAccount Controller：账户管理
  - Deployment Controller：部署管理
  - StatefulSet Controller：有状态应用
  - DaemonSet Controller：守护进程
  - Job Controller：批处理任务

控制循环：
  观察 → 对比 → 执行（Watch → Diff → Act）
```

### 2.3 Node组件

**kubelet**：

```yaml
职责：
  - 每个Node上的代理
  - 接收PodSpec，确保容器运行
  - 向API Server报告节点和Pod状态
  - 容器健康检查

功能：
  - Pod生命周期管理
  - 容器运行时接口（CRI）
  - 存储卷挂载（CSI）
  - 网络配置（CNI）
  - 资源监控
```

**kube-proxy**：

```yaml
职责：
  - 实现Service的网络代理
  - 维护节点上的网络规则

实现模式：
  - iptables（默认）：规则数量多时性能下降
  - IPVS：高性能，支持多种负载均衡算法
  - userspace：已废弃

功能：
  - Service ClusterIP
  - NodePort
  - LoadBalancer
  - SessionAffinity
```

**Container Runtime**：

```yaml
支持的运行时：
  - containerd（推荐）
  - CRI-O
  - Docker（通过cri-dockerd）

CRI接口：
  - RuntimeService：容器生命周期
  - ImageService：镜像管理
```

## 三、核心概念

### 3.1 Pod

**Pod是K8s的最小调度单位**：

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod
  labels:
    app: nginx
spec:
  containers:
  - name: nginx
    image: nginx:1.21
    ports:
    - containerPort: 80
    resources:
      requests:
        memory: "64Mi"
        cpu: "250m"
      limits:
        memory: "128Mi"
        cpu: "500m"
```

**Pod特点**：

```
共享资源：
├── 网络命名空间（共享IP和端口）
├── IPC命名空间
├── 存储卷
└── 可选共享PID命名空间

生命周期：
├── Pending：等待调度
├── Running：正在运行
├── Succeeded：成功完成
├── Failed：失败
└── Unknown：未知状态

设计原则：
├── Pod是临时的，随时可能被替换
├── 不要直接创建Pod，使用Controller
├── 一个Pod一个主进程（通常）
└── Sidecar模式用于辅助容器
```

### 3.2 Label和Selector

**Label（标签）**：

```yaml
metadata:
  labels:
    app: myapp
    environment: production
    version: v1.0.0
    tier: frontend
```

**Selector（选择器）**：

```yaml
# 等值选择
selector:
  matchLabels:
    app: myapp
    environment: production

# 集合选择
selector:
  matchExpressions:
  - key: environment
    operator: In
    values: [production, staging]
  - key: tier
    operator: NotIn
    values: [backend]
```

### 3.3 Namespace

**命名空间用于资源隔离**：

```yaml
apiVersion: v1
kind: Namespace
metadata:
  name: development
  labels:
    env: dev
```

**默认命名空间**：

```
default：默认命名空间
kube-system：系统组件
kube-public：公共资源
kube-node-lease：节点心跳
```

### 3.4 Annotation

**注解用于存储非标识性元数据**：

```yaml
metadata:
  annotations:
    description: "This is my application"
    prometheus.io/scrape: "true"
    prometheus.io/port: "8080"
    kubernetes.io/change-cause: "Update to v2.0"
```

## 四、API对象模型

### 4.1 声明式API

**声明式 vs 命令式**：

```
命令式：
kubectl run nginx --image=nginx
kubectl scale deployment nginx --replicas=3
kubectl set image deployment/nginx nginx=nginx:1.21

声明式（推荐）：
kubectl apply -f deployment.yaml
```

**声明式优势**：

```
├── 配置即代码，可版本控制
├── 幂等性，多次执行结果一致
├── 支持GitOps工作流
├── 审计和回滚
└── 团队协作友好
```

### 4.2 API对象结构

**标准结构**：

```yaml
apiVersion: apps/v1        # API版本
kind: Deployment           # 资源类型
metadata:                  # 元数据
  name: nginx-deployment
  namespace: default
  labels:
    app: nginx
  annotations:
    description: "Nginx deployment"
spec:                      # 期望状态
  replicas: 3
  selector:
    matchLabels:
      app: nginx
  template:
    metadata:
      labels:
        app: nginx
    spec:
      containers:
      - name: nginx
        image: nginx:1.21
status:                    # 实际状态（由系统填充）
  replicas: 3
  readyReplicas: 3
  availableReplicas: 3
```

### 4.3 API版本

```
API版本演进：
├── Alpha（v1alpha1）：实验性，可能随时删除
├── Beta（v1beta1）：基本稳定，可能有小变化
└── Stable（v1）：稳定版本，向后兼容

查看API资源：
kubectl api-resources
kubectl api-versions
kubectl explain <resource>
```

## 五、控制器模式

### 5.1 控制循环

**Reconciliation Loop**：

```
                    ┌─────────────┐
                    │   Observe   │
                    │ (Watch API) │
                    └──────┬──────┘
                           │
                           ▼
          ┌────────────────────────────────┐
          │     Compare                     │
          │  (Desired State vs Actual)      │
          └────────────────┬───────────────┘
                           │
                           ▼
                    ┌─────────────┐
                    │    Act      │
                    │ (Reconcile) │
                    └──────┬──────┘
                           │
                           └──────→ 循环
```

### 5.2 常见控制器

| 控制器 | 用途 | 特点 |
|--------|------|------|
| Deployment | 无状态应用 | 支持滚动更新、回滚 |
| StatefulSet | 有状态应用 | 稳定网络标识、有序部署 |
| DaemonSet | 守护进程 | 每个Node运行一个 |
| Job | 批处理任务 | 运行完成后退出 |
| CronJob | 定时任务 | 按计划执行 |
| ReplicaSet | 副本管理 | 被Deployment管理 |

## 六、最佳实践

### 6.1 资源配置

```yaml
# 始终设置资源请求和限制
resources:
  requests:
    memory: "128Mi"
    cpu: "100m"
  limits:
    memory: "256Mi"
    cpu: "200m"

# 建议：
# - requests用于调度决策
# - limits用于防止资源争用
# - limits >= requests
# - 内存limits建议设置，CPU可选
```

### 6.2 健康检查

```yaml
# 存活探针：检测容器是否运行
livenessProbe:
  httpGet:
    path: /healthz
    port: 8080
  initialDelaySeconds: 30
  periodSeconds: 10

# 就绪探针：检测是否可以接收流量
readinessProbe:
  httpGet:
    path: /ready
    port: 8080
  initialDelaySeconds: 5
  periodSeconds: 5

# 启动探针：检测应用是否启动完成
startupProbe:
  httpGet:
    path: /healthz
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
```

### 6.3 标签规范

```yaml
# 推荐的标签
metadata:
  labels:
    # 标准标签
    app.kubernetes.io/name: myapp

    app.kubernetes.io/version: "1.0.0"
    app.kubernetes.io/component: frontend
    app.kubernetes.io/part-of: myplatform
    app.kubernetes.io/managed-by: helm
    
    # 自定义标签
    environment: production
    team: platform
    cost-center: engineering
```

## 七、总结

### 7.1 核心要点

```
架构理解：
├── Master负责控制平面
├── Node负责运行工作负载
├── 所有组件通过API Server通信
└── etcd是唯一的持久化存储

核心概念：
├── Pod是最小调度单位
├── Label/Selector用于资源关联
├── Namespace用于资源隔离
└── 控制器确保期望状态

设计原则：
├── 声明式优于命令式
├── 控制器模式驱动
├── 松耦合、可扩展
└── 自愈能力
```

### 7.2 学习路径

```
入门：Pod、Deployment、Service
进阶：StatefulSet、DaemonSet、ConfigMap、Secret
高级：网络策略、RBAC、调度策略
运维：监控、日志、故障排查
```
