# Kubernetes运维与故障排查

## 一、日常运维

### 1.1 集群健康检查

```bash
# 检查节点状态
kubectl get nodes -o wide
kubectl describe node <node-name>

# 检查组件状态
kubectl get componentstatuses  # 已废弃但仍可用
kubectl get --raw='/readyz?verbose'
kubectl get --raw='/healthz?verbose'

# 检查系统Pod
kubectl get pods -n kube-system

# 检查API Server
kubectl cluster-info
kubectl version

# 检查etcd
ETCDCTL_API=3 etcdctl endpoint health \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key
```

### 1.2 资源管理

```bash
# 查看资源使用情况
kubectl top nodes
kubectl top pods -A

# 查看资源配额
kubectl get resourcequota -A
kubectl describe resourcequota <name> -n <namespace>

# 查看限制范围
kubectl get limitrange -A

# 资源清理
kubectl delete pod --field-selector=status.phase==Succeeded -A
kubectl delete pod --field-selector=status.phase==Failed -A
```

**ResourceQuota配置**：

```yaml
apiVersion: v1
kind: ResourceQuota
metadata:
  name: compute-quota
  namespace: production
spec:
  hard:
    requests.cpu: "100"
    requests.memory: 100Gi
    limits.cpu: "200"
    limits.memory: 200Gi
    pods: "100"
    persistentvolumeclaims: "50"
    services.loadbalancers: "5"
```

### 1.3 节点管理

```bash
# 节点维护（排空工作负载）
kubectl cordon <node>  # 标记不可调度
kubectl drain <node> --ignore-daemonsets --delete-emptydir-data
# 执行维护...
kubectl uncordon <node>  # 恢复调度

# 添加/删除标签
kubectl label nodes <node> disktype=ssd
kubectl label nodes <node> disktype-

# 添加/删除污点
kubectl taint nodes <node> key=value:NoSchedule
kubectl taint nodes <node> key-
```

## 二、监控体系

### 2.1 Prometheus监控栈

```
┌─────────────────────────────────────────────────────────────┐
│                    Grafana (可视化)                         │
├─────────────────────────────────────────────────────────────┤
│                   Prometheus (存储/查询)                    │
├─────────────────────────────────────────────────────────────┤
│  Node Exporter │ kube-state-metrics │ cAdvisor │ 应用指标  │
└─────────────────────────────────────────────────────────────┘
```

**kube-prometheus-stack安装**：

```bash
helm repo add prometheus-community https://prometheus-community.github.io/helm-charts
helm install prometheus prometheus-community/kube-prometheus-stack \
  -n monitoring --create-namespace \
  --set grafana.adminPassword=admin
```

### 2.2 关键监控指标

**节点指标**：

```
# CPU使用率
100 - (avg by(instance) (irate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)

# 内存使用率
(1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) * 100

# 磁盘使用率
(1 - node_filesystem_avail_bytes / node_filesystem_size_bytes) * 100

# 网络IO
irate(node_network_receive_bytes_total[5m])
irate(node_network_transmit_bytes_total[5m])
```

**Pod指标**：

```
# Pod CPU使用
sum(rate(container_cpu_usage_seconds_total{pod!=""}[5m])) by (pod)

# Pod内存使用
sum(container_memory_working_set_bytes{pod!=""}) by (pod)

# Pod重启次数
kube_pod_container_status_restarts_total

# Pod状态
kube_pod_status_phase
```

**集群指标**：

```
# API Server请求延迟
histogram_quantile(0.99, sum(rate(apiserver_request_duration_seconds_bucket[5m])) by (verb, le))

# API Server错误率
sum(rate(apiserver_request_total{code=~"5.."}[5m])) / sum(rate(apiserver_request_total[5m]))

# etcd延迟
histogram_quantile(0.99, sum(rate(etcd_disk_wal_fsync_duration_seconds_bucket[5m])) by (le))
```

### 2.3 告警规则

```yaml
apiVersion: monitoring.coreos.com/v1
kind: PrometheusRule
metadata:
  name: kubernetes-alerts
  namespace: monitoring
spec:
  groups:
  - name: kubernetes
    rules:
    - alert: PodCrashLooping
      expr: rate(kube_pod_container_status_restarts_total[15m]) > 0
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "Pod {{ $labels.pod }} is crash looping"
    
    - alert: NodeNotReady
      expr: kube_node_status_condition{condition="Ready",status="true"} == 0
      for: 5m
      labels:
        severity: critical
      annotations:
        summary: "Node {{ $labels.node }} is not ready"
    
    - alert: HighMemoryUsage
      expr: (1 - node_memory_MemAvailable_bytes / node_memory_MemTotal_bytes) > 0.9
      for: 5m
      labels:
        severity: warning
      annotations:
        summary: "High memory usage on {{ $labels.instance }}"
```

## 四、故障排查

### 4.1 Pod故障排查

**Pod状态分析**：

```
Pending：
├── 资源不足 → kubectl describe pod 查看Events
├── 无匹配节点 → 检查nodeSelector/affinity
├── PVC未绑定 → kubectl get pvc
└── 镜像拉取问题 → 检查ImagePullSecrets

ImagePullBackOff：
├── 镜像不存在 → 检查镜像名称和标签
├── 认证失败 → 检查imagePullSecrets
└── 网络问题 → 测试节点网络

CrashLoopBackOff：
├── 应用启动失败 → kubectl logs
├── 配置错误 → 检查ConfigMap/Secret
├── 资源限制 → 检查OOMKilled
└── 探针配置错误 → 检查livenessProbe

Evicted：
├── 节点资源压力 → kubectl describe node
└── 磁盘满 → 检查节点磁盘

OOMKilled：
├── 内存不足 → 增加limits.memory
└── 内存泄漏 → 检查应用
```

**排查命令**：

```bash
# 查看Pod详情
kubectl describe pod <pod>

# 查看日志
kubectl logs <pod> --previous

# 进入容器调试
kubectl exec -it <pod> -- /bin/sh

# 使用debug容器
kubectl debug -it <pod> --image=busybox --target=<container>

# 复制文件
kubectl cp <pod>:/path/file ./local-file
```

### 4.2 网络故障排查

```bash
# 部署网络调试Pod
kubectl run netshoot --image=nicolaka/netshoot --rm -it -- bash

# DNS测试
```

### 4.3 存储故障排查

```bash

# 检查挂载

# 检查存储事件

```

### 4.4 节点故障排查

```bash

# SSH到节点检查
```

## 五、备份与恢复

### 5.1 etcd备份

```bash
# 创建快照
ETCDCTL_API=3 etcdctl snapshot save /backup/etcd-snapshot.db \
  --endpoints=https://127.0.0.1:2379 \
  --cacert=/etc/kubernetes/pki/etcd/ca.crt \
  --cert=/etc/kubernetes/pki/etcd/server.crt \
  --key=/etc/kubernetes/pki/etcd/server.key

# 验证快照
ETCDCTL_API=3 etcdctl snapshot status /backup/etcd-snapshot.db

# 恢复快照
ETCDCTL_API=3 etcdctl snapshot restore /backup/etcd-snapshot.db \
  --data-dir=/var/lib/etcd-new
```

### 5.2 Velero备份

```bash
# 安装Velero
velero install \
  --provider aws \
  --plugins velero/velero-plugin-for-aws:v1.5.0 \
  --bucket velero-backup \
  --backup-location-config region=us-east-1 \
  --snapshot-location-config region=us-east-1 \
  --secret-file ./credentials-velero

# 创建备份
velero backup create mybackup --include-namespaces production

# 查看备份
velero backup get
velero backup describe mybackup

# 恢复
velero restore create --from-backup mybackup
```

### 6.2 资源优化

```yaml
# Vertical Pod Autoscaler
apiVersion: autoscaling.k8s.io/v1
kind: VerticalPodAutoscaler
metadata:
  name: myapp-vpa
spec:
  targetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: myapp
  updatePolicy:
    updateMode: "Auto"  # Off/Initial/Recreate/Auto
  resourcePolicy:
    containerPolicies:
    - containerName: app
      minAllowed:
        cpu: 100m
        memory: 128Mi
      maxAllowed:
        cpu: 2
        memory: 2Gi
```

```
□ 节点状态

□ 改进措施
```

### 8.2 故障排查流程

```
1. 确认问题范围
   └── 单Pod/多Pod/节点/集群？

2. 收集信息
   ├── kubectl describe
   ├── kubectl logs
   ├── kubectl get events
   └── 监控指标

3. 定位原因
   ├── 资源问题？
   ├── 网络问题？
   ├── 存储问题？
   ├── 配置问题？
   └── 应用问题？

4. 解决问题
   ├── 临时修复
   └── 根本解决

5. 事后复盘
   ├── 根因分析
   ├── 改进措施
   └── 文档更新
```
