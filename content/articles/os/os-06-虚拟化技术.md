## 虚拟化概述

### 定义

虚拟化是将物理资源抽象为多个逻辑资源的技术。一台物理机可以运行多个虚拟机，每个虚拟机像独立的计算机一样运行操作系统。

### 类型

**硬件虚拟化**：模拟完整的硬件环境，运行未修改的操作系统。

**操作系统虚拟化（容器）**：共享内核，隔离用户空间。

**应用虚拟化**：如JVM，在虚拟机中运行特定应用。

### 虚拟化的价值

**资源整合**：多个虚拟机共享物理资源，提高利用率。

**隔离**：虚拟机之间相互隔离，故障不扩散。

**灵活性**：快速创建、销毁、迁移虚拟机。

**兼容性**：运行不同操作系统或旧版软件。

## CPU虚拟化

### 经典虚拟化问题

x86最初不是为虚拟化设计的。某些敏感指令在用户态执行不会触发异常，但行为与内核态不同。

虚拟机中的操作系统以为自己在Ring 0，实际在Ring 1或Ring 3。直接执行敏感指令会得到错误结果。

### 全虚拟化

**二进制翻译**：VMware早期方案。扫描客户机代码，将敏感指令替换为安全的模拟代码。

优点：客户机操作系统无需修改。

缺点：翻译有性能开销。

### 半虚拟化

**修改客户机**：Xen方案。客户机操作系统调用hypervisor接口（hypercall）替代敏感指令。

优点：性能好。

缺点：需要修改客户机操作系统。

### 硬件辅助虚拟化

**Intel VT-x/AMD-V**：CPU增加新的特权级别（VMX root/non-root）。

敏感指令自动陷入hypervisor。客户机无需修改，性能接近原生。

现代虚拟化的标准方案。

### VMCS/VMCB

虚拟机控制结构，保存虚拟机状态。

VM Entry加载客户机状态，VM Exit保存客户机状态并转移到hypervisor。

## 内存虚拟化

### 两层地址转换

客户机有自己的虚拟地址到"物理地址"的转换（客户机页表）。

但客户机的"物理地址"实际是hypervisor分配的，需要再转换到真正的物理地址。

### 影子页表

Hypervisor维护影子页表，直接将客户机虚拟地址映射到物理地址。

客户机修改页表时，hypervisor需要同步更新影子页表。开销较大。

### 扩展页表（EPT/NPT）

硬件支持的两层地址转换。

**Intel EPT/AMD NPT**：硬件自动进行两层转换。

MMU先查客户机页表，再查EPT页表，最终得到物理地址。

简化了hypervisor，性能更好。

### 内存过量分配

虚拟机配置的内存总和可以超过物理内存。

**气球驱动**：虚拟机内的驱动程序"膨胀"，占用内存并归还给hypervisor。

**内存共享（KSM）**：相同内容的页面只保留一份。

**交换**：hypervisor将不活跃的虚拟机内存换到磁盘。

## I/O虚拟化

### 设备模拟

Hypervisor模拟虚拟设备。客户机访问设备时陷入hypervisor，由软件处理。

优点：支持任意客户机操作系统。

缺点：每次I/O都需要VM Exit，开销大。

### 半虚拟化I/O

**virtio**：标准化的半虚拟化I/O接口。

客户机使用virtio驱动，直接与hypervisor通信，减少模拟开销。

virtio-net（网络）、virtio-blk（块设备）、virtio-scsi等。

### 设备直通

**PCI Passthrough**：将物理设备直接分配给虚拟机。

虚拟机直接访问设备，性能接近原生。但设备被独占，不能共享。

需要IOMMU支持，隔离虚拟机对设备的DMA访问。

### SR-IOV

Single Root I/O Virtualization。一个物理设备呈现为多个虚拟设备（VF）。

每个虚拟机分配一个VF，直接访问，同时支持多个虚拟机。

高性能网络虚拟化的常用方案。

## Hypervisor类型

### Type 1（裸金属）

直接运行在硬件上，没有宿主操作系统。

**代表**：VMware ESXi、Xen、Microsoft Hyper-V

优点：性能好，资源开销小。

缺点：需要专门的管理工具。

### Type 2（托管型）

运行在宿主操作系统上，作为普通进程。

**代表**：VMware Workstation、VirtualBox、QEMU

优点：易于安装使用。

缺点：多一层开销。

### KVM

Linux内核模块，将Linux变成Type 1 hypervisor。

利用Linux的进程调度、内存管理。虚拟机是普通进程。

通常与QEMU配合：KVM提供CPU/内存虚拟化，QEMU提供设备模拟。

## 容器技术

### 与虚拟机的区别

**虚拟机**：每个虚拟机有独立的内核，完整的操作系统。隔离性强，开销大。

**容器**：共享宿主内核，只隔离用户空间。轻量级，启动快，但隔离性弱于虚拟机。

### Linux命名空间

隔离系统资源的视图：

**PID namespace**：进程ID隔离

**Network namespace**：网络栈隔离

**Mount namespace**：文件系统挂载点隔离

**UTS namespace**：主机名隔离

**User namespace**：用户ID隔离

**Cgroup namespace**：cgroup隔离

每个容器有自己的命名空间，看到的是独立的系统环境。

### Cgroups

控制组，限制和统计资源使用：

**CPU**：限制CPU使用比例或时间

**内存**：限制内存使用，超限触发OOM

**I/O**：限制磁盘I/O带宽

**网络**：间接通过tc控制

容器的资源限制依赖cgroups实现。

### 容器运行时

**Docker**：最流行的容器平台，包含镜像打包、分发、运行时。

**containerd**：Docker的核心运行时，现已独立。

**runc**：OCI标准的容器运行时实现，负责创建和运行容器。

**gVisor/Kata**：增强隔离的容器运行时。

## 安全考量

### 虚拟机逃逸

攻击者从虚拟机攻破hypervisor，获取宿主权限。

防护：减少攻击面，及时修补漏洞，使用硬件安全特性。

### 容器隔离

容器共享内核，内核漏洞影响所有容器。

增强方案：
- 用户命名空间：容器内root不等于宿主root
- seccomp：限制系统调用
- AppArmor/SELinux：强制访问控制
- gVisor：用户态内核
- Kata Containers：轻量虚拟机

### 侧信道攻击

Spectre、Meltdown等CPU漏洞可能泄露其他虚拟机的数据。

需要硬件和软件联合防护。

## 总结

| 技术 | 特点 |
|------|------|
| 全虚拟化 | 二进制翻译，无需修改客户机 |
| 硬件辅助 | VT-x/AMD-V，现代标准 |
| 半虚拟化 | 修改客户机，性能好 |
| EPT/NPT | 硬件两层页表 |
| virtio | 半虚拟化I/O标准 |
| SR-IOV | 硬件I/O虚拟化 |
| 容器 | 共享内核，轻量级 |

虚拟化是云计算的基础技术。理解其原理有助于优化虚拟化环境和排查问题。
