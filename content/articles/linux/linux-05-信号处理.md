## 信号概述

### 什么是信号

信号是软件中断，用于通知进程发生了某个事件。信号是异步的，可能在任何时刻到达。

信号的来源：用户输入（Ctrl+C）、硬件异常（除零、段错误）、软件条件（子进程终止、定时器到期）、其他进程发送。

### 信号类型

**标准信号**（1-31）：传统Unix信号，每种信号最多pending一个。

**实时信号**（32-64）：POSIX实时扩展，可以排队，可以携带数据。

常用信号：

| 信号 | 描述 | 默认动作 |
|------|------|----------|
| SIGINT | 中断（Ctrl+C） | 终止 |
| SIGTERM | 终止请求 | 终止 |
| SIGKILL | 强制终止 | 终止（不可捕获） |
| SIGSEGV | 段错误 | 终止+core |
| SIGCHLD | 子进程状态改变 | 忽略 |
| SIGALRM | 定时器到期 | 终止 |
| SIGPIPE | 写入无读端的管道 | 终止 |
| SIGHUP | 终端挂断 | 终止 |
| SIGUSR1/2 | 用户自定义 | 终止 |
| SIGSTOP | 停止进程 | 停止（不可捕获） |
| SIGCONT | 继续运行 | 继续 |

## 信号处理方式

### 三种选择

**默认动作**：内核定义的行为，通常是终止进程、终止并生成core、忽略、停止。

**忽略**：进程选择忽略该信号。SIGKILL和SIGSTOP不能忽略。

**捕获**：进程注册处理函数，信号到达时调用该函数。SIGKILL和SIGSTOP不能捕获。

### signal函数

传统的信号处理设置函数。简单但有可移植性问题，不同系统行为不一致。

信号处理函数接收信号号作为参数。可以设置为SIG_DFL（默认）或SIG_IGN（忽略）。

### sigaction

推荐使用的现代接口。提供更多控制和一致的行为。

可以设置：
- 处理函数
- 处理期间阻塞的信号
- 处理后是否重置为默认
- 是否重启被中断的系统调用

## 信号的发送与等待

### kill函数

向指定进程发送信号。名字虽然是kill，但可以发送任何信号。

kill(pid, sig)：
- pid > 0：发送给指定进程
- pid == 0：发送给同进程组的所有进程
- pid == -1：发送给所有有权限的进程
- pid < -1：发送给进程组|pid|的所有进程

### raise

向自己发送信号。等价于kill(getpid(), sig)。

### alarm

设置定时器，到期后发送SIGALRM。只有一个定时器，新设置覆盖旧设置。

返回之前定时器的剩余时间。参数为0取消定时器。

### pause

挂起进程直到收到信号。信号处理函数返回后pause返回-1，errno为EINTR。

### sigsuspend

原子地设置信号屏蔽字并挂起进程。解决pause的竞态条件问题。

## 信号集与屏蔽

### 信号集

sigset_t类型表示信号集合。

操作函数：
- sigemptyset：清空信号集
- sigfillset：填充所有信号
- sigaddset：添加信号
- sigdelset：删除信号
- sigismember：测试信号是否在集合中

### 信号屏蔽

进程可以暂时阻塞某些信号的递送。被阻塞的信号保持pending状态，解除阻塞后递送。

sigprocmask设置信号屏蔽字。可以添加、删除或设置阻塞的信号集合。

常见用途：保护临界区，防止信号处理函数干扰。

### pending信号

sigpending获取当前pending的信号集合。这些信号已到达但因被阻塞而未递送。

## 可靠信号与不可靠信号

### 不可靠性

标准信号（1-31）有不可靠性：同一信号pending期间再次到达会被丢弃，不会排队。

如果短时间内发送多个相同信号，进程可能只收到一个。

### 实时信号

信号32-64是实时信号，解决了不可靠问题：

**排队**：同一信号可以排队，不会丢失。

**顺序**：按发送顺序递送。

**携带数据**：可以附带一个整数或指针（sigqueue发送，SA_SIGINFO处理）。

### sigqueue

发送实时信号并携带数据。目标进程的处理函数可以通过siginfo_t结构获取数据。

## 信号处理函数安全

### 可重入性

信号可能在任何时刻打断主程序，包括库函数执行过程中。如果信号处理函数调用同一个库函数，可能导致问题。

**可重入函数**：可以安全地从信号处理函数中调用。不使用静态数据，不调用malloc/free等。

POSIX定义了可重入的安全函数列表，包括read、write、_exit等。printf、malloc等是不安全的。

### 异步信号安全

信号处理函数应该尽量简单：
- 只调用异步信号安全函数
- 使用volatile sig_atomic_t类型访问共享变量
- 设置标志后返回，让主程序处理实际工作

### 常见陷阱

**printf**：不是信号安全的，可能死锁或输出混乱。

**malloc/free**：不是信号安全的，可能破坏堆结构。

**errno**：信号处理函数可能修改errno，需要保存和恢复。

## 信号与系统调用

### 中断问题

慢系统调用（如read等待输入）可能被信号中断，返回-1且errno为EINTR。

处理方式：
- 检查EINTR并重新调用
- 使用SA_RESTART标志让系统调用自动重启

### 自动重启

sigaction的SA_RESTART标志让某些系统调用在被信号中断后自动重启，而非返回错误。

不是所有系统调用都支持自动重启。某些场景下需要显式处理EINTR。

## 实用模式

### 优雅退出

捕获SIGTERM和SIGINT，设置全局标志通知主循环退出。主循环检查标志后进行清理工作。

### 定时任务

使用SIGALRM或setitimer实现定时器。更精确的定时使用timer_create（POSIX定时器）。

### 子进程回收

捕获SIGCHLD，在处理函数中调用waitpid回收终止的子进程，避免僵尸进程。

注意使用WNOHANG非阻塞等待，可能有多个子进程同时终止。

### 守护进程

SIGHUP常用于通知守护进程重新加载配置。守护进程已与终端分离，不会收到终端挂断的SIGHUP。

---

## signalfd

### 同步处理信号

signalfd将信号转换为文件描述符事件，可以用read读取，配合epoll使用。

优势：将异步信号转为同步事件，避免信号处理函数的复杂性。

使用前需要用sigprocmask阻塞相关信号，防止默认处理。

---

## 总结

| 概念 | 要点 |
|------|------|
| 信号类型 | 标准信号、实时信号 |
| 处理方式 | 默认、忽略、捕获 |
| sigaction | 推荐的信号设置接口 |
| 屏蔽 | sigprocmask阻塞信号 |
| 安全 | 处理函数只调用安全函数 |
| signalfd | 同步处理信号 |

信号是强大但复杂的机制。理解其异步特性和安全限制是正确使用的前提。现代程序倾向于使用signalfd或其他事件机制替代传统信号处理。
