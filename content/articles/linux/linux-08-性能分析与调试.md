## 性能分析方法论

### 问题定位流程

**确定目标**：明确要优化什么——延迟、吞吐量、CPU使用、内存占用。

**建立基准**：在优化前测量当前性能，作为比较基准。

**识别瓶颈**：使用工具找出性能瓶颈所在。

**优化验证**：修改后重新测量，验证是否改善。

### USE方法

对每个资源检查：

**U**tilization：资源使用率，接近100%可能是瓶颈。

**S**aturation：资源饱和度，任务排队等待的程度。

**E**rrors：错误数量，错误可能导致重试和性能下降。

资源包括：CPU、内存、磁盘I/O、网络I/O。

## strace

### 作用

追踪进程的系统调用和信号。显示每个系统调用的参数、返回值、耗时。

### 基本用法

**追踪命令**：strace command

**附加到进程**：strace -p pid

**常用选项**：
- -f：跟踪子进程
- -t/-tt：显示时间戳
- -T：显示系统调用耗时
- -e trace=类别：只显示特定类型（file、network、process）
- -c：统计系统调用次数和耗时
- -o file：输出到文件

### 分析思路

**找慢操作**：用-T找耗时长的系统调用。

**找频繁操作**：用-c看哪些系统调用最多。

**网络问题**：-e trace=network只看网络相关调用。

**文件问题**：-e trace=file看文件操作。

### 局限性

strace通过ptrace实现，开销较大。被追踪程序会显著变慢（10x-100x）。

生产环境慎用，可能影响服务性能。

---

## ltrace

### 作用

追踪库函数调用。显示动态链接库函数的调用和返回值。

### 用法

类似strace，但显示的是libc等库函数而非系统调用。

可以看到malloc/free调用、字符串操作等。

---

## perf

### 概述

Linux内核提供的性能分析工具。利用CPU性能计数器和软件事件进行采样。

开销低，适合生产环境使用。

### 基本命令

**perf stat**：统计程序的CPU周期、指令数、缓存命中率等。

**perf record**：采样记录性能数据。

**perf report**：分析采样数据，显示热点函数。

**perf top**：实时显示CPU热点，类似top。

### 采样分析

perf record -g ./program  # 采样并记录调用栈
perf report  # 分析报告

找出占用CPU最多的函数和调用路径。

### 火焰图

将perf采样数据可视化为火焰图。x轴是调用栈，y轴是调用深度，宽度表示采样频率。

快速识别热点代码和调用关系。

### 事件类型

**硬件事件**：CPU周期、指令、缓存命中/失效、分支预测。

**软件事件**：上下文切换、页错误、定时器。

**跟踪点**：内核定义的跟踪点，如调度器、系统调用。

## /proc文件系统

### 概述

/proc是虚拟文件系统，提供内核和进程信息的接口。读取这些文件获取运行时信息。

### 进程信息

**/proc/[pid]/status**：进程状态概览，包括内存使用、线程数等。

**/proc/[pid]/maps**：进程内存映射。

**/proc/[pid]/fd/**：打开的文件描述符。

**/proc/[pid]/stat**：进程统计信息（CPU时间、状态等）。

**/proc/[pid]/io**：I/O统计。

**/proc/[pid]/stack**：内核栈信息（需要root）。

### 系统信息

**/proc/meminfo**：系统内存使用。

**/proc/cpuinfo**：CPU信息。

**/proc/loadavg**：系统负载。

**/proc/stat**：系统级CPU统计。

**/proc/diskstats**：磁盘I/O统计。

**/proc/net/**：网络统计和连接信息。

### 内核参数

**/proc/sys/**：可调内核参数。可以读取和写入调整内核行为。

如/proc/sys/net/core/somaxconn控制listen backlog上限。

## GDB调试

### 基本操作

**启动调试**：gdb ./program

**运行**：run [args]

**断点**：break function或break file:line

**单步**：step（进入函数）、next（不进入）

**继续**：continue

**查看变量**：print var

**调用栈**：backtrace或bt

### 多线程调试

**查看线程**：info threads

**切换线程**：thread n

**全线程操作**：thread apply all bt

### 附加到进程

gdb -p pid

可以调试运行中的程序。注意会暂停目标进程。

### 核心转储

程序崩溃时生成core文件。

gdb ./program core

可以查看崩溃时的状态、调用栈、变量值。

确保ulimit -c unlimited允许生成core文件。

## Valgrind

### 概述

动态分析工具套件，在模拟的CPU上运行程序。能检测内存错误、线程问题、性能问题。

开销大（10x-50x），不适合生产环境。

### Memcheck

检测内存错误：

**未初始化内存读取**：使用未初始化的值。

**越界访问**：数组越界读写。

**释放后使用**：访问已释放的内存。

**内存泄漏**：程序结束时未释放的内存。

**重复释放**：同一内存释放两次。

### Helgrind

检测线程错误：

**数据竞争**：多线程无锁访问共享数据。

**锁顺序问题**：可能导致死锁的锁顺序。

**API误用**：pthread API使用错误。

### Cachegrind

缓存模拟器，分析缓存命中率和分支预测。

找出缓存不友好的代码。

## 其他工具

### top/htop

实时显示进程资源使用。CPU、内存、状态。

htop比top更友好，支持树状显示、鼠标操作。

### vmstat

虚拟内存统计。显示进程、内存、分页、I/O、CPU活动。

vmstat 1  # 每秒刷新

### iostat

磁盘I/O统计。显示设备使用率、吞吐量、等待时间。

iostat -x 1  # 详细模式，每秒刷新

### netstat/ss

网络连接和socket统计。

ss -s  # socket统计摘要
ss -lntp  # 监听的TCP端口

### lsof

列出打开的文件。可以查看进程打开的文件、网络连接。

lsof -p pid  # 指定进程
lsof -i :8080  # 使用端口8080的进程

### dmesg

内核环形缓冲区消息。硬件错误、驱动信息、OOM killer等。

dmesg -T  # 人类可读时间戳

## 性能调优思路

### CPU优化

**热点分析**：用perf找出CPU密集的代码。

**算法优化**：选择更高效的算法和数据结构。

**减少系统调用**：批量操作，减少用户态/内核态切换。

### 内存优化

**减少分配**：对象池、预分配。

**避免拷贝**：使用引用、move语义。

**缓存友好**：数据布局优化，减少缓存失效。

### I/O优化

**异步I/O**：不阻塞等待I/O完成。

**批量I/O**：减少系统调用次数。

**缓冲策略**：根据场景选择合适的缓冲策略。

### 网络优化

**连接复用**：避免频繁建立连接。

**减少数据量**：压缩、协议优化。

**优化协议参数**：调整TCP参数、使用更高效的协议。

## 总结

| 工具 | 用途 |
|------|------|
| strace | 追踪系统调用 |
| ltrace | 追踪库函数 |
| perf | CPU性能分析 |
| /proc | 进程和系统信息 |
| GDB | 交互式调试 |
| Valgrind | 内存和线程问题检测 |
| top/htop | 实时资源监控 |

性能分析是迭代过程：测量→分析→优化→验证。选择合适的工具，关注真正的瓶颈，避免过早优化。
