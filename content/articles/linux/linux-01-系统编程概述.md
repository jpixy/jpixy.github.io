## 什么是系统编程

系统编程是与操作系统内核直接交互的编程方式，区别于应用层编程依赖高层抽象库。系统程序员需要理解操作系统如何管理硬件资源，如何提供服务给应用程序。

系统编程的典型场景包括：编写设备驱动、实现文件系统、开发网络协议栈、构建容器运行时、实现数据库存储引擎。这些场景都需要直接与内核交互，对性能和资源控制有严格要求。

## 用户态与内核态

### 特权级别

现代 CPU 通过硬件机制实现特权隔离。x86 架构定义了 4 个特权级别，称为 **Ring**（保护环）。

```
x86 保护环架构（Ring 0 - Ring 3）：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│              Ring 3（最低特权）                          │
│         ┌───────────────────────────────────┐           │
│         │                                    │           │
│         │         Ring 2                     │           │
│         │    ┌───────────────────────┐      │           │
│         │    │                        │      │           │
│         │    │      Ring 1            │      │           │
│         │    │  ┌───────────────┐    │      │           │
│         │    │  │               │    │      │           │
│         │    │  │   Ring 0      │    │      │           │
│         │    │  │  （最高特权）  │    │      │           │
│         │    │  │               │    │      │           │
│         │    │  └───────────────┘    │      │           │
│         │    │                        │      │           │
│         │    └───────────────────────┘      │           │
│         │                                    │           │
│         └───────────────────────────────────┘           │
│                                                          │
└─────────────────────────────────────────────────────────┘

设计意图（Intel 原始设计）：
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
Ring 0  │ 操作系统内核
Ring 1  │ 操作系统服务（设备驱动等）
Ring 2  │ 操作系统服务（扩展）
Ring 3  │ 用户应用程序
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
```

#### x86 四个 Ring 的原始设计

**Ring 0（Supervisor Mode）**
- 最高特权级别，完全控制 CPU 和硬件
- 可执行所有指令，包括特权指令（如 `HLT`、`LGDT`、`MOV CR0`）
- 可访问所有内存地址空间
- 可配置内存保护、中断处理
- 设计用途：操作系统内核

**Ring 1 和 Ring 2（中间层）**
- Intel 原始设计用于操作系统服务
- Ring 1：设备驱动程序
- Ring 2：数据库、虚拟机管理器等系统服务
- 可执行部分特权指令，但受限于 Ring 0
- 设计用途：隔离内核核心与驱动/服务

**Ring 3（User Mode）**
- 最低特权级别
- 不能执行特权指令
- 只能访问被授权的内存区域
- I/O 操作必须通过系统调用
- 设计用途：普通应用程序

#### 为什么 Linux/Windows 只使用 Ring 0 和 Ring 3

```
现代操作系统的实际使用：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   Linux / Windows / macOS 实际使用：                    │
│   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   │
│                                                          │
│   Ring 0  →  内核（包括驱动程序）                       │
│   Ring 1  →  未使用                                     │
│   Ring 2  →  未使用                                     │
│   Ring 3  →  用户空间应用                               │
│                                                          │
│   为什么不用 Ring 1/2？                                 │
│   ─────────────────────                                 │
│   1. 可移植性：其他 CPU 架构（ARM、MIPS）只有 2 级      │
│   2. 复杂性：4 级保护增加内核复杂度，收益不明显         │
│   3. 性能：Ring 间切换有开销                            │
│   4. 历史：Unix 传统就是 2 级模型                       │
│   5. 足够：2 级已满足安全隔离需求                       │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### Ring -1：虚拟化扩展

随着虚拟化技术发展，Intel VT-x 和 AMD-V 引入了比 Ring 0 更高的特权级别：

```
虚拟化环境的特权级别：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   Ring -1 / VMX Root Mode（Hypervisor）                 │
│   ━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━   │
│   • 运行：Hypervisor（如 KVM、Xen、VMware ESXi）        │
│   • 权限：比 Ring 0 更高                                │
│   • 功能：                                              │
│     - 创建和管理虚拟机                                  │
│     - 拦截 Guest OS 的敏感操作                          │
│     - 硬件资源虚拟化                                    │
│     - 内存虚拟化（EPT/NPT）                             │
│                                                          │
│   层次结构：                                             │
│   ┌─────────────────────────────────────┐               │
│   │  Guest Ring 3  │  虚拟机用户程序    │               │
│   ├─────────────────────────────────────┤               │
│   │  Guest Ring 0  │  虚拟机内核        │               │
│   ├─────────────────────────────────────┤               │
│   │  Ring -1       │  Hypervisor        │  ← 最高特权   │
│   └─────────────────────────────────────┘               │
│                                                          │
│   实际例子：                                             │
│   • KVM：Linux 内核模块，运行在 Ring -1                 │
│   • QEMU：用户空间，运行在 Ring 3，与 KVM 配合          │
│   • VMware ESXi：Bare-metal Hypervisor                  │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### ARM 架构的特权级别对比

ARM 使用不同的术语，称为 Exception Level（EL）：

```
ARM vs x86 特权级别对比：

┌──────────────┬──────────────┬─────────────────────────┐
│     ARM      │     x86      │        运行内容          │
├──────────────┼──────────────┼─────────────────────────┤
│    EL0       │   Ring 3     │  用户应用程序            │
├──────────────┼──────────────┼─────────────────────────┤
│    EL1       │   Ring 0     │  操作系统内核            │
├──────────────┼──────────────┼─────────────────────────┤
│    EL2       │   Ring -1    │  Hypervisor              │
├──────────────┼──────────────┼─────────────────────────┤
│    EL3       │     N/A      │  Secure Monitor (TrustZone)│
└──────────────┴──────────────┴─────────────────────────┘

ARM 的 EL3（TrustZone）：
• 比 Hypervisor 更高的特权级别
• 用于安全敏感操作（密钥存储、DRM、支付）
• 普通 OS 和 Hypervisor 都无法访问
• 手机上的指纹、面部识别等在此运行
```

#### 特权指令与 Ring 级别

不同 Ring 可执行的指令不同：

```
特权指令示例（x86）：

┌────────────────┬────────┬─────────────────────────────┐
│      指令       │ 所需Ring│          功能               │
├────────────────┼────────┼─────────────────────────────┤
│ HLT            │ Ring 0 │ 停止 CPU                    │
│ LGDT/LIDT      │ Ring 0 │ 加载描述符表                 │
│ MOV CRn        │ Ring 0 │ 访问控制寄存器               │
│ MOV DRn        │ Ring 0 │ 访问调试寄存器               │
│ IN/OUT         │ Ring 0*│ I/O 端口访问                 │
│ CLI/STI        │ Ring 0 │ 禁用/启用中断                │
│ WRMSR/RDMSR    │ Ring 0 │ 访问 MSR 寄存器              │
│ INVLPG         │ Ring 0 │ 刷新 TLB 条目                │
├────────────────┼────────┼─────────────────────────────┤
│ SYSCALL/SYSRET │ Ring 3→0│ 系统调用（快速切换）         │
│ INT n          │ Ring 3 │ 软中断（可触发态切换）        │
├────────────────┼────────┼─────────────────────────────┤
│ 普通算术/逻辑   │ Any    │ ADD, SUB, MOV, JMP 等       │
└────────────────┴────────┴─────────────────────────────┘

* IN/OUT 可通过 IOPL 标志位允许 Ring 3 执行
```

#### Ring 级别检查机制

CPU 通过以下机制实施保护：

```
保护机制：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   1. CPL（Current Privilege Level）                     │
│      ───────────────────────────────                    │
│      • 存储在 CS 段寄存器的低 2 位                      │
│      • 表示当前代码的特权级别                           │
│      • 0 = Ring 0, 3 = Ring 3                           │
│                                                          │
│   2. DPL（Descriptor Privilege Level）                  │
│      ───────────────────────────────                    │
│      • 存储在段描述符/门描述符中                        │
│      • 定义访问该段/门所需的最低特权                    │
│                                                          │
│   3. RPL（Requested Privilege Level）                   │
│      ───────────────────────────────                    │
│      • 存储在段选择子的低 2 位                          │
│      • 用于防止特权提升攻击                             │
│                                                          │
│   访问检查规则：                                         │
│   ─────────────                                         │
│   • 数据访问：max(CPL, RPL) <= DPL                      │
│   • 代码跳转：需通过门（Call Gate）或中断               │
│   • Ring 3 → Ring 0：必须通过系统调用                   │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

#### 实际内存布局中的 Ring 体现

```
Linux 虚拟地址空间布局（64位）：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│  高地址                                                  │
│  0xFFFFFFFFFFFFFFFF ┌─────────────────────┐             │
│                     │                      │             │
│                     │   内核空间           │  Ring 0     │
│                     │   (Kernel Space)     │  可访问     │
│                     │                      │             │
│  0xFFFF800000000000 ├─────────────────────┤             │
│                     │   非规范地址空洞      │  不可用     │
│  0x00007FFFFFFFFFFF ├─────────────────────┤             │
│                     │                      │             │
│                     │   用户空间           │  Ring 3     │
│                     │   (User Space)       │  可访问     │
│                     │                      │             │
│  0x0000000000000000 └─────────────────────┘             │
│  低地址                                                  │
│                                                          │
│  页表项中的 U/S 位：                                     │
│  • U/S = 0：仅 Ring 0 可访问（内核页）                  │
│  • U/S = 1：Ring 0 和 Ring 3 都可访问（用户页）         │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

Linux 只使用两个 Ring 级别：

**内核态（Ring 0）** 运行操作系统内核代码，拥有完全的硬件访问权限。可以执行特权指令，访问所有内存，控制中断。

**用户态（Ring 3）** 运行应用程序代码，权限受限。不能直接访问硬件，不能执行特权指令，只能访问分配给自己的内存空间。

### 为什么需要分离

**安全隔离**：恶意或有缺陷的应用程序无法破坏系统或其他程序。

**稳定性**：一个程序崩溃不会导致整个系统崩溃。

**资源管理**：内核统一管理资源，防止程序独占或冲突。

### 态切换

当用户程序需要内核服务时，必须从用户态切换到内核态。这个过程称为态切换或上下文切换。

切换涉及：保存用户态寄存器、切换到内核栈、改变特权级别、执行内核代码、恢复并返回用户态。

态切换有一定开销，这是系统调用比普通函数调用慢的主要原因。

## 系统调用

### 概念

系统调用是用户程序请求内核服务的唯一合法途径。它是用户态和内核态之间的桥梁。

常见系统调用分类：
- **进程控制**：fork、exec、exit、wait
- **文件操作**：open、read、write、close、lseek
- **设备操作**：ioctl、mmap
- **信息维护**：getpid、alarm、sleep
- **通信**：pipe、socket、send、recv
- **内存管理**：brk、mmap、munmap

### 调用机制

系统调用通过软中断（x86上是int 0x80或syscall指令）触发。

**调用过程**：
1. 应用程序将系统调用号放入寄存器（如eax/rax）
2. 将参数放入约定的寄存器或栈中
3. 执行syscall指令，触发从用户态到内核态的切换
4. 内核根据调用号查找系统调用表，执行对应函数
5. 结果放入寄存器，返回用户态

### 系统调用 vs 库函数

**系统调用**是内核提供的原始接口，直接与内核交互。每次调用都有态切换开销。

**库函数**（如C标准库）封装系统调用，提供更友好的接口。库函数可能缓冲多次操作后再调用系统调用，减少切换次数。

例如，printf是库函数，它将输出缓冲，最终调用write系统调用。fread是库函数，它可能一次read更多数据到缓冲区，减少系统调用次数。

### 错误处理

系统调用失败时返回-1，并设置全局变量errno表示错误类型。

常见errno值：
- EACCES：权限不足
- ENOENT：文件或目录不存在
- ENOMEM：内存不足
- EINTR：被信号中断
- EAGAIN：资源暂时不可用

perror函数可以打印errno对应的错误信息。strerror函数返回错误描述字符串。

## ABI与API

### API（应用程序编程接口）

API是源代码级别的接口定义。它规定函数名、参数类型、返回值，但不关心底层实现。

POSIX定义了Unix-like系统的标准API，包括文件操作、进程控制、线程等。遵循POSIX的程序可以在不同Unix系统间移植。

### ABI（应用程序二进制接口）

ABI是二进制级别的接口规范。它规定：

**调用约定**：参数如何传递（寄存器还是栈），谁负责清理栈。

**数据布局**：结构体如何对齐，基本类型的大小。

**系统调用约定**：系统调用号，参数传递方式。

**目标文件格式**：ELF格式的具体规范。

ABI兼容意味着编译好的二进制文件可以在不同系统上运行。Linux在同一架构上保持ABI稳定，这就是为什么为某个Linux发行版编译的程序通常能在其他发行版上运行。

### 为什么ABI重要

**二进制分发**：商业软件通常只分发二进制，依赖ABI兼容性。

**动态链接**：程序运行时链接共享库，需要ABI匹配。

**内核兼容**：用户程序依赖内核的系统调用ABI，内核升级不能破坏它。

## Linux内核接口

### 稳定性保证

Linux内核对用户空间ABI有严格的稳定性承诺："我们不破坏用户空间"。一旦接口进入稳定内核，就会永久保持兼容。

这意味着很老的程序仍能在新内核上运行。这是Linux生态成功的重要因素。

### 不稳定接口

内核内部接口没有稳定性保证。驱动开发者需要随内核版本更新代码。这允许内核快速演进而不受历史包袱拖累。

### 查看系统调用

可以通过strace工具追踪程序的系统调用。它显示每个系统调用的参数和返回值，是调试和理解程序行为的利器。

/proc和/sys是内核暴露信息的虚拟文件系统。通过读写这些文件可以查看和修改内核状态。

## 开发环境

### 必要工具

**编译器**：GCC或Clang。理解编译选项对优化和调试的影响。

**调试器**：GDB。掌握断点、单步执行、查看内存和寄存器。

**追踪工具**：strace追踪系统调用，ltrace追踪库函数调用。

**性能工具**：perf进行性能分析，valgrind检测内存问题。

### 头文件

系统编程需要包含特定头文件：

- `<unistd.h>`：POSIX系统调用
- `<fcntl.h>`：文件控制
- `<sys/types.h>`：系统数据类型
- `<sys/stat.h>`：文件状态
- `<errno.h>`：错误号
- `<signal.h>`：信号处理

### 编译链接

系统程序通常静态链接以减少依赖，或仔细管理动态链接版本。

了解ELF格式、符号解析、重定位对于理解链接过程很有帮助。
