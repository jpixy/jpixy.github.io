### 1.3 非功能性需求

| 维度 | 要求 | 量化指标 |
| :--- | :--- | :--- |
| **性能** | 页面响应快速 | 首屏 < 1s，API P99 < 100ms |
| **吞吐** | 支撑双十一峰值 | 百万级 QPS |
| **可用性** | 核心链路高可用 | 99.99% (年停机 < 53分钟) |
| **一致性** | 订单库存一致 | 最终一致，秒级延迟 |
| **扩展性** | 业务快速增长 | 水平扩展，线性增长 |
| **数据量** | 海量数据存储 | 商品亿级，订单日增千万 |

### 1.4 业务约束与挑战

| 挑战 | 说明 | 应对策略 |
| :--- | :--- | :--- |
| **高并发访问** | 大促期间流量暴增100倍 | 多级缓存、限流熔断 |
| **库存超卖** | 热门商品瞬间售罄 | Redis原子操作、分桶 |
| **数据一致性** | 跨服务事务保证 | 事务消息、最终一致 |
| **热点数据** | 爆款商品访问集中 | 本地缓存、数据分片 |
| **海量数据** | 商品/订单持续增长 | 分库分表、冷热分离 |

### 2.2 服务拆分原则

| 原则 | 说明 | 示例 |
| :--- | :--- | :--- |
| **业务边界清晰** | 按领域驱动设计划分 | 商品域、交易域、营销域 |
| **数据独立** | 每个服务独立数据库 | 订单库、商品库分离 |
| **高内聚低耦合** | 减少服务间依赖 | 通过消息解耦 |
| **可独立部署** | 独立开发测试上线 | CI/CD独立流水线 |
| **合理粒度** | 避免过细或过粗 | 不要拆出"加一服务" |

## 三、核心子系统设计

| :--- | :--- | :--- | :--- |

## 五、购物车系统设计

### 5.1 购物车设计要点

| 设计点 | 方案 | 理由 |
| :--- | :--- | :--- |
| **存储位置** | Redis Hash | 高频读写，需要高性能 |
| **持久化** | 异步同步MySQL | 防止Redis故障丢失 |
| **未登录用户** | 本地存储+Cookie | 登录后合并 |
| **商品信息** | 实时查询，不存快照 | 价格库存需要实时 |
| **容量限制** | 单用户最多99个SKU | 防止滥用 |

### 5.2 购物车数据结构

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          Redis购物车结构                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  Key: cart:{user_id}                                                        │
│  Type: Hash                                                                  │
│                                                                              │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │ Field (SKU ID)    │ Value (JSON)                                    │    │
│  ├─────────────────────────────────────────────────────────────────────┤    │
│  │ sku_10001         │ {"qty":2,"checked":true,"add_time":1704672000}  │    │
│  │ sku_10002         │ {"qty":1,"checked":true,"add_time":1704672100}  │    │
│  │ sku_10003         │ {"qty":3,"checked":false,"add_time":1704672200} │    │
│  └─────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  注意:                                                                       │
│  • 不存储商品名称、价格等，展示时实时查询商品服务                              │
│  • checked 表示是否勾选结算                                                   │
│  • add_time 用于排序展示                                                      │
│                                                                              │
│  过期策略:                                                                   │
│  • 活跃用户购物车不过期                                                       │
│  • 30天未活跃用户购物车持久化到MySQL后可从Redis删除                           │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 5.3 购物车核心操作

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                          购物车核心操作                                        │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  添加商品:                                                                   │
│  1. 校验SKU是否存在、是否上架                                                 │
│  2. HINCRBY cart:{user_id} {sku_id} 如果已存在则数量+N                       │
│  3. 校验总SKU数不超过99                                                       │
│  4. 异步同步到MySQL                                                          │
│                                                                              │
│  查询购物车:                                                                  │
│  1. HGETALL cart:{user_id}                                                  │
│  2. 批量查询商品服务获取最新信息 (名称、价格、库存、图片)                      │
│  3. 标记失效商品 (下架、删除、无库存)                                         │
│  4. 计算勾选商品总价                                                          │
│                                                                              │
│  合并购物车 (登录时):                                                         │
│  1. 获取本地临时购物车 (Cookie/LocalStorage)                                 │
│  2. 与登录用户购物车合并                                                      │
│  3. 相同SKU数量累加                                                          │
│  4. 清除临时购物车                                                            │
│                                                                              │
│  结算:                                                                        │
│  1. 获取勾选的商品列表                                                        │
│  2. 再次校验价格和库存                                                        │
│  3. 进入订单确认页                                                            │
│  4. 下单成功后删除对应购物车项                                                │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 8.2 库存扣减方案

| 方案 | 实现 | 优点 | 缺点 | 适用场景 |
| :--- | :--- | :--- | :--- | :--- |
| **数据库扣减** | UPDATE SET stock=stock-N WHERE stock>=N | 强一致 | 性能低 | 低并发 |
| **Redis预扣** | Lua脚本原子扣减 | 高性能 | 需同步DB | 高并发 |
| **分桶库存** | 库存分片到多个Key | 极高性能 | 实现复杂 | 秒杀 |
| **预扣+确认** | 两阶段提交 | 防止恶意占用 | 需补偿 | 常规场景 |

### 8.4 热点库存处理

```
┌─────────────────────────────────────────────────────────────────────────────┐
│                           热点库存分桶方案                                      │
├─────────────────────────────────────────────────────────────────────────────┤
│                                                                              │
│  问题: 爆款商品库存成为Redis热点Key，单Key扛不住高并发                         │
│                                                                              │
│  解决: 将一个库存Key拆分成多个桶                                              │
│                                                                              │
│  原始:                                                                       │
│  stock:sku_123 = 10000                                                      │
│                                                                              │
│  分桶后 (10个桶):                                                            │
│  stock:sku_123:0 = 1000                                                     │
│  stock:sku_123:1 = 1000                                                     │
│  stock:sku_123:2 = 1000                                                     │
│  ...                                                                        │
│  stock:sku_123:9 = 1000                                                     │
│                                                                              │
│  扣减逻辑:                                                                   │
│  ┌─────────────────────────────────────────────────────────────────────┐    │
│  │ 1. bucket_id = hash(request_id) % bucket_count                      │    │
│  │ 2. 扣减 stock:sku_123:{bucket_id}                                   │    │
│  │ 3. 如果当前桶不足:                                                   │    │
│  │    a. 尝试从相邻桶借用                                               │    │
│  │    b. 或返回库存不足                                                 │    │
│  │ 4. 定期执行桶间均衡 (后台任务)                                       │    │
│  └─────────────────────────────────────────────────────────────────────┘    │
│                                                                              │
│  优势:                                                                       │
│  • 10个桶 = 10倍并发能力                                                     │
│  • 热点分散到多个Redis节点                                                   │
│  • 单桶扣完不影响整体可用性                                                   │
│                                                                              │
│  适用场景: 秒杀、大促热门商品                                                 │
│                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘
```

### 17.2 架构设计原则

| 原则 | 实践 | 收益 |
| :--- | :--- | :--- |
| **分层架构** | 接入→聚合→服务→数据 | 职责清晰、易维护 |
| **服务化** | 按领域拆分微服务 | 独立部署、独立扩展 |
| **无状态** | 状态外置到Redis/DB | 易于水平扩展 |
| **异步解耦** | MQ解耦非核心流程 | 削峰填谷、提升吞吐 |
| **缓存优先** | 多级缓存 | 降低延迟、减轻DB压力 |
| **数据分片** | 分库分表 | 突破单机容量瓶颈 |
| **容错设计** | 限流熔断降级 | 故障隔离、优雅降级 |
| **可观测** | Metrics/Logging/Tracing | 快速定位问题 |
| **安全内置** | 安全左移 | 从设计阶段考虑安全 |
