## 二、计算图优化

### 2.1 图优化技术

```
计算图优化方法：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   常量折叠（Constant Folding）                          │
│   ──────────────────────────                            │
│   在编译时计算常量表达式                                │
│   例：2 × 3 → 6                                         │
│                                                          │
│   死代码消除（Dead Code Elimination）                   │
│   ──────────────────────────                            │
│   移除不影响输出的节点                                  │
│   减少不必要计算                                        │
│                                                          │
│   公共子表达式消除（CSE）                               │
│   ──────────────────────────                            │
│   复用相同计算结果                                      │
│   避免重复计算                                          │
│                                                          │
│   算子融合（Operator Fusion）                           │
│   ──────────────────────────                            │
│   合并多个操作为一个                                    │
│   减少内存读写和 kernel 启动开销                        │
│   例：Conv + BN + ReLU → 一个融合算子                   │
│                                                          │
│   布局优化（Layout Optimization）                       │
│   ──────────────────────────                            │
│   选择最优数据排布                                      │
│   NCHW vs NHWC                                          │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 2.2 算子融合详解

```
算子融合示例：

原始计算图：
┌──────┐   ┌──────┐   ┌──────┐
│ Conv │ → │  BN  │ → │ ReLU │
└──────┘   └──────┘   └──────┘
   ↓          ↓          ↓
 写内存     读写内存    读写内存

融合后：
┌────────────────────────────┐
│   Conv + BN + ReLU (融合)   │
└────────────────────────────┘
   ↓
 一次内存读写

收益：
• 减少 2 次内存读写（GPU 内存带宽瓶颈）
• 减少 2 次 kernel 启动开销
• 更好的缓存利用

常见融合模式：
• Conv/MatMul + Bias + Activation
• LayerNorm + Linear
• Softmax + Mask
• Attention 融合（FlashAttention）
```

## 三、LLM 专用优化

### 3.1 KV Cache

```
KV Cache 优化：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   问题：                                                │
│   ────                                                  │
│   自回归生成时，每个 token 需要计算 attention           │
│   每次都重新计算之前 token 的 K、V 很浪费               │
│                                                          │
│   解决方案：KV Cache                                    │
│   ────                                                  │
│   缓存之前 token 的 K、V 值                             │
│   新 token 只需计算自己的 K、V                          │
│   然后与缓存的 K、V 一起做 attention                    │
│                                                          │
│   效果：                                                │
│   ────                                                  │
│   计算量从 O(n²) 变为 O(n)                              │
│   但内存占用增加                                        │
│                                                          │
│   内存占用估算：                                        │
│   ────                                                  │
│   每层每 token：2 × hidden_size × 2 bytes（FP16）       │
│   LLaMA-7B, 2048 tokens:                                │
│   32 层 × 4096 × 2 × 2048 × 2 bytes ≈ 1GB               │
│                                                          │
│   优化方向：                                            │
│   • 量化 KV Cache（INT8/INT4）                          │
│   • PagedAttention（vLLM）                              │
│   • 滑动窗口                                            │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 3.2 FlashAttention

```
FlashAttention：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   问题：标准 Attention 内存瓶颈                         │
│   ────                                                  │
│   需要存储完整的 QK^T 矩阵（seq_len × seq_len）         │
│   大序列长度时内存爆炸                                  │
│                                                          │
│   FlashAttention 方案                                   │
│   ────                                                  │
│   • 分块计算（Tiling）                                  │
│   • 在 SRAM 中完成计算                                  │
│   • 避免写完整注意力矩阵到 HBM                          │
│                                                          │
│   效果                                                  │
│   ────                                                  │
│   • 内存从 O(n²) 降到 O(n)                              │
│   • 速度提升 2-4 倍                                     │
│   • 支持更长序列                                        │
│                                                          │
│   使用                                                  │
│   ────                                                  │
│   # PyTorch 2.0+                                        │
│   torch.nn.functional.scaled_dot_product_attention(     │
│       query, key, value,                                │
│       is_causal=True  # 自动使用 FlashAttention        │
│   )                                                     │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 3.3 Continuous Batching

```
Continuous Batching（持续批处理）：

┌─────────────────────────────────────────────────────────┐
│                                                          │
│   传统批处理问题                                        │
│   ────────────                                          │
│   • 等待凑够一批再处理                                  │
│   • 不同请求生成长度不同                                │
│   • 短请求等待长请求完成                                │
│   • GPU 利用率低                                        │
│                                                          │
│   Continuous Batching                                   │
│   ────────────                                          │
│   • 请求随到随处理                                      │
│   • 完成的请求立即释放                                  │
│   • 新请求立即加入                                      │
│   • 保持 GPU 持续忙碌                                   │
│                                                          │
│   示意图                                                │
│   ────────────                                          │
│   传统：[req1][req2][req3] → 等最长完成                 │
│                                                          │
│   持续：[req1]     → 完成释放                           │
│         [req2]    [req4] → 新请求加入                   │
│         [req3]                                          │
│                                                          │
│   实现：vLLM, TGI                                       │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

### 4.3 vLLM 使用

```python
from vllm import LLM, SamplingParams

# 加载模型
llm = LLM(
    model="meta-llama/Llama-2-7b-chat-hf",
    tensor_parallel_size=1,  # GPU 数量
    gpu_memory_utilization=0.9,
    dtype="float16",
)

# 推理
sampling_params = SamplingParams(
    temperature=0.7,
    top_p=0.9,
    max_tokens=256,
)

prompts = [
    "What is machine learning?",
    "Explain quantum computing.",
    # 可以同时处理多个请求
]

outputs = llm.generate(prompts, sampling_params)

for output in outputs:
    print(output.outputs[0].text)
```

### 6.2 性能测试

```python
import time
import numpy as np

def benchmark_inference(model, inputs, warmup=10, runs=100):
    """推理性能测试"""
    
    # 预热
    for _ in range(warmup):
        _ = model(inputs)
    
    # 同步（GPU）
    if hasattr(torch.cuda, 'synchronize'):
        torch.cuda.synchronize()
    
    # 计时
    latencies = []
    for _ in range(runs):
        start = time.perf_counter()
        _ = model(inputs)
        if hasattr(torch.cuda, 'synchronize'):
            torch.cuda.synchronize()
        end = time.perf_counter()
        latencies.append((end - start) * 1000)  # ms
    
    # 统计
    latencies = np.array(latencies)
    print(f"Latency (ms):")
    print(f"  Mean: {latencies.mean():.2f}")
    print(f"  Std:  {latencies.std():.2f}")
    print(f"  P50:  {np.percentile(latencies, 50):.2f}")
    print(f"  P95:  {np.percentile(latencies, 95):.2f}")
    print(f"  P99:  {np.percentile(latencies, 99):.2f}")
    print(f"Throughput: {1000 / latencies.mean():.2f} req/s")
```
