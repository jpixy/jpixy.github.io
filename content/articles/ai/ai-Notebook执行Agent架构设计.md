# Notebook 执行 Agent 架构设计

---

## 一、背景与痛点

### 1.1 现状问题

Jupyter Notebook 是数据科学和机器学习领域的主流工具，但在自动化执行方面存在严重障碍：

| 痛点 | 描述 | 影响 |
|------|------|------|
| **人工指令散落** | Markdown 中写着"请执行 xxx"、"请创建文件 xxx" | 无法自动化 |
| **逐单元格执行** | 需要手动一个个运行 | 效率低下 |
| **错误需人工排查** | 执行失败后需手动调试 | 阻断流程 |
| **结果难以分享** | 需手动导出 HTML/PDF | 协作困难 |
| **环境依赖隐蔽** | 缺失的包只有运行时才发现 | 浪费时间 |

### 1.2 核心痛点：人工介入指令

**这是阻碍 Notebook 自动化的最大障碍。**

开发者习惯在 Markdown 单元格中写入需要手动执行的操作：

> **示例 1**："请打开终端，执行 `pip install torch transformers`"
> 
> **示例 2**："请在 config/ 目录下创建 settings.yaml 文件"
> 
> **示例 3**："请从 HuggingFace 下载模型到 ./models/ 目录"
> 
> **示例 4**："请设置环境变量 `export API_KEY=xxx`"

这些指令导致：**即使使用 papermill/nbclient，Notebook 也无法真正"一键执行到底"。**

### 1.3 我们的解决方案

设计一个 **AI Agent**，具备以下核心能力：

| 能力 | 说明 |
|------|------|
| **人工指令识别** | LLM 自动识别 Markdown 中的操作指令 |
| **人工指令执行** | 自动执行终端命令、文件操作、下载等 |
| **错误自动修复** | LLM 分析错误原因并尝试修复 |
| **一键执行** | 从头到尾无需人工干预 |
| **报告生成** | 自动输出 HTML 格式结果 |

## 二、整体架构设计

### 2.1 架构总览

```
┌─────────────────────────────────────────────────────────────┐
│                        User Interface                        │
│                    (CLI / REST API / Web UI)                 │
└─────────────────────────────────┬───────────────────────────┘
                                  │
                                  ▼
┌─────────────────────────────────────────────────────────────┐
│                      Agent Controller                        │
│         (Task Scheduler / State Manager / Orchestrator)      │
└─────────────────────────────────┬───────────────────────────┘
                                  │
        ┌─────────────────────────┼─────────────────────────┐
        ▼                         ▼                         ▼
┌───────────────┐       ┌─────────────────┐       ┌───────────────┐
│  Pre-flight   │       │    Execution    │       │     Post      │
│   Checker     │       │     Engine      │       │   Processor   │
└───────────────┘       └────────┬────────┘       └───────────────┘
                                 │
              ┌──────────────────┼──────────────────┐
              ▼                                     ▼
┌──────────────────────────┐          ┌──────────────────────────┐
│  Human Instruction       │          │     Error Handler        │
│  Handler (LLM-Powered)   │          │     (LLM-Powered)        │
└──────────────────────────┘          └──────────────────────────┘
```

### 2.2 模块职责

| 模块 | 职责 | 核心技术 |
|------|------|----------|
| **Pre-flight Checker** | 执行前检查依赖、参数、环境 | AST 解析、pip check |
| **Execution Engine** | 执行 Notebook 单元格 | nbclient、papermill |
| **Human Instruction Handler** | 识别并执行人工指令 | LLM、subprocess |
| **Error Handler** | 分析错误并尝试修复 | LLM、重试机制 |
| **Post Processor** | 生成 HTML 报告 | nbconvert |

### 2.3 技术选型

| 组件 | 选型 | 理由 |
|------|------|------|
| Notebook 执行 | **papermill** + **nbclient** | 参数化 + 精细控制 |
| 人工指令解析 | **LLM** (GPT-4/Claude/本地模型) | 理解自然语言 |
| 报告生成 | **nbconvert** | 官方工具，稳定 |
| 命令执行 | **subprocess** | 安全可控 |
| 文件操作 | **pathlib** | 跨平台 |

## 四、重点模块详解

### 4.1 人工指令处理模块 (Human Instruction Handler)

这是本系统的**核心创新模块**。

#### 4.1.1 支持的指令类型

| 类型 | 识别关键词 | 执行动作 |
|------|------------|----------|
| **终端命令** | "请执行"、"运行命令"、"在终端输入" | subprocess 执行 |
| **文件创建** | "创建文件"、"新建文件"、"保存为" | 写入文件 |
| **目录创建** | "创建目录"、"新建文件夹" | os.makedirs |
| **下载文件** | "下载"、"获取"、"从...下载到" | httpx 下载 |
| **环境变量** | "设置环境变量"、"export" | os.environ |
| **权限修改** | "chmod"、"修改权限" | os.chmod（受限） |

#### 4.1.2 LLM 解析 Prompt 设计

```
┌──────────────────────────────────────────────────────────┐
│                    LLM Parsing Prompt                     │
├──────────────────────────────────────────────────────────┤
│  Role: 你是一个专业的指令解析器                            │
│                                                          │
│  Input:                                                  │
│  - Markdown 内容                                         │
│  - 当前工作目录                                          │
│  - Notebook 路径                                         │
│                                                          │
│  Output (JSON):                                          │
│  [                                                       │
│    {                                                     │
│      "type": "terminal|file|directory|download|env",     │
│      "description": "操作描述",                          │
│      "command": "具体命令",                              │
│      "path": "目标路径",                                 │
│      "content": "文件内容",                              │
│      "risk_level": "low|medium|high"                     │
│    }                                                     │
│  ]                                                       │
└──────────────────────────────────────────────────────────┘
```

#### 4.1.3 安全机制

| 安全层 | 机制 | 说明 |
|--------|------|------|
| **第一层** | 命令白名单 | 仅允许 pip/mkdir/wget 等安全命令 |
| **第二层** | 危险模式检测 | 拦截 rm -rf / sudo / 系统目录写入 |
| **第三层** | 路径沙箱 | 所有路径必须在工作目录内 |
| **第四层** | 风险分级 | high 级别需用户确认 |
| **第五层** | 执行回滚 | 失败时恢复原状态 |

**命令白名单示例：**

| 允许 | 阻止 |
|------|------|
| pip install xxx | sudo xxx |
| mkdir -p xxx | rm -rf xxx |
| wget url | chmod 777 |
| git clone | curl \| bash |

## 五、配置与使用

### 5.1 配置项

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `timeout_per_cell` | int | 300 | 单元格执行超时（秒） |
| `max_retries` | int | 3 | 最大重试次数 |
| `enable_instruction_execution` | bool | true | 是否自动执行人工指令 |
| `safety_level` | str | "medium" | 安全级别：strict/medium/permissive |
| `llm_provider` | str | "openai" | LLM 提供商 |
| `generate_html` | bool | true | 是否生成 HTML 报告 |

### 5.2 CLI 使用示例

```bash
# 基本执行
nb-agent run notebook.ipynb

# 带参数执行
nb-agent run notebook.ipynb --param epochs=10 --param lr=0.001

# 预览人工指令（不执行）
nb-agent scan notebook.ipynb

# 严格安全模式
nb-agent run notebook.ipynb --safety-level strict

# 生成 HTML 报告
nb-agent run notebook.ipynb --output report.html
```

### 5.3 Python API 示例

```python
from nb_agent import NotebookAgent

agent = NotebookAgent(
    llm_provider="openai",
    enable_instruction_execution=True,
    safety_level="medium"
)

result = agent.execute(
    notebook_path="analysis.ipynb",
    parameters={"epochs": 10}
)

print(f"Status: {result.status}")
print(f"Report: {result.html_path}")
print(f"Instructions executed: {result.instruction_count}")
```

## 七、总结

### 7.1 核心价值

| 传统痛点 | Agent 解决方案 |
|----------|---------------|
| Markdown 中的人工指令 | LLM 自动识别 + 自动执行 |
| 逐单元格手动执行 | 一键执行到底 |
| 错误需人工排查 | LLM 自动诊断修复 |
| 结果难以分享 | 自动生成 HTML 报告 |

### 7.2 技术栈

| 层级 | 技术 |
|------|------|
| **执行层** | papermill + nbclient + nbconvert |
| **智能层** | LLM (GPT-4 / Claude / Ollama) |
| **安全层** | 白名单 + 沙箱 + 风险分级 |
| **接口层** | CLI + REST API |

### 7.3 适用场景

- 数据分析流水线自动化
- 机器学习实验批量运行
- CI/CD 中的 Notebook 测试
- 遗留 Notebook 的自动化改造
- 定时报告生成
